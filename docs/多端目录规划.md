# 多端目录规划（TV / 手机平板）

> 状态：已落地，`./gradlew :app:assembleDebug` 通过。
> 对应分支：`arch/v2-rebuild`
> 约束：最低 Android 4.4（API 19）、单个 APK 按设备形态分叉。
>
> **本文只讲目录与模块划分。**两端逐项的差异归属、公共层对外 API、迁移阶段、
> 回归清单与开发规范，见 [`多端重构-差异矩阵与迁移.md`](多端重构-差异矩阵与迁移.md)。

---

## 一、为什么拆

改造前是一个 `:app` 模块装下全部 36k 行 Kotlin：TV 页面（`MainActivity` 的 23 个 partial）
与数据层（`data/`）、播放封装（`architecture/`）、兼容层（`compat/`）混在一起。
要在同一份代码上做手机端，只有两条路：

1. 在 `MainActivity` 里加 `if (isPhone)` 分支——两套版面互相污染，焦点导航与触摸手势
   会在同一个类里打架，最终没人敢改；
2. **按端拆模块**，公共能力沉到下面一层。

选了第 2 条。边界不是靠约定，而是靠 Gradle 的模块依赖：手机端**编译期就看不到** TV 的任何 View。

## 二、模块图

```
core（纯 JVM）← shared（Android 公共层）← feature-tv    ← app
                                       ← feature-phone ←
```

| 模块 | 类型 | 职责 | 不允许出现 |
| --- | --- | --- | --- |
| `:core` | JVM library | 网络协议、签名、解析、播放状态机、缓存 | 任何 `android.*` 依赖 |
| `:shared` | Android library | 账号 / 会话 / 收藏 / 进度 / 封面 / 播放传输 / 弹幕渲染 / 调试 | 任何页面、任何端专属的版面令牌 |
| `:feature-tv` | Android library | 遥控器焦点导航、1280×720 设计画布、TV 全部页面 | 触摸手势、竖屏版面 |
| `:feature-phone` | Android library | 触摸、竖屏、底部导航、手势播放 | 遥控器按键、焦点链 |
| `:app` | application | `Application`、启动路由、Manifest、图标、签名 | 任何业务逻辑 |

依赖方向单向：`feature-tv` 与 `feature-phone` **互不依赖**。
一旦需要共享，只能往下沉到 `:shared`——这条规则由 Gradle 强制，不靠 review。

## 四、启动路由

`LaunchActivity` 是唯一带 `LAUNCHER` / `LEANBACK_LAUNCHER` 的组件，主题为
`Theme.NoDisplay`（不建视图），只做一次判定然后转发：

```
用户点图标
   └── LaunchActivity
         ├── 读设置 native-library-v1 / deviceForm
         │     ├── phone / tablet → PhoneMainActivity
         │     ├── tv             → tv.MainActivity
         │     └── auto           → detectDeviceForm() 打分判定
         └── finish()
```

**设置优先于自动判定**：电视上的「使用设备」可以强制成手机，改完重启就进竖屏界面；
手机端「我的」页底部有一枚「切换为电视界面」，两边都能改，不会互相锁死。

形态判定的打分规则原样保留（见 `shared/compat/DeviceForm.kt`）：
`uiMode=tv` / `leanback` / 电视能力位 / 无触屏有方向键 / `ro.build.characteristics` /
对角线 / 品牌词表，够 4 分判电视，否则按短边 600dp 分平板与手机。

## 五、手机端页面设计（对照官方 APP）

参考 `com.phoenix.read` 7.3.x（内部包名 `com.dragon.read.*`，aid=8662）的页面结构，
**只保留内容消费链路**，官方那套金币、任务、会员、活动、广告全部不搬。

| 官方 APP | 本实现 | 说明 |
| --- | --- | --- |
| 首页竖屏全屏播放流 | `PhoneFeedView`：整屏吸附卡片 | 不自动播放（每屏一个播放器在 4.4 上内存扛不住），点击进播放页 |
| 顶部频道 tab | 无 | 短剧用户靠封面决策，不靠频道 |
| 剧场 / 分类 | `page/PhoneCategoryPage`：两列海报网格 + 体裁筛选 | 筛选收成一行 chip，不做多层下钻 |
| 榜单 | `page/PhoneRankPage` | 与剧场共用网格，多一个名次角标 |
| 详情页 | `PhoneDetailActivity` | 简介 / 选集 / 相关剧集；从推荐流可直接进播放页 |
| 播放页 | `PhonePlayerActivity`：竖屏全屏 + 剧集抽屉 + 手势 | 单击显隐控制层，左右拖进度、上下滑亮度音量、长按倍速；进度每秒刷新、每 5 秒落盘 |
| 我的（金币/任务/会员） | `page/PhoneMinePage`：继续观看 + 收藏 + 设置入口 | 官方那套金币任务会员一律不搬 |
| 登录（验证码/扫码） | `PhoneAccountActivity`：扫码（`core/QrLogin`）+ 本机记录 | 会话与 TV 共用 `shared/data/AppSessionStore` |

视觉令牌（`PhoneTheme`）：品牌红 `#FF2D55` + 近黑底 `#0A0A0C`。
手机端**有自己的设计画布**（竖屏 360×640 / 横屏 640×360），与 TV 的 1280×720 是同一条思路
（只按屏幕像素算、不读 density），但**画布尺寸不同**——直接套 TV 画布会把整块版面压小，
反过来把手机画布放大成 960×540 又会让「界面整体变大」，两个方向都试过并已定稿为现在这套。

## 六、迁移映射（旧 → 新）

| 旧位置 | 新位置 |
| --- | --- |
| `com.hgtv.star.data.*` | `com.hgtv.star.shared.data.*` |
| `com.hgtv.star.architecture.*` | `com.hgtv.star.shared.architecture.*` |
| `com.hgtv.star.compat.*` | `com.hgtv.star.shared.compat.*` |
| `com.hgtv.star.player.DanmakuView` / `DanmakuEmojiStore` / `VideoDataSource` | `com.hgtv.star.shared.media.*` |
| `com.hgtv.star.DebugFaults` / `Diagnostics` / `NetSpeed` / `PerfStats` | `com.hgtv.star.shared.debug.*` |
| `com.hgtv.star.list.*` | `com.hgtv.star.tv.list.*` |
| `com.hgtv.star.player.*`（其余） | `com.hgtv.star.tv.player.*` |
| `com.hgtv.star.MainActivity*` / `DebugOverlay` / `PlaybackDiagnostics` | `com.hgtv.star.tv.*` |
| `com.hgtv.star.tv.*` | 不变（已迁入 `:feature-tv`） |

跨模块后 `internal` 不再可见，已统一放开为 `public`（1018 处）。
`Library` 需要的导航白名单 `NAV_KEYS` / `NAV_KEY_RECOMMEND` 从 TV 常量里抽出，
放到 `shared/data/NavKeys.kt`，两端共用同一套 key。

## 七、当时刻意没做、后来补上的事

> 这一节保留历史结论，同时标注现状。原先列在这里的三项手机能力已经补齐，
> 只留下「确实不做」的两项。

| 项 | 当时的原因 | 现状 |
| --- | --- | --- |
| 手机端登录（验证码 / 扫码） | 需要一套独立的登录面板，属于下一轮 | ✅ 已实现：`PhoneAccountActivity` + `core/QrLogin` + `shared/account/AccountLogin` |
| 手机端弹幕 | `DanmakuView` 已可复用，但播放页还没接 | ✅ 已接：`PhonePlayerActivity` / `PhoneFeedView` 共用 `shared/media/DanmakuView` 与 `DanmakuLoader` |
| 手机端设置页 | TV 的设置项在手机上大多无意义，需要重新筛 | ✅ 已实现：`PhoneSettingsActivity` + `PhonePlaybackSettings`，只保留有意义的项 |
| 推荐流自动播放 | 每屏持有一个播放器，在 2GB 内存的 4.4 机器上是灾难 | ⛔ 仍然不做 |
| 拆 `:core` 的测试到独立模块 | `core/src/test` 的用例跟着 core 走 | ⛔ 仍然不做（`:core` 本身就是纯 JVM，测试跟着它最省事） |

## 八、构建与验证

```bash
cd android
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@17/17.0.20.1/libexec/openjdk.jdk/Contents/Home

./gradlew :app:assembleDebug                      # 必须过
./gradlew :core:test :shared:testDebugUnitTest    # 406 例必须全绿
```

- 必须 JDK 17–23（根 `build.gradle.kts` 有自检）。
- Media3 仍钉在 **1.4.1**（1.5.0+ 要求 minSdk 21）。
- `baseline-prof.txt` 的类名已随包迁移；校验脚本对 448 条项目类做存在性检查，
  缺失的 6 条都是编译器生成的 lambda 内部类（原本也会随版本漂移）。
- 单元测试：`:core` 382 例（纯 JVM），`:shared` 24 例（纯逻辑：头像色 / TLS 读数压缩 / 滑杆判定 / 页面名）。
  碰 `Context` 的部分没有单测，由真机回归覆盖——清单见
  [`多端重构-差异矩阵与迁移.md`](多端重构-差异矩阵与迁移.md) §9。
