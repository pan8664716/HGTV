## 0. 结论与接入路线

原版**不是"登录一次管很久"**，而是五件事叠加：

```text
① 每 10 分钟打一次 /passport/token/beat/v2/ 心跳；网络失败也照样按周期续期
② 每一个响应都扫 X-Tt-Token 响应头，变了就落盘（服务端可在任意接口轮换 token）
③ Cookie 跨域共享：.snssdk.com / .zijieapi.com / .fqnovel.com … 视为同一份 jar（扁平串，不分 host）
④ token 与 cookie 严格分头送：X-Tt-Token 只放 token，Cookie 只放 cookie
⑤ 失效只认 data.error_name == session_expired；HTTP 200 / 网络异常都不算登出
```

缺任何一条，表现都是「用一阵子就掉登录」。

**本项目当前的实际状态**（已逐行核对，见 §5.3）：
只做了「登录时收一次 token + 收一份 cookie」，**没有心跳、不扫响应头轮换、且把整段 cookie 串塞进了
`x-tt-token`**。所以掉线是必然的，而且第 4 条 bug 会让「补上心跳」之后播放接口仍然取不到地址。

### 0.1 五步接入（30 分钟）

| 步 | 动作 | 落点（绝对路径） | 验收 |
|---|---|---|---|
| 1 | 先修 `withSession()`：token 与 cookie 分开 | `android/core/.../ContentRepository.kt` L614-632 | 抓包里 `x-tt-token` 只有 300+ 字符的 hex，不再含 `=` |
| 2 | 加 6 个 core 文件 + 3 个 app 文件（§4） | `android/core/src/main/kotlin/com/hgtv/star/core/session/`、`android/app/src/main/kotlin/com/hgtv/star/data/` | `./gradlew :core:test` 通过 |
| 3 | `defaultHttpClient()` 挂 `SessionInterceptor`；`Application` 调 `SessionBootstrap.init` | 见 §4.10 | 任意业务请求都带 `X-Tt-Token` 与 `Cookie: sessionid=` |

### 0.2 掉线归因速查

| 你观察到的现象 | 真实根因 | 对应章节 |
|---|---|---|
| 登录后 10~40 分钟必掉，重登又好 | 从没打过 `beat`，服务端 TTL 到期 | §1.1 / §4.5 |
| 用 1~3 天突然掉，重登很快又掉 | 只存登录响应的 token，没扫响应头轮换，token 与 cookie 版本错位 | §1.7 / §4.3 |
| 掉线时 `beat` 明明返回 200 | 判的是 HTTP code，不是 `data.error_name` | §1.9 / §2.1 |
| 一断网/切 WiFi 就掉 | 把 `IOException` 当会话失效，直接清号 | §3 / §4.5 |
| `beat` 一直 `session_expired` 但 cookie 明明有 `sessionid` | cookie 按 host 分组存，`security.snssdk.com` 取不到 `api*.fqnovel.com` 的 cookie | §1.12 / §4.1 |
| 每次冷启动都像首次登录 | `first_beat` 没持久化 / 每次重跑 `device_register` | §1.3 / §6 |
| 后台待久了回前台掉线 | 系统冻结后台定时任务，心跳出现空窗 | §4.5 `onForeground()` |
| 搜索能出结果、播放取不到地址 | `x-tt-token` 里塞了整段 cookie（≥99 字符判死） | §5.3 第 1 条 |
| 导入 `cookieStore.xml` 能用几小时就掉 | 只有 cookie 没有 token，且没心跳；token 只能靠响应头回写拿到 | §5.3 第 4 条 |

> 前两条与最后两条占实际案例的九成以上。改之前先用 §7.1 抓一次包确认缺哪一环，别盲改。

## 2. 协议规范（可直接照着实现）

### 2.1 心跳

```
GET https://security.snssdk.com/passport/token/beat/v2/?scene={scene}&first_beat={true|false}
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `scene` | `boot` / `polling` / `wap_login` / `frontier` | 冷启动 / 定时 / wap 登录后 / 推送触发 |
| `first_beat` | `true` / `false` | 仅首次为 true，成功后永久 false |

请求头（最小可用集）：

```
X-Tt-Token: <token>
Cookie: sessionid=...; sid_guard=...; sid_tt=...; uid_tt=...; d_ticket=...
X-Tt-Store-Region: cn
X-Tt-Store-Region-Src: did
sdk-version: 2
passport-sdk-version: 5051452
X-SS-DP: 8662
Accept: application/json
User-Agent: <VendorConstants.userAgent(device)>
```

响应判定：

| 条件 | 处理 |
|---|---|
| `data.error_name == "session_expired"` | 清 token + 清 cookie + 广播掉线 |
| `data.error_code == 0` 或 `message == "success"` | 有效，续期 |
| HTTP 400 | 只报自检错误，**不登出** |
| HTTP 404 / `detail_error_message == "Not Found"` | 关掉 config 上报，**不登出** |
| 网络异常 / 超时 / 5xx | 退避重试，**不登出** |
| 响应头带 `X-Tt-Token` | 覆盖本地 token |

> **本工程实测补充（§5.3 第 1 条的由来）**：`x-tt-token` 一旦混进整段 cookie 串（800+ 字符），
> `api5-normal-*.fqnovel.com` 上的播放取地址接口会回 `200 + 0 字节`；同一份凭证只带 `Cookie` 头时
> 15/15 稳定命中 `code 0`。真机 App 在这条路径上用的是 **355 字符**的 hex token。
> 结论：token 与 cookie 必须分头送，且播放路径**只补 Cookie**。

### 2.2 账号信息

```
GET https://security.snssdk.com/passport/account/info/v2/?scene={boot|normal|polling}
```

判定同上（`session_expired` 才登出）。

### 2.3 登出（仅在明确失效时调用，可选）

```
POST https://security.snssdk.com/passport/user/logout/
form: logout_from=<sdk_expired_logout|frontier>
```

原版 `TTTokenManager.logout(str, cb)`：`request(url, null, {"logout_from": str}, false, cb)`。
注意第三个参数 `false` = 不注入 token（因为 token 已清）。

## 3. 状态机

```
                 ┌──────────────────────────────────────────┐
                 │              LoggedOut                    │
                 └───────────────┬──────────────────────────┘
                                 │ 登录成功（sessionid + X-Tt-Token）
                                 ▼
                 ┌──────────────────────────────────────────┐
     onAppStart  │              LoggedIn                     │
   ─────────────►│  first_beat=true → beat("boot")           │
                 │  account/info?scene=boot                  │
                 │  start(): 每 600s beat("polling")         │
                 └───┬───────────────────────────┬──────────┘
                     │                           │
       响应头 X-Tt-Token 变化             data.error_name
       → saveToken()                    == "session_expired"
       （继续 LoggedIn）                        │
                     │                           ▼
                     │              ┌────────────────────────┐
                     │              │  clearToken + clearCookie│
                     │              │  广播 session_expired   │
                     │              └───────────┬────────────┘
                     │                          ▼
                     └──────────────────►  LoggedOut
```

失败重试策略：

```
第 n 次失败（网络/5xx/超时）→ 退避：10min → 10min（原版是固定 10min）
                              ★ 绝不清凭证
第 n 次成功 → 重置退避，恢复 10min
session_expired → 立即清凭证，停止循环
```

### 4.1 `CookieRecord.kt`（core）

**作用**：把一条 `Set-Cookie` 解析成会话要的三项，并提供「合并进扁平串」的唯一实现。

**为什么这样写**：`sid_guard` 的值里带 `%7C`、`Expires` 的值里带逗号，因此只按 `;` 切分；`Max-Age` 优先于 `Expires`（RFC 6265）；`Max-Age=0` 必须**删除**而不是写空值。

```kotlin
package com.hgtv.star.core.session

/**
 * 一条 `Set-Cookie` 解析后的结果。只保留会话用得到的三项：`name` / `value` / 过期时刻。
 *
 * **刻意丢掉 `Domain` / `Path`**：本工程的 cookie 是扁平串（`AccountCredentials.cookie`），
 * 所有 host 共用一份。这与原版 `share_cookie_host_list` 的效果一致，也是「心跳拿不到
 * `sessionid`」这个最常见掉线原因的根治办法——按 host 分组存时，
 * `security.snssdk.com` 取不到 `api5-*.fqnovel.com` 下那份 `sessionid`。
 */
data class CookieRecord(
    val name: String,
    val value: String,
    /** 绝对毫秒；`0` 表示会话 cookie。 */
    val expiresAt: Long = 0L,
    /** 服务端要求删除这一条（`Max-Age=0` / 负值 / `Expires` 已过）。 */
    val deletion: Boolean = false,
) {
    val isExpired: Boolean get() = expiresAt in 1 until System.currentTimeMillis()

    /** 拼进 `Cookie:` 头的那一段。 */
    val pair: String get() = "$name=$value"

    companion object {
        private val DATE_FORMATS = listOf(
            "EEE, dd MMM yyyy HH:mm:ss zzz",
            "EEEE, dd-MMM-yy HH:mm:ss zzz",
            "EEE MMM d HH:mm:ss yyyy",
        )

        /**
         * 解析一条 `Set-Cookie`；不是 cookie 行返回 null。
         *
         * 注意 `sid_guard` 的值里带 `%7C`、`Expires` 的值里带逗号，
         * 因此**只按 `;` 切分**，不在值里再切。
         */
        fun parse(raw: String?): CookieRecord? {
            val text = raw?.trim().orEmpty()
            if (text.isEmpty()) return null
            val parts = text.split(';')
            val first = parts[0].trim()
            val eq = first.indexOf('=')
            if (eq <= 0) return null
            val name = first.substring(0, eq).trim()
            if (name.isEmpty()) return null
            val value = first.substring(eq + 1).trim()

            var expiresAt = 0L
            var maxAgeSeen = false
            var deleteByMaxAge = false
            var deleteByExpires = false
            for (index in 1 until parts.size) {
                val attr = parts[index].trim()
                val at = attr.indexOf('=')
                val key = (if (at >= 0) attr.substring(0, at) else attr).trim().lowercase()
                val v = if (at >= 0) attr.substring(at + 1).trim() else ""
                when (key) {
                    "max-age" -> {
                        val seconds = v.toLongOrNull() ?: continue
                        maxAgeSeen = true
                        if (seconds <= 0L) deleteByMaxAge = true
                        else expiresAt = System.currentTimeMillis() + seconds * 1000L
                    }
                    // RFC 6265：`Max-Age` 优先于 `Expires`
                    "expires" -> if (!maxAgeSeen) {
                        val at2 = parseDate(v)
                        if (at2 != null) {
                            if (at2 <= System.currentTimeMillis()) deleteByExpires = true else expiresAt = at2
                        }
                    }
                }
            }
            val deletion = deleteByMaxAge || deleteByExpires
            return CookieRecord(name, value, expiresAt, deletion)
        }

        fun parseDate(raw: String): Long? {
            for (pattern in DATE_FORMATS) {
                val parsed = runCatching {
                    java.text.SimpleDateFormat(pattern, java.util.Locale.US).apply {
                        timeZone = java.util.TimeZone.getTimeZone("GMT")
                        isLenient = false
                    }.parse(raw)
                }.getOrNull()
                if (parsed != null) return parsed.time
            }
            return null
        }

        /** `Cookie:` 头 → `name -> value`（同名保留最后一个）。 */
        fun headerToMap(header: String): MutableMap<String, String> {
            val out = LinkedHashMap<String, String>()
            for (segment in header.split(';')) {
                val part = segment.trim()
                val at = part.indexOf('=')
                if (at > 0) out[part.substring(0, at).trim()] = part.substring(at + 1).trim()
            }
            return out
        }

        fun mapToHeader(map: Map<String, String>): String =
            map.entries.joinToString("; ") { (name, value) -> "$name=$value" }

        /**
         * 把一批 `Set-Cookie` 合并进现有 cookie 串。
         *
         * * 同名覆盖（最后写入胜出，与 `uk0.f` 的 `uri|name` 覆盖语义一致）；
         * * `Max-Age=0` / `Expires` 已过 → **移除**，而不是写空值；
         * * 其它属性（`Path` / `Domain` / `HttpOnly` / `Secure` / `SameSite`）忽略。
         */
        fun merge(header: String, setCookies: List<String>): String {
            if (setCookies.isEmpty()) return header
            val map = headerToMap(header)
            var changed = false
            for (raw in setCookies) {
                val rec = parse(raw) ?: continue
                if (rec.deletion) {
                    if (map.remove(rec.name) != null) changed = true
                    continue
                }
                if (map[rec.name] != rec.value) {
                    map[rec.name] = rec.value
                    changed = true
                }
            }
            return if (changed) mapToHeader(map) else header
        }

        /** 从 cookie 串里取一项（`store-region` 这类）。 */
        fun value(header: String, name: String): String = headerToMap(header)[name].orEmpty()
    }
}
```

### 4.2 `SessionState.kt`（core）

**作用**：会话状态的接口 + 全局单例出口 `SessionBridge`。

**为什么这样拆**：`android/core` 是 `kotlin("jvm")` 纯 Kotlin 模块（见 `core/build.gradle.kts`），编译期**没有** `android.*`。`SharedPreferences` 只能放 app 模块，所以状态用接口注入；而 `ContentRepository` 在**构造时**就建好了 `OkHttpClient`（`val http: OkHttpClient = defaultHttpClient()`），拦截器必须每次请求现读一个可变引用，才能做到「先建 client、后登录」也不丢会话。

```kotlin
package com.hgtv.star.core.session

import okhttp3.Request

/**
 * 会话状态的最小接口。**放在 `core` 里、不带任何 Android 类型**：
 *
 * `android/core` 是 `kotlin("jvm")` 纯 Kotlin 模块（见 `core/build.gradle.kts`），
 * 编译期没有 `android.*`。因此：
 *
 * * `CookieRecord` / 请求头装配 / 拦截器 / 心跳（本文件与同包其余文件）→ `core`
 * * `SharedPreferences` 实现、广播、`Application` 接线 → `app`（`com.hgtv.star.data.AppSessionStore`）
 *
 * 这样 `ContentRepository` 的默认 client（`defaultHttpClient()`）可以直接装上拦截器，
 * 不必改任何一处 `ContentRepository(...)` 的调用点——工程里至少有四处
 * （`MainActivity.repository`、`FavoriteMonitor`、播放预取、`PlaybackTransport`）。
 */
interface SessionState {
    /** 当前 `X-Tt-Token`。 */
    val token: String

    /** 会话 cookie 的扁平串（`name=value; name=value`）。 */
    val cookieHeader: String

    /** 设备注册下发的 cookie（`install_id` / `ttreq` / `store-region` …）。 */
    val deviceCookies: Map<String, String>

    /** `store-region`，以 cookie 里那份为准；没有时 `cn`。 */
    val storeRegion: String

    /** 真机设备档案（`account-device` 那份 JSON 解出来的）。心跳的 `User-Agent` 用它。 */
    val deviceProfile: Map<String, String>

    /**
     * 原版 `first_beat`：只有首次心跳带 `true`，成功后永久 `false`。
     *
     * 每次启动都发 `true` 会被服务端当成重复首刷（原版 `b.k` 与 `c.a` 都会把它写成 false 并落盘）。
     */
    var firstBeat: Boolean

    /** token 真的变了才落盘，并返回是否变化。 */
    fun saveToken(token: String, tsSign: String = ""): Boolean

    /** 合并一批 `Set-Cookie`，返回是否有变化。 */
    fun mergeSetCookie(setCookies: List<String>): Boolean

    /** 设备注册下发的 cookie（`install_id` / `ttreq` / `store-region` …）落盘。 */
    fun saveDeviceCookies(cookies: Map<String, String>)

    /**
     * 只清会话（token / ts-sign / cookie），**不动设备身份与设备档案**。
     *
     * 设备身份（`registered-device-id` / `registered-install-id`）是「这台设备」的凭据，
     * 退出登录后必须保留：换账号登录时平台仍要认出同一台设备，否则会再要一次上行短信。
     */
    fun clearSession()
}

/**
 * 全局唯一的会话出口。
 *
 * 为什么要一个全局 object：`core` 里的 client 是**在对象构造时**建好的
 * （`ContentRepository(val http: OkHttpClient = defaultHttpClient())`），而会话是在
 * `Application.onCreate` 之后才就绪的。把 [state] 做成可空的可变引用，拦截器每次请求时现读，
 * 就能做到「先建 client、后登录」也不丢会话。
 *
 * `state` 为空 = 匿名（未登录），拦截器只补设备 cookie，不补 token。
 */
object SessionBridge {
    @Volatile var state: SessionState? = null

    /** 确认失效时的回调（`app` 层接广播 + 清 UI）。 */
    @Volatile var onExpired: ((reason: String) -> Unit)? = null

    /** token 轮换时的回调（落外部镜像 / 打日志用）。 */
    @Volatile var onTokenChanged: ((token: String) -> Unit)? = null

    /** 诊断日志出口；`core` 没有 `android.util.Log`，由 `app` 注入。 */
    @Volatile var log: (String) -> Unit = {}

    /**
     * 把会话身份补到一个请求上。**token 与 cookie 严格分开**：
     *
     * ```
     * X-Tt-Token: <token>                        ← 只有 token
     * Cookie: <device cookies>; <session cookie>  ← 只有 cookie
     * ```
     *
     * 这是本工程当前最严重的既有缺陷所在：`ContentRepository.withSession()` 把**整段
     * cookie 串**也塞进了 `x-tt-token`（`ContentRepository.kt` L617）。搜索接口容忍这种写法，
     * 播放与账号接口不容忍——`x-tt-token` 实测 ≥99 字符直接判死、回 `200 + 0 字节`。
     */
    fun decorate(builder: Request.Builder, injectToken: Boolean = true): Request.Builder {
        val current = state
        val merged = LinkedHashMap<String, String>()
        current?.deviceCookies?.forEach { (name, value) -> if (name.isNotBlank() && value.isNotBlank()) merged[name] = value }
        current?.cookieHeader?.takeIf { it.isNotBlank() }?.let { merged.putAll(CookieRecord.headerToMap(it)) }

        val token = current?.token.orEmpty()
        if (injectToken && token.isNotEmpty()) builder.header("X-Tt-Token", token)
        if (merged.isNotEmpty()) builder.header("Cookie", CookieRecord.mapToHeader(merged))

        builder.header("X-SS-DP", "8662")
        builder.header("X-Tt-Store-Region", current?.storeRegion ?: "cn")
        builder.header("X-Tt-Store-Region-Src", "did")
        builder.header("Sdk-Version", "2")
        builder.header("passport-sdk-version", "5051452")
        builder.header("X-Xs-From-Web", "0")
        return builder
    }

    /** 当前要发给心跳的 `Cookie` 头（设备 + 会话）。 */
    fun cookieHeaderForBeat(): String {
        val current = state ?: return ""
        val merged = LinkedHashMap<String, String>()
        current.deviceCookies.forEach { (name, value) -> if (name.isNotBlank() && value.isNotBlank()) merged[name] = value }
        merged.putAll(CookieRecord.headerToMap(current.cookieHeader))
        return CookieRecord.mapToHeader(merged)
    }

    /**
     * 能不能打心跳。判据是**会话 cookie 或 token 有其一**：
     *
     * * 手机号 / 扫码登录：两样都有；
     * * 导入 `cookieStore.xml`：只有 cookie、没有 `X-Tt-Token`（那份文件里不存 token）。
     *   这种会话照样要心跳——第一次 beat / account/info 的响应头就会把 `X-Tt-Token` 发回来，
     *   拦截器收到即落盘，之后就与登录路径完全一致。若这里死要求 token，
     *   导入来的会话永远不会被心跳续期，正是「导入后能用几小时就掉」的成因。
     */
    fun signedIn(): Boolean {
        val current = state ?: return false
        return current.token.isNotEmpty() || current.cookieHeader.contains("sessionid=")
    }

    fun saveToken(token: String, tsSign: String = ""): Boolean {
        val changed = state?.saveToken(token, tsSign) ?: false
        if (changed) onTokenChanged?.invoke(token)
        return changed
    }

    /** 清会话（退出登录 / 确认失效）。设备身份不受影响。 */
    fun clearSession() { state?.clearSession() }

    fun mergeSetCookie(setCookies: List<String>): Boolean = state?.mergeSetCookie(setCookies) ?: false

    /**
     * 服务端说会话过期（`data.error_name == "session_expired"`）。
     *
     * **不在这里清凭证**：本方法可能在响应体还没读完时被调（拦截器），当场清 token 会让
     * 同一批在途请求全部退化成匿名请求。这里只把标记交给 [SessionKeeper]，
     * 由它在心跳回调里统一执行。
     */
    fun markExpired(reason: String) { pendingExpiry = reason }
    @Volatile var pendingExpiry: String? = null
}
```

### 4.3 `SessionInterceptor.kt`（core）

**作用**：对齐原版 `px7/a.java` 的拦截器——补身份、扫 `X-Tt-Token`、合并 `Set-Cookie`、嗅探 `session_expired`。

**关键**：`X-Tt-Token` 只放 token，`Cookie` 只放 cookie；播放取地址路径额外**只补 Cookie 不补 token**（实测那条接口对 token 长度极度敏感）。

```kotlin
package com.hgtv.star.core.session

import okhttp3.Interceptor
import okhttp3.Response

/**
 * 对齐原版 `px7/a.java`（Retrofit 拦截器）+ `TTTokenManager.addRequestHeader`
 * / `processResponseHeader`。三件事：
 *
 * 1. **补身份**（只对会话 host）：`x-tt-token` 只放 token、`Cookie` 只放 cookie；
 * 2. **每个响应扫 `X-Tt-Token`**：服务端可以在任意接口的响应头里换 token；
 * 3. **每个响应合并 `Set-Cookie`**：登录之外的接口也会下发 / 删除 cookie。
 *
 * 挂在哪：`ContentRepository.defaultHttpClient()`。这样 `MainActivity.repository`、
 * `FavoriteMonitor`、播放预取、`PlaybackTransport` 四处 `ContentRepository(...)` 自动都带上，
 * 不必改调用点（`ContentRepository(http)` 传进来的 client 也应先 `.newBuilder()
 * .addInterceptor(SessionInterceptor()).build()`）。
 */
class SessionInterceptor(
    /**
     * 是否给会话 host 补 `X-Tt-Token`。
     *
     * 默认 `true`（与真机一致：App 每个业务请求都带 token）。若某条接口在补齐之后回空
     * （本工程 `videoModel` 曾经因为 `x-tt-token` 里放了整段 cookie 而回空），
     * 先把这里关掉定位，再按 §5.3 修正 token 内容——**不要**退化成「不带 token」长期运行。
     */
    private val injectToken: Boolean = true,
) : Interceptor {

    override fun intercept(chain: Interceptor.Chain): Response {
        val original = chain.request()
        val host = original.url().host()
        val sessionHost = isSessionHost(host)

        // ★ 只补一次：业务代码自己 set 过的不覆盖（`ContentRepository.text` 里已有
        //   `X-SS-DP` / `X-Tt-Store-Region`，重复 set 同值无害；但 `videoModel` 显式只补
        //   Cookie 的那条路径不能被这里改成「也补 token」以外的样子）。
        // 播放取地址接口（`/novel/player/...`）**只补 Cookie、不补 token**：
        // `ContentRepository.videoModel` 的注释记着实测结论——这条接口对 `x-tt-token` 的长度
        // 极其敏感（整段 cookie 串 800 多字符塞进去直接回 `200 + 0 字节`），而真机 App 在这条
        // 路径上用的是一个 355 字符的 hex token。Cookie 才是它真正的门槛，token 不是必需品。
        val skipToken = original.url().encodedPath().startsWith("/novel/player/")
        val request = if (sessionHost) {
            SessionBridge.decorate(original.newBuilder(), injectToken && !skipToken).build()
        } else original
        val response = chain.proceed(request)

        if (sessionHost) {
            val rotated = response.header("X-Tt-Token")
            if (!rotated.isNullOrBlank() && rotated != SessionBridge.state?.token) {
                if (SessionBridge.saveToken(rotated)) SessionBridge.log("token rotated by ${original.url().host()}")
            }
            SessionBridge.mergeSetCookie(response.headers("Set-Cookie"))
            sniffExpired(response)
        }
        return response
    }

    /**
     * `session_expired` 嗅探。**只看 body 里的 `data.error_name`**，不看状态码：
     * beat 过期时服务端照样回 `HTTP 200`。
     *
     * 只嗅探小 JSON 响应：媒体分片（`/novel/player/` 下的 206）与超过 32 KB 的响应跳过，
     * 用 `peekBody` 复制一份，下游照常读原 body。
     */
    private fun sniffExpired(response: Response) {
        if (SessionBridge.state == null) return
        val path = response.request().url().encodedPath()
        if (path.startsWith("/novel/player/")) return
        val length = response.body()?.contentLength() ?: -1L
        if (length <= 0L || length > SNIFF_LIMIT) return
        val text = runCatching { response.peekBody(SNIFF_LIMIT).string() }.getOrNull() ?: return
        if (!text.contains("session_expired", ignoreCase = true)) return
        val flag = runCatching {
            org.json.JSONObject(text).optJSONObject("data")?.optString("error_name").orEmpty()
        }.getOrNull().orEmpty()
        if (flag.equals("session_expired", ignoreCase = true)) {
            SessionBridge.markExpired("http:${response.code()}")
        }
    }

    private fun isSessionHost(host: String): Boolean {
        val h = host.lowercase()
        return SESSION_HOSTS.any { h == it || h.endsWith(".$it") }
    }

    private companion object {
        /** 对齐原版 `share_cookie_host_list`（`dc5/a.java`） */
        val SESSION_HOSTS = listOf(
            "snssdk.com", "zijieapi.com", "ulpay.com", "fqnovel.com",
            "ecombdapi.com", "luckysf.net", "iluckysf.net",
            "awemeughun.com", "awemeugsoul.com",
        )
        const val SNIFF_LIMIT = 32L * 1024
    }
}

### 4.4 `SessionHeaders.kt`（core）

### 4.5 `SessionKeeper.kt`（core）

**作用**：10 分钟心跳 + `account/info` 同步 + frontier + 60 秒自检。

**为什么用 `ScheduledExecutorService` 而不是 `Handler`**：`core` 没有 Android SDK，而且 Handler 的 `postDelayed` 在 Doze 下会被整体推迟；单线程调度器不受这个影响。

```kotlin
package com.hgtv.star.core.session

import okhttp3.Call
import okhttp3.Callback
import okhttp3.OkHttpClient
import okhttp3.Request
import org.json.JSONObject
import java.io.IOException
import java.util.concurrent.Executors
import java.util.concurrent.ScheduledExecutorService
import java.util.concurrent.ScheduledFuture
import java.util.concurrent.TimeUnit
import java.util.concurrent.atomic.AtomicBoolean

/**
 * 心跳保活。对齐原版：
 *
 * * `com/ss/android/token/b.java` —— `sendEmptyMessageDelayed(1000, 600000)` 的 10 分钟循环；
 * * `com/ss/android/token/c.java` —— 成功 / 失败**都续期**，只有 `session_expired` 才清凭证；
 * * `com/bytedance/sdk/account/impl/i.java` —— 账号 SDK 自己那条 10 分钟 `account/info` 轮询；
 * * `com/bytedance/sdk/account/impl/b0.java` —— frontier 主动失效通道。
 *
 * ## 为什么不用 `android.os.Handler`
 *
 * `android/core` 是 `kotlin("jvm")` 纯 Kotlin 模块，编译期没有 `android.*`；而且 Handler 的
 * `postDelayed` 在 Doze 下会被整体推迟。这里用 `ScheduledExecutorService`（后台单线程），
 * 后台冻结时它不会「停表」——下一次真正跑起来时会立刻补上，空窗不会被无限放大。
 *
 * ## 三条铁律（缺一条就会「用一阵子掉登录」）
 *
 * 1. **失败也续期**：网络异常、5xx、400、404 一律不清凭证，10 分钟后接着打；
 * 2. **只认 `data.error_name == "session_expired"`**：过期时 HTTP 状态码仍是 200；
 * 3. **token 与 cookie 分开**：`X-Tt-Token` 只放 token，`Cookie` 只放 cookie。
 */
class SessionKeeper(
    private val client: OkHttpClient,
    /** 设备档案头（`User-Agent` / `X-VC-Bdturing-Sdk-Version` / `Lc` …），与业务请求同一份。 */
    private val deviceHeaders: () -> Map<String, String> = { emptyMap() },
    /** 确认失效时回调（清 UI / 广播），由装配层接。 */
    private val onExpired: (reason: String) -> Unit = {},
    private val log: (String) -> Unit = {},
) {
    private val scheduler: ScheduledExecutorService =
        Executors.newSingleThreadScheduledExecutor { task ->
            Thread(task, "hgtv-session-beat").apply { isDaemon = true }
        }

    @Volatile private var tick: ScheduledFuture<*>? = null
    @Volatile private var selfCheck: ScheduledFuture<*>? = null
    private val beatInFlight = AtomicBoolean(false)
    private val infoInFlight = AtomicBoolean(false)
    @Volatile private var started = false

    // ---------------- 生命周期 ----------------

    /**
     * 冷启动：对齐原版 `b.a()`。
     *
     * `account/info(scene=boot)` + `beat(scene=boot)` + 60 秒后自检，然后排上 10 分钟循环。
     * 重复调用安全（进程内真正的 boot 只跑一次）。
     */
    fun onAppStart() {
        if (!SessionBridge.signedIn()) return
        if (started) { start(); return }
        started = true
        accountInfo(SCENE_BOOT)
        beat(SCENE_BOOT)
        scheduleSelfCheck()
        start()
    }

    /**
     * 回前台：补一次 `polling` + 重排 10 分钟。
     *
     * 为什么必须有：设备休眠 / 厂商省电会让后台定时整体推迟，后台待两小时醒来时上一次心跳
     * 可能已隔了几小时。`Activity.onResume` 里补一发，空窗就收敛到「回前台立即续上」。
     */
    fun onForeground() {
        if (!SessionBridge.signedIn()) return
        started = true
        beat(SCENE_POLLING)
        start()
    }

    /** 用户主动退出：停循环 + 清会话（`Library.clearAccount` 负责清外部镜像）。 */
    fun onLogout() {
        stop()
        started = false
        SessionBridge.pendingExpiry = null
        SessionBridge.clearSession()
    }

    /** 从"现在"起重新计时；重复调用安全（先取消旧任务再排新的）。 */
    @Synchronized
    fun start() {
        if (!SessionBridge.signedIn()) return
        tick?.cancel(false)
        tick = scheduler.schedule({ runBeatTick() }, INTERVAL_MS, TimeUnit.MILLISECONDS)
    }

    @Synchronized
    fun stop() {
        tick?.cancel(false)
        tick = null
        selfCheck?.cancel(false)
        selfCheck = null
    }

    /** 进程退出用（`MainActivity` 的网络清理里可以调）。 */
    fun shutdown() {
        stop()
        scheduler.shutdownNow()
    }

    // ---------------- 心跳 ----------------

    private fun runBeatTick() {
        expireIfFlagged()
        beat(SCENE_POLLING)
    }

    fun beat(scene: String) {
        expireIfFlagged()
        if (!SessionBridge.signedIn()) { stop(); return }
        if (!beatInFlight.compareAndSet(false, true)) return
        val first = SessionBridge.state?.firstBeat ?: true
        val url = "$BEAT_BASE?scene=$scene&first_beat=$first"
        client.newCall(beatRequest(url)).enqueue(object : Callback {
            override fun onFailure(call: Call, e: IOException) {
                beatInFlight.set(false)
                // ★ 网络失败不清凭证：原版 c.b() 走的就是这条路，末尾照样续期
                log("beat($scene) net=${e.javaClass.simpleName}")
                finishBeat()
            }

            override fun onResponse(call: Call, response: okhttp3.Response) {
                beatInFlight.set(false)
                val code = response.code()
                val body = runCatching { response.body()?.string().orEmpty() }.getOrDefault("")
                response.header("X-Tt-Token")?.takeIf { it.isNotBlank() }?.let { SessionBridge.saveToken(it) }
                runCatching { response.close() }

                if (isSessionExpired(body)) {
                    log("beat($scene) session_expired -> logout")
                    expire("beat")
                    return
                }
                when {
                    code == 400 -> log("beat($scene) http 400 (self-check only)")
                    code == 404 -> log("beat($scene) http 404 (config off)")
                    code !in 200..299 -> log("beat($scene) http $code")
                }
                SessionBridge.state?.firstBeat = false
                finishBeat()
            }
        })
    }

    private fun finishBeat() {
        if (!SessionBridge.signedIn()) { stop(); return }
        start()
    }

    // ---------------- 账号信息 ----------------

    /**
     * `GET /passport/account/info/v2/?scene=…`：把服务端的会话状态同步回来。
     * 判定与 beat 完全相同——只有 `session_expired` 才登出。
     */
    fun accountInfo(scene: String) {
        if (!SessionBridge.signedIn()) return
        if (!infoInFlight.compareAndSet(false, true)) return
        client.newCall(beatRequest("$ACCOUNT_INFO_BASE?scene=$scene")).enqueue(object : Callback {
            override fun onFailure(call: Call, e: IOException) {
                infoInFlight.set(false)
                log("accountInfo($scene) net=${e.javaClass.simpleName}")
            }

            override fun onResponse(call: Call, response: okhttp3.Response) {
                infoInFlight.set(false)
                val body = runCatching { response.body()?.string().orEmpty() }.getOrDefault("")
                response.header("X-Tt-Token")?.takeIf { it.isNotBlank() }?.let { SessionBridge.saveToken(it) }
                runCatching { response.close() }
                if (isSessionExpired(body)) {
                    log("accountInfo($scene) session_expired -> logout")
                    expire("account_info")
                }
            }
        })
    }

    // ---------------- frontier ----------------

    /**
     * 长连接推来「会话可能要失效」时调用（对齐 `b0.b()`）：
     * 暂停轮询 → 立刻打一次 `scene=frontier` → 3 秒后恢复轮询。
     *
     * 没有这条通道也能保活，只是被踢下线最多晚 10 分钟才发现。
     */
    fun onFrontierMessage(raw: String) {
        if (!SessionBridge.signedIn()) return
        val json = runCatching { JSONObject(raw) }.getOrNull() ?: return
        if (json.optBoolean("degrade", false)) return
        stop()
        beat(SCENE_FRONTIER)
        scheduler.schedule({ if (SessionBridge.signedIn()) start() }, FRONTIER_RESUME_MS, TimeUnit.MILLISECONDS)
    }

    // ---------------- 内部 ----------------

    private fun beatRequest(url: String): Request {
        val builder = Request.Builder()
            .url(url)
            .get()
            .header("X-Tt-Token", SessionBridge.state?.token.orEmpty())
            .header("X-SS-DP", "8662")
            .header("X-Tt-Store-Region", SessionBridge.state?.storeRegion ?: "cn")
            .header("X-Tt-Store-Region-Src", "did")
            .header("sdk-version", "2")
            .header("passport-sdk-version", "5051452")
            .header("Accept", "application/json")
        // 心跳必须同时带设备 cookie（`install_id` / `ttreq`），否则平台认不出这台设备
        SessionBridge.cookieHeaderForBeat().takeIf { it.isNotEmpty() }?.let { builder.header("Cookie", it) }
        deviceHeaders().forEach { (name, value) -> if (value.isNotBlank()) builder.header(name, value) }
        return builder.build()
    }

    /** ★ 唯一判定入口：HTTP 200 + body 里的 `data.error_name`。 */
    private fun isSessionExpired(body: String): Boolean {
        if (body.isBlank()) return false
        val data = runCatching { JSONObject(body).optJSONObject("data") }.getOrNull() ?: return false
        return data.optString("error_name").equals(ERR_SESSION_EXPIRED, ignoreCase = true)
    }

    private fun expire(reason: String) {
        stop()
        started = false
        // 清凭证在这里做（而不是在拦截器里）：此时已确认是 `session_expired`，
        // 且没有下游还在读响应体。
        SessionBridge.clearSession()
        onExpired(reason)
    }

    /**
     * 消费拦截器留下的标记（拦截器在响应体线程上只能标记，见 `SessionBridge.markExpired`）。
     */
    fun expireIfFlagged() {
        val reason = SessionBridge.pendingExpiry ?: return
        SessionBridge.pendingExpiry = null
        if (SessionBridge.signedIn()) return   // 标记可能是上一次会话留下的
        expire(reason)
    }

    private fun scheduleSelfCheck() {
        selfCheck?.cancel(false)
        selfCheck = scheduler.schedule({
            // 对齐原版 handleMsg(2000)：登录着但循环没跑起来，就把它拉起来
            if (SessionBridge.signedIn() && tick == null) {
                log("self-check: beat loop not scheduled, restart")
                start()
            }
        }, SELF_CHECK_DELAY_MS, TimeUnit.MILLISECONDS)
    }

    companion object {
        /** 原版 `z68.c.f484030d` = 600000。 */
        const val INTERVAL_MS = 600_000L
        /** 原版 `sendEmptyMessageDelayed(2000, 60000)`。 */
        const val SELF_CHECK_DELAY_MS = 60_000L
        const val FRONTIER_RESUME_MS = 3_000L

        const val SCENE_BOOT = "boot"
        const val SCENE_POLLING = "polling"
        const val SCENE_FRONTIER = "frontier"
        const val SCENE_WAP = "wap_login"

        const val ERR_SESSION_EXPIRED = "session_expired"

        /** 硬编码在 `TTTokenManager.getHost()` 里，与原版一致。 */
        const val BEAT_BASE = "https://security.snssdk.com/passport/token/beat/v2/"
        const val ACCOUNT_INFO_BASE = "https://security.snssdk.com/passport/account/info/v2/"
    }
}

### 4.6 `SessionClients.kt`（core）

**作用**：心跳专用 client（独立超时、独立连接池）。

**为什么独立**：`MainActivity.onDestroy` 会 `dispatcher().cancelAll()` + `connectionPool().evictAll()`（`MainActivity.kt` L1326），心跳若共用同一个 client 会被一起掐断。

```kotlin
package com.hgtv.star.core.session

import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

/**
 * 会话模块自己的 client。**只给心跳用**，不复用业务 client：
 *
 * * 业务 client 的 `callTimeout` 是 45 秒、`readTimeout` 30 秒（见 `ContentRepository`），
 *   心跳没必要等这么久；
 * * 心跳要能在业务 client 被 `cancelAll()` / 连接池被 `evictAll()` 时**不受影响**
 *   （`MainActivity` 的网络清理会干这件事）。
 *
 * 业务 client 不需要单独建：`defaultHttpClient()` 里加一行 `addInterceptor(SessionInterceptor())`
 * 就够（见 `ContentRepository.kt` L96）。
 */
object SessionClients {
    /**
     * 复刻 `HgtvTls.configure` 的**最小**效果：把系统 TLS 装上。
     *
     * `HgtvTls` 在 `core` 的默认包（`com.hgtv.star.core`）里是 `public object`，
     * 同模块直接 `HgtvTls.configure(builder)` 即可；这里显式写全限定名，
     * 是因为本文件在子包里、且 §4 的示例要与 `ContentRepository` 的用法保持一字不差。
     */
    private fun tls(builder: OkHttpClient.Builder): OkHttpClient.Builder =
        com.hgtv.star.core.HgtvTls.configure(builder)

    fun forBeat(): OkHttpClient =
        tls(OkHttpClient.Builder())
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .writeTimeout(15, TimeUnit.SECONDS)
            .callTimeout(20, TimeUnit.SECONDS)
            .retryOnConnectionFailure(true)
            // 心跳**不要**自动重试整套请求链：一次 beat 失败就等下一个 10 分钟，别放大流量
            .addInterceptor(SessionInterceptor())
            .build()
}

### 4.7 `AppSessionStore.kt`（app）

**作用**：`SessionState` 的 `SharedPreferences` 实现，**读写工程里已有的 `native-session-v1`**。

**为什么不新建 SP**：`Library.SessionMirror` 已按 `MIRROR_KEYS` 把这份 SP 镜像到 `/sdcard/.hgtv/`（targetSdk 29 + `requestLegacyExternalStorage` 才能写），卸载重装靠它认回设备与会话。新开一个 SP 等于让镜像少一半内容，重装后仍是「陌生设备 + 老账号」。

```kotlin
package com.hgtv.star.data

import android.content.Context
import android.content.SharedPreferences
import com.hgtv.star.core.AccountCredentialsParser
import com.hgtv.star.core.session.CookieRecord
import com.hgtv.star.core.session.SessionState
import org.json.JSONObject

/**
 * `SessionState` 的落盘实现。**读写的就是工程里已有的 `native-session-v1`**，不新建 SP。
 *
 * | 键 | 谁写 | 说明 |
 * |---|---|---|
 * | `account-cookie` | 本类 / `Library.saveAccount` | 扁平 Cookie 串 |
 * | `account-device` | `Library.saveAccountDevice` | 设备档案 JSON（不动） |
 * | `account-expires` | 本类 / `Library.saveAccount` | `sid_guard` 推算的过期**秒** |
 * | `x-tt-token` | 本类 / `Library.searchToken` | **同一个键**：账号会话与搜索共用一份 token |
 * | `ts-sign` | 本类 | 响应头 `bd-ticket-guard-sign-res-static-ts-sign`，可空 |
 * | `first-beat` | 本类 | 仅首次 `true`，成功 beat 后置 `false` |
 * | `registered-cookies` | `Library.saveRegistrationCookies` | 设备注册下发的 cookie（JSON） |
 *
 * 为什么复用而不是新建 SP：`Library.SessionMirror` 已按 `MIRROR_KEYS` 把这份 SP 镜像到
 * `/sdcard/.hgtv/`，卸载重装后靠它认回设备与会话。新开一个 SP 等于让镜像少一半内容，
 * 重装后仍是「陌生设备 + 老账号」，风控会再要一次上行短信。
 */
class AppSessionStore(
    context: Context,
    /** 外部镜像写入（`Library.mirrorSession`）；为空则只写本机。 */
    private val mirror: (String, String?) -> Unit = { key, value -> SessionBootstrap.mirror?.invoke(key, value) },
) : SessionState {

    private val sp: SharedPreferences =
        context.applicationContext.getSharedPreferences(SP_NAME, Context.MODE_PRIVATE)

    override val token: String
        get() = sp.getString(K_TOKEN, "").orEmpty().trim()

    override val cookieHeader: String
        get() = sp.getString(K_COOKIE, "").orEmpty()

    override val deviceCookies: Map<String, String>
        get() {
            val raw = sp.getString(K_REGISTERED_COOKIES, "").orEmpty()
            if (raw.isBlank()) return emptyMap()
            val json = runCatching { JSONObject(raw) }.getOrNull() ?: return emptyMap()
            return buildMap {
                for (key in json.keys()) {
                    val value = json.optString(key).trim()
                    if (value.isNotEmpty()) put(key, value)
                }
            }
        }

    /** 真机设备档案：`account-device` 里的 JSON（由 `Library.saveAccountDevice` 写入）。 */
    override val deviceProfile: Map<String, String>
        get() {
            val raw = sp.getString(K_DEVICE_PROFILE, "").orEmpty()
            if (raw.isBlank()) return emptyMap()
            val json = runCatching { JSONObject(raw) }.getOrNull() ?: return emptyMap()
            return buildMap {
                for (key in json.keys()) {
                    val value = json.optString(key).trim()
                    if (value.isNotEmpty()) put(key, value)
                }
            }
        }

    override val storeRegion: String
        get() = CookieRecord.value(cookieHeader, "store-region").ifBlank {
            deviceCookies["store-region"].orEmpty().ifBlank { "cn" }
        }

    /**
     * 写 token。**空值 / 占位符直接忽略**（对齐原版：`change.token` 视为未登录），
     * 否则一次异常响应就能把好会话覆盖成空。
     */
    override fun saveToken(token: String, tsSign: String): Boolean {
        val clean = token.trim()
        if (clean.isEmpty() || clean == TOKEN_PLACEHOLDER) return false
        if (clean == this.token && tsSign.trim() == sp.getString(K_TS_SIGN, "").orEmpty()) return false
        val edit = sp.edit().putString(K_TOKEN, clean)
        if (tsSign.isNotBlank()) edit.putString(K_TS_SIGN, tsSign.trim())
        edit.apply()
        mirror(K_TOKEN, clean)
        if (tsSign.isNotBlank()) mirror(K_TS_SIGN, tsSign.trim())
        return true
    }

    /** 合并 `Set-Cookie`：会话响应里 `sid_guard` 会续期，必须跟着更新 `account-expires`。 */
    override fun mergeSetCookie(setCookies: List<String>): Boolean {
        if (setCookies.isEmpty()) return false
        val before = cookieHeader
        val merged = CookieRecord.merge(before, setCookies)
        if (merged == before) return false
        val expires = AccountCredentialsParser.expiryOf(CookieRecord.headerToMap(merged))
        val edit = sp.edit().putString(K_COOKIE, merged)
        if (expires > 0L) edit.putLong(K_EXPIRES, expires)
        edit.apply()
        mirror(K_COOKIE, merged)
        if (expires > 0L) mirror(K_EXPIRES, expires.toString())
        return true
    }

    /** 登录成功 / 导入 `cookieStore.xml` 时用整段串覆盖（`MainActivity.savePhoneLogin` 调用）。 */
    fun replaceCookie(header: String): Boolean {
        val clean = header.trim()
        if (clean.isEmpty() || clean == cookieHeader) return false
        val expires = AccountCredentialsParser.expiryOf(CookieRecord.headerToMap(clean))
        val edit = sp.edit().putString(K_COOKIE, clean)
        if (expires > 0L) edit.putLong(K_EXPIRES, expires)
        edit.apply()
        mirror(K_COOKIE, clean)
        if (expires > 0L) mirror(K_EXPIRES, expires.toString())
        return true
    }

    /** 设备注册成功后把 `install_id` / `ttreq` / `store-region` 存下来（匿名时也要带）。 */
    override fun saveDeviceCookies(cookies: Map<String, String>) {
        val clean = cookies.filterValues { it.isNotBlank() }
        if (clean.isEmpty()) return
        val json = JSONObject().apply { clean.forEach { (key, value) -> put(key, value) } }.toString()
        sp.edit().putString(K_REGISTERED_COOKIES, json).apply()
        mirror(K_REGISTERED_COOKIES, json)
    }

    /**
     * 存成字符串 `"true"/"false"` 而不是 Boolean，是为了迁就 `Library.restoreFromMirror`：
     * 它把外部镜像里除 `account-expires` 以外的键**一律按字符串**写回 SP（见 `Library.kt` L373-378），
     * 用 `getBoolean` 读会永远拿到默认值 `true`，于是每次冷启动都发一遍 `first_beat=true`。
     */
    override var firstBeat: Boolean
        get() = sp.getString(K_FIRST_BEAT, "").orEmpty().ifBlank { "true" }.toBoolean()
        set(value) { sp.edit().putString(K_FIRST_BEAT, value.toString()).apply() }

    /** 只清会话，不动设备身份（`registered-*`）与设备档案。 */
    override fun clearSession() {
        sp.edit().remove(K_TOKEN).remove(K_TS_SIGN).remove(K_COOKIE).remove(K_EXPIRES).apply()
        mirror(K_TOKEN, null)
        mirror(K_TS_SIGN, null)
        // 退出登录 **必须**把 cookie 从镜像里也抹掉，否则下次启动会把刚退掉的账号救回来
        mirror(K_COOKIE, null)
        mirror(K_EXPIRES, null)
        // `first-beat` 刻意保留：重登不代表「新设备首刷」
    }

    companion object {
        /** 与 `Library.sessionPrefs` 同一份文件。 */
        const val SP_NAME = "native-session-v1"
        /**
         * 专用键：**账号会话的 token**。
         *
         * 为什么不复用 `x-tt-token`：那个键是「搜索登录态」的用户设置（`Library.searchToken`），
         * 由用户在设置页手填，退出登录不该把它一起抹掉。两者共用一份会让「退出账号」顺手清掉
         * 用户手填的搜索令牌。想合并也可以，见 §6.2 的一行改法。
         */
        const val K_TOKEN = "session-token"
        const val K_TS_SIGN = "ts-sign"
        const val K_FIRST_BEAT = "first-beat"
        const val K_COOKIE = "account-cookie"
        const val K_EXPIRES = "account-expires"
        const val K_REGISTERED_COOKIES = "registered-cookies"
        /** 与 `Library` 的 `account-device` 同一个键，只读。 */
        const val K_DEVICE_PROFILE = "account-device"
        const val TOKEN_PLACEHOLDER = "change.token"
    }
}

### 4.8 `SessionBootstrap.kt`（app）

**作用**：装配入口，`HgtvApplication.onCreate` 调一次（现在是 MultiDex + 友盟，会话初始化加在它们之后）。

**注意**：`ContentRepository` 有四处实例（`MainActivity.repository`、`FavoriteMonitor`、播放预取、`PlaybackTransport`），所以拦截器挂在 `defaultHttpClient()` 里，而不是靠调用点一个个改。

```kotlin
package com.hgtv.star.data

import android.content.Context
import com.hgtv.star.core.session.SessionBridge
import com.hgtv.star.core.session.SessionInterceptor
import com.hgtv.star.core.session.SessionKeeper
import okhttp3.OkHttpClient

/**
 * 会话装配。**`Application.onCreate` 里调一次**（`HgtvApplication` 现在只有 MultiDex + 友盟，
 * 会话初始化加在它们之后）。
 *
 * 三件事：
 * 1. 建 [AppSessionStore]（读写 `native-session-v1`）并交给 [SessionBridge]；
 * 2. 把 `first_beat` 的读写接到 SP；
 * 3. 记住 `OkHttpClient`（由 `ContentRepository.defaultHttpClient()` 装 [SessionInterceptor]）。
 *
 * 为什么 `OkHttpClient` 不由这里建：`ContentRepository` 的默认参数
 * （`val http: OkHttpClient = defaultHttpClient()`）在**对象构造时**就建 client，
 * 而工程里有四处 `ContentRepository(...)`。只要拦截器挂在 `defaultHttpClient()` 里，
 * 那四处自动都带上会话，不必改调用点。
 */
object SessionBootstrap {

    @Volatile private var keeper: SessionKeeper? = null
    @Volatile private var store: AppSessionStore? = null

    /**
     * 心跳用的设备档案。`Application.onCreate` 时尚且没有登录凭据，先用 SP 里那份；
     * 之后 `updateDevice()` 换掉即可——[SessionKeeper] 持的是 lambda，每次请求现读。
     */
    @Volatile private var device: Map<String, String> = emptyMap()

    val sessionStore: AppSessionStore? get() = store

    /**
     * 外部镜像写入（`/sdcard/.hgtv/`）。由 `Library` 在构造时挂上（它自己持有 `SessionMirror`），
     * 因此这里只存一个回调，不依赖 `Library` 实例。
     */
    @Volatile var mirror: ((String, String?) -> Unit)? = null
    fun attachMirror(block: (String, String?) -> Unit) { mirror = block }

    /** 设备档案有变化（注册成功 / 导入凭据 / 换账号）时调一次。 */
    fun updateDevice(profile: Map<String, String>) { device = profile.filterValues { it.isNotBlank() } }

    private val headers: () -> Map<String, String> = {
        com.hgtv.star.core.session.SessionHeaders.build(device)
    }

    /**
     * @param log 诊断出口（`Log.i("HGTV-SESSION", …)` + `Diagnostics.trace`）。
     * @param onExpired 确认失效时的界面动作（清 UI + 提示）。
     */
    fun init(
        context: Context,
        store: AppSessionStore,
        log: (String) -> Unit = {},
        onExpired: (String) -> Unit = {},
    ) {
        this.store = store
        device = store.deviceProfile
        SessionBridge.state = store
        SessionBridge.log = log
        SessionBridge.onExpired = onExpired
        SessionBridge.onTokenChanged = { token -> log("token rotated len=${token.length}") }

        val client: OkHttpClient = com.hgtv.star.core.session.SessionClients.forBeat()
        keeper = SessionKeeper(
            client = client,
            deviceHeaders = headers,
            onExpired = { reason -> SessionBridge.onExpired?.invoke(reason) },
            log = log,
        )
    }

    /** 冷启动 / 登录成功后调（内部幂等）。 */
    fun onAppStart() { keeper?.onAppStart() }

    /** 每个 Activity 的 `onResume` 调：补一次 heartbeat + 重排 10 分钟。 */
    fun onForeground() { keeper?.onForeground() }

    /** 用户点「退出登录」时先调这里，再 `Library.clearAccount()`。 */
    fun onLogout() { keeper?.onLogout() }

    /** 长连接推来会话变更时调（可选）。 */
    fun onFrontierMessage(raw: String) { keeper?.onFrontierMessage(raw) }
}

### 4.9 `SessionEvents.kt`（app）

**作用**：掉线广播的发送端。**放 app 模块**（`sendBroadcast` 需要 `Context`，core 没有 Android SDK）。

判定在 core（`SessionKeeper.expire()`），发送在这里；两者通过 `SessionBootstrap` 的 `onExpired` 回调连起来。

```kotlin
package com.hgtv.star.data

import android.content.Context
import android.content.Intent

/**
 * 掉线通知。对齐原版 `com.dragon.read.user.h0` 的 `action_reading_user_session_expired`：
 * **只有确认失效（`data.error_name == "session_expired"`）才发**，界面收到才清 UI。
 *
 * 为什么放 app 模块：`sendBroadcast` 需要 `android.content.Context`，而 `android/core` 是纯 Kotlin
 * JVM 模块（编译期没有 Android SDK）。判定逻辑在 core（`SessionKeeper`），发送在这里。
 *
 * 为什么用广播而不是直接回调界面：网络层与界面层是通过 `Repository` / `Library` 解耦的，
 * 广播是两边都能接、且不需要互相持有引用的最省事方式；显式 `setPackage` 保证只有自己收得到
 * （Android 8+ 隐式广播受限，必须显式指定包名）。
 */
object SessionEvents {
    const val ACTION_SESSION_EXPIRED = "com.hgtv.star.action.SESSION_EXPIRED"
    const val EXTRA_REASON = "reason"

    fun sendExpired(context: Context, reason: String) {
        runCatching {
            context.sendBroadcast(
                Intent(ACTION_SESSION_EXPIRED)
                    .setPackage(context.packageName)
                    .putExtra(EXTRA_REASON, reason)
            )
        }
    }
}

### 5.2 登录成功时必须落盘的完整清单

对 `AccountCredentials` 来说，能落的就是下面这些；**少一项都可能让下一次心跳拿不到完整身份**：

| 数据 | 来源 | 落在哪 | 代码位置 |
|---|---|---|---|
| `X-Tt-Token` | 登录 / 扫码响应头 | SP `session-token` | `PhoneLogin.credentials()` / `QrLogin.credentials()` → `Library.saveAccount` |
| `bd-ticket-guard-sign-res-static-ts-sign` | 同上响应头 | SP `ts-sign` | 同上（`tsSign` 字段） |
| `sessionid` | `Set-Cookie` | `account-cookie` | `AccountCredentialsParser.headerOf` 已含 |
| `sessionid_ss` | `Set-Cookie` | 同上 | 同上 |
| `sid_guard` | `Set-Cookie`（**含过期时间**） | 同上 | 同上（`expiryOf` 从它算 `account-expires`） |
| `sid_tt` | `Set-Cookie` | 同上 | 同上 |
| `uid_tt` / `uid_tt_ss` | `Set-Cookie` | 同上 | 同上 |
| `d_ticket` | `Set-Cookie` | 同上 | 同上 |
| `odin_tt` | `Set-Cookie` | 同上 | 同上 |
| `install_id` | `Set-Cookie`（注册时） | `registered-cookies` | `registerDeviceOnce` → `saveDeviceCookies` |
| `ttreq` | `Set-Cookie`（注册时） | `registered-cookies` | 同上 |
| `store-region` | `Set-Cookie`（注册时） | `registered-cookies` + 头 | `ContentRepository.text` 已按它发 `X-Tt-Store-Region` |
| `multi_sids` / `passport_csrf_token*` | `Set-Cookie` | 同上（可选） | `AccountCredentialsParser.COOKIE_KEYS` 未含，按需加 |
| `device_id` / `iid` | `device_register` 返回 | `registered-device-id` / `registered-install-id` | `Library.saveDeviceIdentity` 已有 |
| `cdid` / `openudid` / 机型 / 系统 | 本机 | `account-device`（JSON） | `Library.saveAccountDevice` 已有 |
| `first_beat` | 本地状态 | SP `first-beat` | `AppSessionStore`（**按字符串存**，见 §4.10 ④ 的说明） |

> **`sid_guard` 是最容易被忽略的一项**：它是唯一告诉你「会话什么时候到期」的 cookie
> （`sessionid|签发时间|max-age|可读时间`）。丢了它，本地就再也算不出 `account-expires`，
> 界面上「剩余天数」永远显示未知，也无法在到期前主动提醒。

这七条都是**当前代码**里实际存在的，不修的话 §4 接进去仍然会掉线（甚至掉得更明显）。

    "sessionid","sessionid_ss","sid_tt","uid_tt","uid_tt_ss","d_ticket",

### 5.4 错误写法 vs 正确写法

**① 只存 token，cookie 只取 sessionid**

```kotlin

SessionBootstrap.onAppStart()                          // 立刻 beat(boot) + account/info(boot)
```

**② 用 HTTP 状态码判断掉线**

```kotlin
// ✗ 错误：401/403 就清号；网络异常也清号
if (code == 401 || code == 403) { library.clearAccount(); showLogin() }

// ✓ 正确：只认 body 里的 error_name，网络异常不动凭证
val err = JSONObject(body).optJSONObject("data")?.optString("error_name").orEmpty()
if (err.equals("session_expired", ignoreCase = true)) SessionBootstrap.onLogout()
```

**③ 把 cookie 放进 `x-tt-token`**

```kotlin
// ✗ 错误（ContentRepository.kt L617 的现状）

// ✓ 正确
copy(headers = headers + buildMap {
    put("Cookie", cookie)
    token.takeIf { it.isNotBlank() }?.let { put("x-tt-token", it) }
})
```

## 6. 存储 Schema（复用 native-session-v1）

**不要新建 SP。** 工程里已经有一份 `native-session-v1`（`Library.sessionPrefs`，`Library.kt` L61），
并且它被 `SessionMirror` 镜像到 `/sdcard/.hgtv/hgtv-session.json`——那份镜像正是「卸载重装后免登录」的全部依据。

### 6.1 键表

`SharedPreferences("native-session-v1")`：

| key | 类型 | 写入方 | 说明 |
|---|---|---|---|
| `session-token` | String | `AppSessionStore.saveToken` | 账号会话的 `X-Tt-Token`。服务端可随时轮换，本键必须跟着响应头更新 |
| `ts-sign` | String | `AppSessionStore.saveToken` | `bd-ticket-guard-sign-res-static-ts-sign`，可空 |
| `first-beat` | String(`"true"/"false"`) | `AppSessionStore` | 仅首次 `true`；**存字符串**，因为 `Library.restoreFromMirror` 按字符串回写 |
| `account-cookie` | String | `AppSessionStore` / `Library.saveAccount` | 扁平 Cookie 串，`name=value; name=value` |
| `account-expires` | Long | `AppSessionStore` / `Library.saveAccount` | `sid_guard` 推算的绝对秒；`restoreFromMirror` 对它有特判（`getLong`） |
| `account-device` | String(JSON) | `Library.saveAccountDevice` | 真机设备档案（机型 / 系统 / `cdid` / `klink_egdi` …） |
| `registered-cookies` | String(JSON) | `AppSessionStore.saveDeviceCookies` | 设备注册下发的 `install_id` / `ttreq` / `store-region` … |
| `x-tt-token` | String | `Library.searchToken` | **历史遗留、只给搜索用**的用户手填令牌；与账号会话分开，见 6.2 |
| `registered-device-id` | String | `Library.saveDeviceIdentity` | `device_register` 返回的 `device_id` |
| `registered-install-id` | String | `Library.saveDeviceIdentity` | 同上，`install_id` |

### 6.2 为什么 `session-token` 与 `x-tt-token` 分开

`x-tt-token` 是**用户在设置页手填的「搜索登录态」**（`Library.searchToken`，L341），
它不进备份、不随记录迁移，用户可能随时清掉或填成整段 Cookie。
如果账号会话直接复用它，会发生两件事：

1. 用户点「退出账号」时，`clearSession()` 会顺手把手填的搜索令牌一起抹掉；
2. 用户改搜索令牌时，会把正在用的账号会话覆盖成他手填的东西。

**如果你确认这两条都无所谓**，想合并成一个键，只改一行：

```kotlin
// AppSessionStore.kt 的 companion object
const val K_TOKEN = "x-tt-token"      // ← 与 Library.searchToken 共用
```

代价是退出登录要额外决定「要不要连搜索令牌一起清」——多数产品会选择继续清，那就别合并。

### 6.3 外部镜像

`SessionMirror` 写 `/sdcard/.hgtv/hgtv-session.json`（targetSdk 29 + `requestLegacyExternalStorage`）。
`MIRROR_KEYS` 必须包含上面所有会被 `restoreFromMirror` 用到的键，否则重装后恢复出来的是「半份会话」。

**安全边界**（工程已有注释，这里重申）：这个文件是明文凭据，Android 9 及以下任何有存储权限的
应用都能读；与真机红果同一层级的取舍。不要在此之上再扩大暴露面（例如不要改成可被广播读的 ContentProvider）。

## 8. 排错表

| 现象 | 根因 | 修法 |
|---|---|---|
| 登录后 10~40 分钟掉线 | 没打 beat | 上 §4.5 + §4.10 ② |
| beat 一直回 `session_expired` | cookie 没跨域共享 / 只存了某台 host 的 cookie | 统一 `account-cookie` 扁平串（§4.1） |
| 用了几天突然掉 | 只读登录响应的 token，没扫响应头轮换 | `SessionInterceptor`（§4.3） |
| 断网 / 切网就掉 | 把 IOException / 5xx 当掉线清号 | 只有 `data.error_name == session_expired` 才清（§4.5） |
| 每次启动都像「重新登录」 | `first-beat` 按 Boolean 存、镜像按字符串写回 → 永远读回 true | §4.7 已改成字符串 |
| 后台一段时间回前台掉线 | 后台定时被系统推迟，心跳空窗 | `onResume` 补 `onForeground()` |
| **搜索能出结果、播放取不到地址** | `x-tt-token` 里塞了整段 cookie | §5.3 第 1 条 + §5.1 ① |
| 播放仍回空、但账号接口正常 | 播放接口对 token 长度敏感 | `SessionInterceptor` 已对 `/novel/player/` 跳过 token，只补 Cookie |
| 导入 `cookieStore.xml` 后几小时掉 | 只有 cookie 没有 token，且无心跳 | §4.5 `signedIn()` 判据 + 第一次 beat 换回 token |
| 退出登录后重开又是登录态 | 只清本机 SP，外部镜像没清 | `clearSession()` 里 `mirror(K_COOKIE, null)`（§4.7） |
| 偶发 `bd-ticket-guard-key-sign-result: 2` | `/passport/*` 需要 TicketGuard 头 | 至少透传 `bd-ticket-guard-*`；完整实现见 `com.bytedance.android.sdk.bdticketguard` |
| 多账号切换互相顶掉 | 同一份 SP 存两个账号 | 按账号 id 分 `SessionState` 实例（不同 SP 文件名） |

## 9. 可选增强

### 9.1 frontier 通道

已有长连接（自建推送 / 厂商推送）时，收到「会话变更」消息调用：

```kotlin
SessionBootstrap.onFrontierMessage(rawJson)
```

没有也能保活，只是被踢下线最多晚 10 分钟才发现。

### 9.2 连接层保活

原版 TTNet 配置（`dc5/a.java`）：

```json
"h2_session_check_enabled": 1,
"h2_session_check_interval": 65,
"ping_keepalive_interval": 30,
"ping_keepalive_hosts": ["api5-normal-lq.fqnovel.com:443", "..."]
```

**本工程不要照抄**：`PlaybackTransport` 与 `ContentRepository` 都主动钉了 HTTP/1.1
（`PlaybackTransport.kt` 的类注释记着 h2 读线程在部分 TV 芯片上越界崩溃的现场）。
心跳走 HTTP/1.1 + 10 分钟一次已经足够，加 ping 只会增加后台唤醒。

### 9.3 后台兜底

TV 端通常常驻前台，`onResume` 补心跳已经够用。若确实要在「熄屏待机」时也保活：

```kotlin
// 15 分钟一次的兜底（WorkManager 最小间隔）
WorkManager.getInstance(ctx).enqueueUniquePeriodicWork(
    "session_beat",
    ExistingPeriodicWorkPolicy.KEEP,
    PeriodicWorkRequestBuilder<SessionBeatWorker>(15, TimeUnit.MINUTES).build()
)
```

`SessionBeatWorker.doWork()` 里调：

```kotlin
com.hgtv.star.data.SessionBootstrap.onForeground()   // 等价于补一次 polling + 重排
```

> 本工程没引入 WorkManager。要加就得改 `app/build.gradle.kts` 加依赖，
> 而 targetSdk 29 + 自签分发不受后台限制收紧的影响，因此**先不做**是合理的默认。

### 9.4 多进程

本工程目前是单进程（`AndroidManifest.xml` 里没有 `android:process`）。
如果以后加播放子进程，注意 `SessionBridge.state` 是**进程内**的，子进程读不到主进程的 token：
要么子进程不初始化会话（只做解码），要么给子进程一个只读的 `SessionState` 实现
（读同一个 SP + `MODE_MULTI_PROCESS`，并在读到空时回主进程问一次）。

判断标准：**子进程只做播放 / 解码、不发带 token 的 HTTP 就用「不初始化」，别引入跨进程复杂度。**

## 12. 附录 A：单文件版 SessionKit（app 模块）

不想拆这 9 个文件时用这一版：**整段丢进
`android/app/src/main/kotlin/com/hgtv/star/data/SessionKit.kt`**，只依赖 okhttp3 与 `org.json`。

与 §4 的差别只在「放哪儿」：这一版把状态实现与装配合成一个 `object`，因此**不需要改 `core`**，
代价是 `ContentRepository` 的默认 client 不能自动带上拦截器，必须显式传（见下面的接线三步）。

> 也可以直接把它当参考实现读：逻辑与 §4 一一对应，只是省掉了接口那层间接。

```kotlin
package com.hgtv.star.data

import android.content.Context
import android.content.Intent
import android.content.SharedPreferences
import com.hgtv.star.core.AccountCredentialsParser
import okhttp3.Call
import okhttp3.Callback
import okhttp3.Interceptor
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.Response
import org.json.JSONObject
import java.io.IOException
import java.util.concurrent.Executors
import java.util.concurrent.ScheduledExecutorService
import java.util.concurrent.ScheduledFuture
import java.util.concurrent.TimeUnit
import java.util.concurrent.atomic.AtomicBoolean

/**
 * 单文件版会话保活。**只放 app 模块**（`android/app/src/main/kotlin/com/hgtv/star/data/`），
 * `core` 一行不改——因为 `android/core` 是 `kotlin("jvm")` 纯 Kotlin 模块，编译期没有 `android.*`，
 * `SharedPreferences` 放不进去。
 *
 * 需要动的地方只有两处：
 *
 * 1. `MainActivity`：`ContentRepository()` → `ContentRepository(SessionKit.client)`；
 * 2. `PlaybackTransport.client`：`.addInterceptor(SessionKit.interceptor)`（预取与播放都走它）。
 *
 * 剩下三件（心跳、token 轮换、cookie 合并）全在本文件内自洽。
 */
object SessionKit {

    // ======================= 1. 持久化 =======================

    /** 读写工程里已有的 `native-session-v1`（`Library.sessionPrefs`），不新建 SP。 */
    class Store internal constructor(context: Context) {
        private val sp: SharedPreferences =
            context.applicationContext.getSharedPreferences(SP_NAME, Context.MODE_PRIVATE)

        /** 当前 `x-tt-token`。 */
        var token: String
            get() = sp.getString(K_TOKEN, "").orEmpty().trim()
            private set(value) {
                val clean = value.trim()
                if (clean.isEmpty() || clean == TOKEN_PLACEHOLDER) return
                sp.edit().putString(K_TOKEN, clean).apply()
            }

        var tsSign: String
            get() = sp.getString(K_TS_SIGN, "").orEmpty()
            private set(value) { sp.edit().putString(K_TS_SIGN, value.trim()).apply() }

        /** 存字符串：`Library.restoreFromMirror` 会把镜像里的键一律按字符串回写。 */
        var firstBeat: Boolean
            get() = sp.getString(K_FIRST_BEAT, "").orEmpty().ifBlank { "true" }.toBoolean()
            set(value) { sp.edit().putString(K_FIRST_BEAT, value.toString()).apply() }

        /** 扁平 Cookie 串（`name=value; name=value`）。 */
        var cookieHeader: String
            get() = sp.getString(K_COOKIE, "").orEmpty()
            private set(value) { sp.edit().putString(K_COOKIE, value.trim()).apply() }

        /** 设备注册下发的 cookie（`install_id` / `ttreq` / `store-region` …）。 */
        var deviceCookies: Map<String, String>
            get() {
                val raw = sp.getString(K_DEVICE_COOKIES, "").orEmpty()
                if (raw.isBlank()) return emptyMap()
                val json = runCatching { JSONObject(raw) }.getOrNull() ?: return emptyMap()
                return buildMap {
                    for (key in json.keys()) json.optString(key).trim().takeIf { it.isNotEmpty() }?.let { put(key, it) }
                }
            }
            private set(value) {
                val clean = value.filterValues { it.isNotBlank() }
                if (clean.isEmpty()) return
                sp.edit().putString(K_DEVICE_COOKIES, JSONObject().apply { clean.forEach { (k, v) -> put(k, v) } }.toString()).apply()
            }

        val storeRegion: String
            get() = CookieKit.value(cookieHeader, "store-region").ifBlank { deviceCookies["store-region"].orEmpty() }.ifBlank { "cn" }

        /** token 非空且不是占位符（原版 `isLogin()`）。 */
        val hasToken: Boolean get() = token.isNotEmpty() && token != TOKEN_PLACEHOLDER

        /**
         * 能不能打心跳：token 或会话 cookie **有其一**即可。
         *
         * 导入 `cookieStore.xml` 只有 cookie、没有 `X-Tt-Token`（那份文件不存 token），
         * 这种会话也必须心跳——第一次 beat 的响应头会把 token 发回来并落盘。
         * 若死要求 token，导入来的会话永远不被续期，正是「导入后几小时就掉」的成因。
         */
        val complete: Boolean get() = hasToken || cookieHeader.contains("sessionid=")

        /** token 变了才写盘；返回是否真的变了。 */
        fun saveToken(newToken: String, newTsSign: String = ""): Boolean {
            val clean = newToken.trim()
            if (clean.isEmpty() || clean == TOKEN_PLACEHOLDER) return false
            if (clean == token && newTsSign.trim() == tsSign) return false
            sp.edit().apply {
                putString(K_TOKEN, clean)
                if (newTsSign.isNotBlank()) putString(K_TS_SIGN, newTsSign.trim())
            }.apply()
            return true
        }

        /** 合并一批 `Set-Cookie`（登录 / 业务 / 心跳响应都走这里）。 */
        fun mergeSetCookie(setCookies: List<String>): Boolean {
            if (setCookies.isEmpty()) return false
            val before = cookieHeader
            val merged = CookieKit.merge(before, setCookies)
            if (merged == before) return false
            val expires = AccountCredentialsParser.expiryOf(CookieKit.headerToMap(merged))
            sp.edit().apply {
                putString(K_COOKIE, merged)
                if (expires > 0L) putLong(K_EXPIRES, expires)
            }.apply()
            return true
        }

        /** 登录成功 / 导入 `cookieStore.xml`：整段覆盖。 */
        fun replaceCookie(header: String): Boolean {
            val clean = header.trim()
            if (clean.isEmpty() || clean == cookieHeader) return false
            val expires = AccountCredentialsParser.expiryOf(CookieKit.headerToMap(clean))
            sp.edit().apply {
                putString(K_COOKIE, clean)
                if (expires > 0L) putLong(K_EXPIRES, expires)
            }.apply()
            return true
        }

        fun saveDeviceCookies(cookies: Map<String, String>) { deviceCookies = cookies }

        /** 只清会话，不动设备身份（`registered-*` 与 `account-device`）。 */
        fun clearSession() {
            sp.edit().remove(K_TOKEN).remove(K_TS_SIGN).remove(K_COOKIE).remove(K_EXPIRES).apply()
            // `first-beat` 保留：重登不代表「新设备首刷」
        }

        companion object {
            const val SP_NAME = "native-session-v1"
            /** 账号会话的 token。与 `x-tt-token`（用户手填的搜索令牌）分开，原因见 §6.2。 */
            const val K_TOKEN = "session-token"
            const val K_TS_SIGN = "ts-sign"
            const val K_FIRST_BEAT = "first-beat"
            const val K_COOKIE = "account-cookie"
            const val K_EXPIRES = "account-expires"
            const val K_DEVICE_COOKIES = "registered-cookies"
            /** 原版把 `change.token` 当「未登录」。 */
            const val TOKEN_PLACEHOLDER = "change.token"
        }
    }

    // ======================= 2. Cookie 解析 =======================

    internal object CookieKit {
        private val DATE_FORMATS = listOf(
            "EEE, dd MMM yyyy HH:mm:ss zzz",
            "EEEE, dd-MMM-yy HH:mm:ss zzz",
            "EEE MMM d HH:mm:ss yyyy",
        )

        /** 解析一条 `Set-Cookie`；返回 `name to value`，删除指令返回 `name to null`。 */
        fun parse(raw: String?): Pair<String, String?>? {
            val text = raw?.trim().orEmpty()
            if (text.isEmpty()) return null
            val parts = text.split(';')
            val first = parts[0].trim()
            val eq = first.indexOf('=')
            if (eq <= 0) return null
            val name = first.substring(0, eq).trim()
            if (name.isEmpty()) return null
            val value = first.substring(eq + 1).trim()
            var maxAgeSeen = false
            var delete = false
            for (index in 1 until parts.size) {
                val attr = parts[index].trim()
                val at = attr.indexOf('=')
                val key = (if (at >= 0) attr.substring(0, at) else attr).trim().lowercase()
                val v = if (at >= 0) attr.substring(at + 1).trim() else ""
                when (key) {
                    "max-age" -> {
                        maxAgeSeen = true
                        if ((v.toLongOrNull() ?: 1L) <= 0L) delete = true
                    }
                    // RFC 6265：Max-Age 优先
                    "expires" -> if (!maxAgeSeen) {
                        val at2 = date(v)
                        if (at2 != null && at2 <= System.currentTimeMillis()) delete = true
                    }
                }
            }
            return name to if (delete) null else value
        }

        fun date(raw: String): Long? {
            for (pattern in DATE_FORMATS) {
                val parsed = runCatching {
                    java.text.SimpleDateFormat(pattern, java.util.Locale.US).apply {
                        timeZone = java.util.TimeZone.getTimeZone("GMT")
                        isLenient = false
                    }.parse(raw)
                }.getOrNull()
                if (parsed != null) return parsed.time
            }
            return null
        }

        fun headerToMap(header: String): MutableMap<String, String> {
            val out = LinkedHashMap<String, String>()
            for (segment in header.split(';')) {
                val part = segment.trim()
                val at = part.indexOf('=')
                if (at > 0) out[part.substring(0, at).trim()] = part.substring(at + 1).trim()
            }
            return out
        }

        fun mapToHeader(map: Map<String, String>): String = map.entries.joinToString("; ") { (n, v) -> "$n=$v" }

        fun value(header: String, name: String): String = headerToMap(header)[name].orEmpty()

        /** 合并：同名覆盖，`Max-Age=0` / 已过期 → 移除（不写空值）。 */
        fun merge(header: String, setCookies: List<String>): String {
            if (setCookies.isEmpty()) return header
            val map = headerToMap(header)
            var changed = false
            for (raw in setCookies) {
                val (name, value) = parse(raw) ?: continue
                if (value == null) {
                    if (map.remove(name) != null) changed = true
                } else if (map[name] != value) {
                    map[name] = value
                    changed = true
                }
            }
            return if (changed) mapToHeader(map) else header
        }
    }

    // ======================= 3. 拦截器 =======================

    /** 对齐原版 `share_cookie_host_list`：这些域视为同一份 jar。 */
    private val SESSION_HOSTS = listOf(
        "snssdk.com", "zijieapi.com", "ulpay.com", "fqnovel.com",
        "ecombdapi.com", "luckysf.net", "iluckysf.net",
        "awemeughun.com", "awemeugsoul.com",
    )

    private fun isSessionHost(host: String): Boolean {
        val h = host.lowercase()
        return SESSION_HOSTS.any { h == it || h.endsWith(".$it") }
    }

    /** 补身份 + 扫 `X-Tt-Token` + 合并 `Set-Cookie`。 */
    val interceptor: Interceptor = Interceptor { chain ->
        val original = chain.request()
        val host = original.url().host()
        // 播放取地址接口只补 Cookie：该接口对 `x-tt-token` 长度极敏感（≥99 字符回空）
        val skipToken = original.url().encodedPath().startsWith("/novel/player/")
        val target = if (isSessionHost(host)) decorate(original, !skipToken) else original
        val response = chain.proceed(target)
        if (isSessionHost(host)) {
            val rotated = response.header("X-Tt-Token")
            if (!rotated.isNullOrBlank() && rotated != store?.token) store?.saveToken(rotated)
            val setCookies = response.headers("Set-Cookie")
            if (setCookies.isNotEmpty()) store?.mergeSetCookie(setCookies)
        }
        response
    }

    /**
     * ★ token 与 cookie 严格分开。
     *
     * `X-Tt-Token: <token>`；`Cookie: <device cookies>; <session cookies>`。
     * **绝不能**把 cookie 串也塞进 `x-tt-token`（本工程原有 `withSession()` 就是这么写的）：
     * 搜索接口容忍，播放与账号接口不容忍（`x-tt-token` 实测 ≥99 字符直接判死、回 `200 + 0 字节`）。
     */
    private fun decorate(original: Request, injectToken: Boolean = true): Request {
        val builder = original.newBuilder()
        val current = store
        val token = current?.token.orEmpty()
        if (injectToken && token.isNotEmpty()) builder.header("X-Tt-Token", token)
        val merged = LinkedHashMap<String, String>()
        current?.deviceCookies?.forEach { (name, value) -> if (name.isNotBlank() && value.isNotBlank()) merged[name] = value }
        current?.cookieHeader?.takeIf { it.isNotBlank() }?.let { merged.putAll(CookieKit.headerToMap(it)) }
        if (merged.isNotEmpty()) builder.header("Cookie", CookieKit.mapToHeader(merged))
        builder.header("X-SS-DP", "8662")
        builder.header("X-Tt-Store-Region", current?.storeRegion ?: "cn")
        builder.header("X-Tt-Store-Region-Src", "did")
        builder.header("Sdk-Version", "2")
        builder.header("passport-sdk-version", "5051452")
        builder.header("X-Xs-From-Web", "0")
        deviceHeaders().forEach { (name, value) -> if (value.isNotBlank()) builder.header(name, value) }
        return builder.build()
    }

    // ======================= 4. 心跳 =======================

    private val scheduler: ScheduledExecutorService =
        Executors.newSingleThreadScheduledExecutor { task -> Thread(task, "hgtv-session-beat").apply { isDaemon = true } }

    private var tick: ScheduledFuture<*>? = null
    private val beatInFlight = AtomicBoolean(false)
    private val infoInFlight = AtomicBoolean(false)
    private var started = false

    /** 心跳专用 client（与业务 client 隔离：业务侧 `cancelAll()` 不影响它）。 */
    val client: OkHttpClient by lazy {
        OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .callTimeout(20, TimeUnit.SECONDS)
            .addInterceptor(interceptor)
            .build()
    }

    /** 冷启动：`account/info(boot)` + `beat(boot)` + 10 分钟循环。幂等。 */
    fun onAppStart() {
        val current = store ?: return
        if (!current.complete) return
        if (started) { start(); return }
        started = true
        accountInfo("boot")
        beat("boot")
        start()
    }

    /** 回前台：补一次 `polling` + 重排（Doze 会把后台定时整体推迟）。 */
    fun onForeground() {
        val current = store ?: return
        if (!current.complete) return
        started = true
        beat("polling")
        start()
    }

    /** 退出登录（清会话，保留设备身份）。 */
    fun onLogout() {
        stop()
        started = false
        store?.clearSession()
    }

    @Synchronized
    private fun start() {
        val current = store ?: return
        if (!current.complete) return
        tick?.cancel(false)
        tick = scheduler.schedule({ beat("polling") }, INTERVAL_MS, TimeUnit.MILLISECONDS)
    }

    @Synchronized
    private fun stop() {
        tick?.cancel(false)
        tick = null
    }

    fun beat(scene: String) {
        val current = store ?: return
        if (!current.complete) { stop(); return }
        if (!beatInFlight.compareAndSet(false, true)) return
        val url = "$BEAT_BASE?scene=$scene&first_beat=${current.firstBeat}"
        client.newCall(request(url)).enqueue(object : Callback {
            override fun onFailure(call: Call, e: IOException) {
                beatInFlight.set(false)
                // ★ 网络失败不清凭证，按固定 10 分钟续期（原版 c.b()）
                log("beat($scene) net=${e.javaClass.simpleName}")
                finish()
            }

            override fun onResponse(call: Call, response: Response) {
                beatInFlight.set(false)
                val code = response.code()
                val body = runCatching { response.body()?.string().orEmpty() }.getOrDefault("")
                response.header("X-Tt-Token")?.takeIf { it.isNotBlank() }?.let { current.saveToken(it) }
                runCatching { response.close() }
                if (expired(body)) { log("beat($scene) session_expired"); expire(); return }
                if (code == 400) log("beat($scene) http 400 self-check")
                if (code == 404) log("beat($scene) http 404")
                if (current.firstBeat) current.firstBeat = false
                finish()
            }
        })
    }

    private fun finish() {
        val current = store ?: return
        if (!current.complete) { stop(); return }
        start()
    }

    private fun accountInfo(scene: String) {
        val current = store ?: return
        if (!current.complete) return
        if (!infoInFlight.compareAndSet(false, true)) return
        client.newCall(request("$INFO_BASE?scene=$scene")).enqueue(object : Callback {
            override fun onFailure(call: Call, e: IOException) { infoInFlight.set(false) }
            override fun onResponse(call: Call, response: Response) {
                infoInFlight.set(false)
                val body = runCatching { response.body()?.string().orEmpty() }.getOrDefault("")
                runCatching { response.close() }
                if (expired(body)) expire()
            }
        })
    }

    private fun request(url: String): Request {
        val builder = Request.Builder().url(url).get()
            .header("X-SS-DP", "8662")
            .header("X-Tt-Store-Region", store?.storeRegion ?: "cn")
            .header("X-Tt-Store-Region-Src", "did")
            .header("sdk-version", "2")
            .header("passport-sdk-version", "5051452")
            .header("Accept", "application/json")
        val token = store?.token.orEmpty()
        if (token.isNotEmpty()) builder.header("X-Tt-Token", token)
        return builder.build()
    }

    /** ★ 唯一判定入口：HTTP 200 + body 里的 `data.error_name`。 */
    private fun expired(body: String): Boolean {
        if (body.isBlank()) return false
        val data = runCatching { JSONObject(body).optJSONObject("data") }.getOrNull() ?: return false
        return data.optString("error_name").equals("session_expired", ignoreCase = true)
    }

    private fun expire() {
        stop()
        started = false
        store?.clearSession()
        context?.let { ctx ->
            runCatching {
                ctx.sendBroadcast(
                    Intent(ACTION_SESSION_EXPIRED).setPackage(ctx.packageName).putExtra(EXTRA_REASON, "beat")
                )
            }
        }
    }

    // ======================= 5. 装配 =======================

    @Volatile private var store: Store? = null
    @Volatile private var context: Context? = null

    /** 诊断日志出口（`Log.i("HGTV-SESSION", …)` + `Diagnostics.trace`）。 */
    @Volatile var log: (String) -> Unit = {}

    /**
     * 设备头（与业务请求同源）。默认空表；`init` 时传进来即可。
     * 传 `{ com.hgtv.star.core.session.SessionHeaders.build(device) }` 最省事。
     */
    @Volatile private var deviceHeaders: () -> Map<String, String> = { emptyMap() }

    val sessionStore: Store? get() = store

    /** `Application.onCreate` 调一次。 */
    fun init(
        appContext: Context,
        deviceHeaders: () -> Map<String, String> = { emptyMap() },
        log: (String) -> Unit = {},
    ) {
        context = appContext.applicationContext
        this.deviceHeaders = deviceHeaders
        this.log = log
        if (store == null) store = Store(appContext)
    }

    const val ACTION_SESSION_EXPIRED = "com.hgtv.star.action.SESSION_EXPIRED"
    const val EXTRA_REASON = "reason"
    const val INTERVAL_MS = 600_000L
    private const val BEAT_BASE = "https://security.snssdk.com/passport/token/beat/v2/"
    private const val INFO_BASE = "https://security.snssdk.com/passport/account/info/v2/"
}

private fun Signer.Request.withSession(): Signer.Request {

    }
