# 界面改版：新拟态（Neumorphism / Soft UI）

本轮把原生版从「近黑底色 + 描边卡片 + 强调色块」换成**新拟态**：全站只有一块石墨材质，
层次由「凸起 / 凹陷」和柔光（右下深投影 + 左上浅高光）表达。
改动只发生在 UI 层；内容协议、请求签名、播放与解密代码一行未动。

> 上一版（极光 TV 式排版）的说明保留在本文件末尾的「上一版设计」一节，两者的排版结构是继承关系，
> 本轮换掉的是**材质与形状语言**，不是信息架构。
>
> **色板于 2026-10-07 二次改版**：材质从灰蓝退成中性石墨，强调色从高饱和品牌蓝 `#5980FF`
> 换成香槟金 `#DFB77C`，选中态从「染色底」改成「抬面 + 金环 + 金字」。原因见
> [第 2.1 节](#21-色板改版2026-10-07石墨--香槟金)；结构、柔光实现、按钮规范一条未变。
>
> **主题于 2026-10-07 三次改版**：**选框不再有任何颜色**——焦点与选中都不再画强调色细环、
> 也不再用强调色写字（焦点靠「打亮」、选中靠「按进去」），并且材质本身变成可在
> **设置 → 主题外观** 里切换的十四套（经典浅灰 / 优雅奶白 / 深邃暗调 / 高级柔冷 +
> 瓷白 / 月岩灰 / 象牙沙 / 银鼠尾草 / 蓝雾 / 香槟丝绸 / 灰雾玫瑰 / 苍岩橄榄 / 石墨 / 午夜蓝）。
> 原因与派生规则见 [第 2.2 节](#22-主题改版2026-10-07十四套材质--去掉选框的颜色)；
> 结构、柔光实现、按钮规范、焦点余量规则一条未变。

## 1. 为什么新拟态在电视上要改三个地方

教科书式的新拟态是「底板与控件同色，只靠双向投影分层」。直接搬到电视上会踩三个坑：

| 坑 | 后果 | 本项目的处理 |
| --- | --- | --- |
| 同色 = 没有对比 | 3 米外看不清哪里是按钮、哪里是背景 | 材质分三档明度（底色 / 凸起面 / 凹陷面），差值约 3%，投影仍然承担主要层次 |
| 投影必须画到控件边界之外 | 与滚动容器的裁剪规则打架：要么描边被切掉，要么卡片盖住页头 | 每个控件四周留 **柔光带**（自己的 padding），投影与高光全部画在控件边界内 |
| 实时模糊太贵 | `setShadowLayer` 在硬件加速画布上对形状无效；`RenderEffect` 要 API 31 | 柔光**预渲染成半分辨率位图**，按尺寸共享 LRU 缓存，每帧只画一张图 |

## 2. 设计令牌（`TvStyle.kt`）

下表是**深邃暗调**（默认主题）的实际取值。除几何与「播放界面」那一组之外，
所有颜色令牌都不是写死的常量，而是从当前主题的三个色值派生出来的（见
[第 2.2 节](#22-主题改版2026-10-07十四套材质--去掉选框的颜色)）：
换主题只换色值，几何、圆角、柔光带、按钮档位一件都不动。

| 类别 | 取值 | 用途 |
| --- | --- | --- |
| 底色 `background` | `#2E3238` | 页面底板，也是柔光的基准色（= 主题的「背景与元素底色」） |
| 凸起面 `surface` | 底色 → 亮部阴影色 45% | 按钮、卡片、设置项的常态 |
| 抬升面 `surfaceHigh` | 底色 → 亮部阴影色 72% | 焦点容器、设置分组、**抬一档的选中态** |
| 凹陷面 `well` | 底色 → 暗部阴影色 45% | 搜索框、海报井、**按进去的选中态** |
| 深凹槽 `wellDeep` | 底色 → 暗部阴影色 72% | 进度条轨道、禁用态 |
| 深投影 `shadowDark` | 暗部阴影色，深色主题 62% / 浅色 72% | 右下，偏移约 `0.36 × 柔光带` |
| 浅高光 `shadowLight` | 亮部阴影色，同一档强度 | 左上，偏移约 `0.32 × 柔光带` |
| 内阴影 | `innerDark` 暗部色 / `innerLight` 亮部色 | 凹陷槽的左上深、右下亮（浅色主题的配方更重，见 2.2） |
| 焦点面 `lit` | `#F0EAE0`（暖白） | 焦点态与主操作：整个材质里最亮的一档 |
| 亮面板上的字 `onLit` | `#1A1612`（暖近黑） | 焦点 / 主操作按钮的字色 |
| 亮面板柔光 `litGlow` | 焦点面的 20%（深色）/ 35%（浅色） | 亮面板外的一圈光晕，**焦点唯一的「线」** |
| 强调 `accent` | `#DFB77C` | **只做线与小色块**：进度条、名次星标。**不画任何选框** |
| 按进去的选中面 `selectedWell` | = `well` | 开关、选项、设置项、主题行的选中态（`INSET`） |
| 抬一档的选中面 `selectedFace` | = `surfaceHigh` | 网格当前集、当前页图标（它们周围已经是凹的，再凹分不清） |
| 提示色 `tips` | `#FFC24B` | 只做小色块：评分星标、榜单前三 |
| 文字 | 文字基色的 100% / 84% / 70% / 62% | 标题 / 区块标题 / 正文 / 辅助（浅色主题是深墨，深色主题是暖白） |
| 播放界面 | `playerText` / `playerDim` / `playerLine` | 压在视频上的字与线，**永远暖白，不跟主题** |
| 圆角 | 卡片 12–14dp、胶囊 26dp、弹窗 24dp | 全站只此三档，整体比上一版放大一倍 |
| 柔光带 | 控件 6dp、大面板 10dp | `SOFT_BAND` / `SOFT_BAND_LARGE` |
| 焦点 | 放大 1.05、最亮的 `lit` 面板 + `litGlow` 光晕 + `onLit` 字 | **没有细环**；不做位移 |
| 选中 | 按进去（`well` + `INSET`）或抬一档（`selectedFace` + 更深的柔光） | **没有细环、没有强调色文字** |

### 2.1 色板改版（2026-10-07）：石墨 + 香槟金

上线后收到的问题很具体：**「边框颜色是蓝色，太丑了，和整体风格完全不搭；选中的选项也是蓝色」**。
指向的是两处：海报卡焦点那圈 3dp 的品牌蓝描边，和播放设置面板里「720P / 1.25×」这类选中胶囊。

#### 诊断：问题不在蓝，在「唯一一块高饱和色」

旧色板是「灰蓝材质 `#1F232B`（HSV 饱和 28%）+ 品牌蓝 `#5980FF`（饱和 100%）」。
页面里所有东西的明度差只有 3%、饱和度都在 30% 以下，唯独那圈蓝是满饱和——
它成了整屏唯一的「彩色事件」，于是看起来不像这套材质长出来的，像从别的应用截图贴上去的。

所以真正要修的不是「蓝不好看」，而是**一个低饱和的世界里不该出现一块满饱和的色**。
按这个诊断，改版动了两条轴，其余规则（焦点靠打亮、强调只做线、柔光带、圆角档位）一条没动：

| 维度 | 旧 | 新 | 为什么 |
| --- | --- | --- | --- |
| 材质 | 灰蓝 `#1F232B`（饱和 28%） | 石墨 `#1F2024`（饱和 13%） | 材质先退成中性，才装得下任何一支强调色；偏蓝的底会把非蓝强调色全衬成外来户 |
| 强调 | 品牌蓝 `#5980FF`（饱和 100%） | 香槟金 `#DFB77C`（饱和 44%） | 暖金属贴在中性石墨上是「钢与黄铜」，冷暖对比自带层次；饱和度砍掉一半，不再抢焦点 |
| 亮面 | 冷白 `#E7ECF5` | 暖白 `#F0EAE0` | 亮面和强调色是同一个光源，冷白配金环会互相打架 |
| 选中 | 18% 蓝染色底 + 蓝环 + 白字 | 抬升面 + 金环 + **金字** | 染色在蓝上勉强成立，混到暖金就变成褐色泥 |

#### 怎么选的：六支候选并排比

`tools/neumorphism-preview.py` 会额外输出 `docs/preview/.local/palette.png`：同一块石墨材质上并排画六支强调色
（海报卡细环 / 选中胶囊 / 亮面焦点按钮 / 当前页图标 / 选集当前集 / 进度条 / 名次星标 / 强调色文字），
第一列就是上一版的品牌蓝，用来对照「为什么换」。

- **品牌蓝**：满饱和，就是问题本身，淘汰；
- **香槟金 `#DFB77C`**：低饱和暖金属，冷暖对比清楚，选中态和进度条都成立，**采用**；
- **暖铜 / 玫瑰铜 `#DE9E77`**：偏粉，少了金属的「贵」，更像生活类应用；
- **琥珀 `#E8A33D`**：太饱和，和提示黄 `#FFC24B` 撞车，两套暖色会在同一屏里互相打散；
- **雾青 `#86C4B4`**：和石墨是一家人，但整体偏「医用 / 科技」，缺少「影视」的温度；
- **雾银 `#C9D3E2`**：近乎无彩，选中态和常态分不开，等于放弃了强调色。

#### 对比度（WCAG）

| 组合 | 对比度 | 用在哪 |
| --- | --- | --- |
| 香槟金 `#DFB77C` / 底色 `#1F2024` | 7.6:1 | 细环、进度条、名次星标、强调色文字 |
| 香槟金 / 抬升面 `#2F323A` | 6.7:1 | 选中态的文字与细环 |
| 暖白亮面 `#F0EAE0` / 底色 | 13.4:1 | 焦点态、主操作 |
| 暖近黑 `#1A1612` / 暖白亮面 | 14.6:1 | 焦点态、主操作的字 |
| 深铜 `#A8793C` / 暖白亮面 | 3.2:1 | 亮面上的那圈细环（非文字，门槛 3:1） |

#### 下次再改色板

> 这一节写于第二次改版，当时色值还写死在 `TvStyle.kt` 里、细环色还分两档。
> 第三次改版之后**色值住在 `TvTheme.kt`**（每个主题三个色值 + 文字基色 + 强调色 + 提示色），
> 细环已经不存在，流程改成下面这样。

1. 改 `TvTheme.kt` 里对应主题的色值与 `tools/theme-preview.py` 顶部的同一张表，
   两处必须一一对应（`tools/verify-button-system.py` 第 15 条会核对每个色值）；
2. 跑 `python3 tools/theme-preview.py`，看 `docs/preview/theme.png`：先确认三档材质分得开，
   再确认「常态 / 按进去 / 打亮」三个台阶在浅色底与深色底上都读得出来；
3. 强调色只做线与小色块，过一遍非文字 3:1 即可；文字基色对底色要过 WCAG AA（4.5:1）；
4. `tools/neumorphism-preview.py` 顶部的色板是**深邃暗调**那一套的镜像，改了深色主题要同步；
5. `app/src/main/res/values/styles.xml` 的 `windowBackground` / `colorAccent` 跟着改
   （启动第一帧的兜底配色）；**桌面图标与电视桌面卡片不在运行时主题里**，由
   `tools/app-icon.py` 生成——改色改脚本顶部的材质表，再跑 `python3 tools/app-icon.py
   --emit-vector` 重出矢量与位图，没有设备时的校对图是 `docs/preview/.local/icon.png`。

### 为什么焦点不是「强调色实心块」

第一版把焦点做成了 `#5980FF` 实心 + 近黑字。离线预览三套并排一比就看出来了：一块高饱和的蓝
贴在灰蓝材质上，像是从另一个应用截图贴过来的——**焦点色和选中色都比页面本身更"吵"**。

新拟态里「被打亮」才是焦点的母语：同一块材质被推到最亮的一档（[lit]），
再补一层光晕。于是：

- 焦点面 `#F0EAE0` 对页面底色 `#1F2024` 是 **13.4:1**，比任何强调色都亮；
- 暖近黑字在它上面是 **14.6:1**，3 米外读起来毫无压力；
- 强调色退到「线」上（进度条、名次星标），面积不到一屏的千分之一。

当时还给焦点补了一圈强调色细环（石墨上香槟金、亮面上深铜）。**那一圈环在第三次改版里被删掉了**
（见 [2.2](#22-主题改版2026-10-07十四套材质--去掉选框的颜色)）：焦点现在只靠「打亮 + 光晕」，
不再有任何颜色。

**选中态**：不再染色。品牌蓝时代 18% 蓝混进凸起面还能得到一块「石板蓝」，
换成暖金之后同样的配方混出来是一块褐色泥，比底色还闷。现在选中 = **抬一档明度**
（`selectedFace` = `surfaceHigh`）。第三次改版又把「按进去」加成了另一种选中表达，
并且把细环与强调色文字一起去掉，见 [2.2](#22-主题改版2026-10-07十四套材质--去掉选框的颜色)。

**主操作**（详情页「开始观看」）用同一个亮面板，但不带光晕——一屏一个亮块，
不用点也知道它是主操作；焦点移上去时它才多出一圈光晕。

### 2.2 主题改版（2026-10-07）：十四套材质 + 去掉选框的颜色

第二次改版之后仍然有一处没解决：**焦点框与选中项还是一圈带颜色的线**。
哪怕换成低饱和的香槟金，它依旧是整屏唯一一块「有颜色的事件」，看起来不像这套材质长出来的。
本轮把两件事一起做掉，规则收敛成一句话：

> **状态只用「凹 / 凸 / 亮」三个台阶表达，选框不带颜色；材质本身可选。**

| 状态 | 画法 | 用在哪 |
| --- | --- | --- |
| 常态 | 凸起面 `surface`（`RAISED`） | 按钮、卡片、设置项 |
| 选中（按进去） | 凹陷面 `selectedWell` + `SoftStyle.INSET`（左上更深、右下更亮） | 开关、播放选项、设置项、**主题行** |
| 选中（抬一档） | 抬升面 `selectedFace` + 更深的柔光（`depth` 1.3） | 顶部当前页图标 |
| 当前项（常亮） | 常亮的 `lit` 面板 + `onLit` 字 | 选集网格里的当前集（= 主操作那一档：一屏里那块「本来就是它」的亮色） |
| 焦点 | 最亮的 `lit` 面板 + `litGlow` 光晕（`depth` 1.2–1.35） | 全站唯一的焦点表达 |
| 主操作 | 常亮的 `lit` 面板（不带光晕） | 详情页「开始观看」这类一屏一个的按钮 |
| 禁用 | 压平的凹槽 `well` + 40% 透明度 | 不可用按钮 |

为什么选中要分两种：**周围是什么，决定「选中」往哪个方向走**。
一排凸起的按钮里，凹下去的那一个最好认；而选集网格里格子挨着格子，
再凹一层的明度差在 20 个格子里读不出来，所以那里改用「抬一档 + 更深的柔光」。两条路径都不带颜色。

选集里的**当前集**比「选中」更特殊：20 个格子里
3% 的明度差读不出来——「你在看第几集」却是这张网格唯一必须一眼看到的信号。
因此它借用主操作那一档（常亮的亮面板 + 亮面上的字），和旧版的「金环 + 金字」一样醒目，
但不带颜色；焦点落在它上面时只是多一圈光晕、放大 1.05。

```
凸起面 surface      = 底色 → 亮部阴影色 45%
抬升面 surfaceHigh  = 底色 → 亮部阴影色 72%
凹陷面 well         = 底色 → 暗部阴影色 45%
深凹槽 wellDeep     = 底色 → 暗部阴影色 72%
投影 / 高光         = 表里两档阴影色，深色主题 62% 强度、浅色主题 72%
内阴影              = 暗部色（左上）/ 亮部色（右下）；浅色主题的配方更重（72% / 50%）
文字四级            = 文字基色的 100 / 84 / 70 / 62%
焦点面 lit          = 浅色主题纯白、深色主题暖白 #F0EAE0
```

文字四级从旧的 100 / 80 / 65 / 40 调高了一档，原因是**底色换了**：40% 那一档压在
新底色上只剩 2.1:1（旧底色 `#1F2024` 更暗，同样一档还有 3.6:1）。现在最低一档
在两个方向上都过 3:1——十二套浅色 3.10–3.46、两套深色 5.19–5.33；正文 7.8–9.6（浅）/ 10.6–11.1（深）
（由 `tools/theme-preview.py` 的自检逐套打印，低于门槛直接报错退出）。

为什么不照抄教科书式新拟态的「元素与底色完全同色」：电视 3 米外看，
3% 的明度差是分不出「哪里是按钮」的（这是第一次改版就踩过的坑）。
因此凸起面 / 凹陷面各挪一档，**但只挪一档**——层次主要还是柔光在说，
这一点与教科书一致。

文字基色是「浅色主题用深墨、深色主题用暖白」，所以 `TvStyle.text` / `muted` 这类令牌
在两个方向上都能直接用。**唯一不跟主题的是播放界面**：它压在视频上，永远用
`playerText` 的暖白（浅色主题下如果跟着变成深色字，标题条与控制层会完全看不见）。

#### 主题怎么存、怎么切

- **存**：`native-theme-v1` 一个只有一项的独立 SharedPreferences（`TvThemeStore`），
  按 `storedValue`（`soft-gray` / `creamy-milk` / `deep-dark` / `cool-mint` /
  `porcelain` / `moonstone` / `ivory-sand` / `silver-sage` / `blue-haze` / `champagne-silk` /
  `dusty-mauve` / `pale-olive` / `graphite` / `midnight-blue`）落盘。
  它**不进** `com.hgtv.star.core` 的 `Library`：那里装的是内容与观看记录，
  还要参与手机备份的合并与冲突处理，让一套配色跟着备份在设备之间搬家没有意义。
- **读**：`MainActivity.onCreate` 里在建任何视图之前同步读一次（一个很小的文件），
  顺手把窗口底色也换成该主题的底色，启动那一帧不会闪出另一套材质。
- **切**：设置页底部是**整宽的「主题外观」分组**，里面 `chunked(4)` 排成一行 4 个的主题芯片
  （14 套 = 4 行，最后一行用空位占住列宽，芯片不会被拉成半屏宽）。芯片就是全站统一的
  紧凑档按钮，标签是「中文 英文」，选中态是**按进去**的凹槽——凹下去的那一枚就是当前主题，
  下面还有一行「当前：瓷白 Porcelain · 极简、奢华」。点一下 → 落盘 → `TvStyle.applyTheme()` →
  `Soft.trim()`（柔光位图里烤着上一套材质的投影色）→ `showCatalog()` 重建当前页面 →
  焦点回到刚点的芯片。柔光缓存的 key 里也带上了主题，双保险。
  **为什么不是一行一个主题**：14 × 60dp 会把设置页顶出屏幕，芯片网格只占 4 行。
- **反悔**：十四套材质都只改色值，几何、圆角、柔光带、按钮档位、焦点余量一件不动，
  所以换主题不可能改变布局——这也是 `tools/verify-button-system.py` 会核对的一条。

#### 顺手修掉的两处「系统控件的颜色」

「选框不带颜色」这条规则同样适用于弹窗里的开关：备份恢复的「同时恢复播放设置和内容分类」
与版本更新里的「自动检查并下载更新」原来都是系统 `CheckBox`，勾选色是系统自带的一套
（还会在浅色主题里跳出一个灰框）。现在两处都换成全站统一的开关按钮（选中 = 按进去），
`CheckBox` 在整个工程里已经清零，静态校验会拦住回退。

#### 怎么复核

`python3 tools/theme-preview.py` 会输出 `docs/preview/theme.png`：十四套材质排成 7 列 × 2 行，
每列画出三档材质色块、三个状态台阶（常态 / 按进去 / 打亮）、海报卡的常态与焦点、
强调色只做线的三个例子、以及四级文字。它用的是与 `TvTheme.kt` 相同的派生公式，
`tools/verify-button-system.py` 会核对两边的色值表——改色时先重跑这张图，
比在真机上逐个改值快得多。`tools/neumorphism-preview.py`（整页排版预览）仍然是
深邃暗调那一套的令牌镜像。

## 3. 柔光怎么画（`TvSoft.kt`）

`SoftDrawable` 有四种形态，任何控件的外观都必须从这四种里挑一种：

| 形态 | 画法 | 用在哪 |
| --- | --- | --- |
| `SoftStyle.RAISED` | 预渲染柔光位图（右下深投影 + 左上高光 + 可选外发光）+ 面板填充 | 按钮、卡片、图标入口、弹窗、播放器底座 |
| `SoftStyle.INSET` | 面板填充 + 裁剪到面板内画两条方向相反的内阴影渐变 | 搜索框 |
| `SoftStyle.RING` | 只有一圈描边，无投影无底 | 目前没有调用方：留给「底板不能改色、只能补一圈」的场合。**它不允许再画强调色**——2026-10-07 之后全站的焦点都不带颜色，真要补圈只能补 45% 文字基色的中性细线（`TvStyle.focusLine`） |
| `SoftStyle.SHADE` | 面板 + 径向暗角 | 压在封面上的「海报井」 |

几何约定：**底板 = 控件 bounds 四边各内缩 `band`**。因此控件的 `padding` 必须 ≥ `band`，
否则内容会压到柔光带里。全站控件的高度令牌（`BUTTON_NORMAL` 等）指的是**底板高度**，
控件实际高度 = 令牌 + `2 × SOFT_BAND`。

性能：位图按「尺寸 + 圆角 + 形态 + 深度 + **主题**」做 LRU（24 条），一屏里同尺寸的卡片共用一张；
半分辨率渲染再放大，投影本来就是模糊的，看不出差别。
低内存设备在 `onCreate` 里把 `Soft.quality` 调小（见 `MainActivity.onCreate`）。
位图里烤着当时的投影 / 高光色，所以 key 里必须带主题（`TvStyle.themeId`），
`TvStyle.applyTheme()` 还会整体 `Soft.trim()` 一次。

## 4. 组件清单（`TvComponents.kt`）

- `TvButton`：**全站唯一的按钮实现**。尺寸走 `ButtonSize`（40 / 48 / 56dp 底板）、
  外观走 `ButtonTone`（主操作 / 常规 / 文字）。状态：
  常态 = 凸起面板 + 正文色；选中 = **按进去**（凹陷槽 + 内阴影）+ 正文色；
  **焦点 = 亮面板 + 光晕 + 近黑字**；主操作 = 常亮的亮面板（不带光晕）；
  禁用 = 压平的凹槽 + 40% 透明度。焦点与选中都不带颜色。
- `IconButton`：顶部导航的圆形入口，常态凸起圆盘 + 正文色图标、
  当前页**抬一档**（更深的柔光，图标仍与常态同色）、焦点亮圆盘 + 光晕 + 近黑图标。
  控件最小边长 = `BUTTON_NORMAL + 2 × SOFT_BAND`，调用方给 `lp(-2, -2)` 即可。
- `ToggleChip`：短剧 / 漫剧互斥开关，就是 `TvButton` 的选中态。
- `PosterCard`：一块凸起底板，里面嵌海报井（`SHADE` 暗角）、角标、进度条与两行文字。
  卡片的焦点态和按钮不同——卡里是图片，底板换不成亮面，因此焦点 = 抬一档 + 更深的柔光
  + 光晕 + 剧名转全白。
- `SectionHeading`：粗体标题，从内容线开始；2026-10-12 起不再有强调色圆点与「更多 ›」。
  2026-10-12 起不再有右侧「更多 ›」：剧架行末的「查看全部」底板就是入口。
- `EpisodeCell`：选集方格，常态凸起、**当前集是常亮的亮面板**
  （3% 的明度差在 20 个格子里读不出来，所以借主操作那一档）、焦点是亮面板 + 光晕。
- `SeekIndicator`：进度条，**保持原样**（4dp 轨道 18% 白 + 白色已播 + 10dp 白色圆滑块）。
  它只出现在播放界面，跟着那条「播放界面不套新拟态」的规则走，
  颜色取 `playerLine` / `playerText`，不跟主题。
- `TvDialog`（`TvDialog.kt`）：**全站唯一的模态框**，一块 24dp 圆角的大号凸起面板，
  柔光带 9dp、投影更深一档，背景压暗 66%。列表项的「当前选择」也是按进去的凹槽。
- `EpisodeGrid`（`EpisodeGrid.kt`）：简介页与播放界面共用的选集网格。
  只有播放界面有背板（浮层渐变，压在画面上）；简介页**不套背板**，网格直接落在页面上，
  左右与页面内容线对齐。两处的文字色不同：播放界面固定 `playerText` 暖白，简介页跟主题。
- `PlaybackMenu`（`PlaybackMenu.kt`）：播放器设置面板，底座是原来的三段黑渐变（播放界面不套新拟态），
  里面的选项按钮仍然是全站统一的胶囊按钮（选中 = 按进去）。

## 4.1 离线预览

没有设备时用 `tools/neumorphism-preview.py` 校对观感：它用 PIL + numpy 复刻
[SoftDrawable] 的绘制顺序（柔光 = 形状的模糊剪影 + 偏移、凹陷 = 两条 45° 渐变裁剪到面板内、
暗角 = 径向渐变），令牌数值与 `TvStyle.kt` 一一对应，输出 `docs/preview/.local/home.png`、`docs/preview/.local/sheet.png` 与 `docs/preview/.local/palette.png`（六支强调色候选并排，第一列是上一版的品牌蓝）。

```sh
python3 tools/neumorphism-preview.py          # 整页排版（深邃暗调那一套令牌），需要 Pillow + numpy
python3 tools/theme-preview.py                # 十四套主题 × 状态台阶，输出 docs/preview/theme.png
```

这几个数值都是它比出来的（前两条是第一次改版、第三条是第二次改版，第四次改版把「细环 / 金字」
换成了「按进去」，见 [2.2](#22-主题改版2026-10-07十四套材质--去掉选框的颜色)）：

- `shadowDark` 从 35% 提到 **42%**。35% 时凸起面与底色（明度只差 3%）在整屏缩略图里糊成一片，
  55% 以上投影又会变成一道硬边；
- 焦点从「实心强调色」换成 **亮面板 + 强调色细环**（三套配色并排比过，见
  「为什么焦点不是强调色实心块」）；
- 选中态从「18% 染色底」换成 **抬一档明度 + 金环 + 金字**：同一套配方在蓝上成立、在暖金上变成褐色泥
  （见 [第 2.1 节](#21-色板改版2026-10-07石墨--香槟金)）；
- 强调色从品牌蓝换成香槟金：`docs/preview/.local/palette.png` 六列并排比出来的，比在真机上逐个改值快得多。

`tools/theme-preview.py` 是主题改版新增的那张：十四套材质排成 7 列 × 2 行，每格画出三档材质、
三个状态台阶（常态 / 按进去 / 打亮）、海报卡的常态与焦点、强调色只做线的三个例子、四级文字。
它的色值表与 `TvTheme.kt` 一一对应，`tools/verify-button-system.py` 第 15 条会核对，
派生公式（45% / 72% / 62% / 72% / 文字四级）也与 `TvTheme` 的 `mix` / `alpha` 相同。
它同时是**十四套主题的回归门槛**：脚本按 WCAG 公式算正文、四级文字、亮面上的字、
焦点面 / 凹陷面 / 抬升面与底色的对比度，任何一项低于门槛就直接报错退出，
并把每一套的实测值打在终端上（加主题或改色板之后先看这张表，再去看图）。

预览**不是** Android 渲染器的替代品：字体、字距、真实海报、遥控器焦点移动、
低端 GPU 上的帧率都不在这里验证。

## 5. 必须保持的不变量

改版只动外观，以下结构一件都不能改，`tools/verify-button-system.py` 会静态核对：

1. **按钮只有一套实现**。除 `TvComponents.kt` 外不允许出现第二个继承 `TextView` 的控件，
   也不允许别处调用 `paintButton(`。
2. **模态框只有一套实现**。系统 `AlertDialog` 只允许出现在 `TvDialog.kt`。
3. **滚动容器的裁剪规则不变**：容器自己 `clipChildren = false` + 外壳 `tvScrollHost` `clipChildren = true`；
   每个纵向滚动容器必须 `focusBleed()`（或注明 `focus-bleed-exempt`）并挂在 `tvScrollHost(` 上。
   柔光带是控件自己的事，与这条规则互不替代。
4. **焦点余量不变**：`FOCUS_BLEED = 7` / `FOCUS_BLEED_VERTICAL = 12`，`FOCUS_SCALE = 1.05`。
5. **按钮高度只引用令牌**：`minimumHeight` 只能写成 `dp(size.height + 2 * TvStyle.SOFT_BAND)`
   或 `dp(TvStyle.BUTTON_XXX + 2 * TvStyle.SOFT_BAND)`。
6. **内边距不再各写各的**：横向内边距只能来自 `size.pad`（`paintButton` 内部），
   调用方不再自己拼 `setPadding(dp(32), ...)` 这类字面量。
7. **长期持有的控件重新挂载必须走 `rehost()`**。判定不看具体控件名，看形状：缩进 4 空格声明的属性（跨函数存活）出现在带 `removeAllViews()` 的重建函数里、被裸 `addView` 挂载、且该函数没有重新给它赋值 —— 这就是「第二次重建抛 `IllegalStateException`」的形状，`tools/verify-button-system.py` 第 10 条按此核对。
8. **焦点图（`nextFocusXxxId`）与按键处理一行不改**：换皮不动交互。
9. **选框不带颜色**：`ring=` 上不允许出现 `TvStyle.accent`，`accentGlow` 已经删除，
   选中态只能是「按进去」（`TvStyle.well` + `INSET`）或「抬一档」（`TvStyle.selectedFace`），
   焦点态只能是「打亮的 `lit` + `litGlow`」。强调色只允许出现在进度条、名次星标。
10. **主题只改色值**：`TvStyle` 的颜色令牌全部来自 `TvTheme`，几何 / 圆角 / 柔光带 /
    按钮档位 / 焦点余量一个都不能跟主题变。换主题必须 `Soft.trim()`，柔光缓存的 key 必须带主题。
11. **主题不进内容库**：只存在 `native-theme-v1`（`TvThemeStore`），
    不参与 `Library` 的备份合并；`TvTheme` 的四个 `storedValue` 是落盘契约，不能随手改。
12. **播放界面的字与线不跟主题**：压在视频上的文字一律取 `playerText` / `playerDim`，
    进度条轨道取 `playerLine`，否则浅色主题下会变成深色字、完全看不见。
13. **工程里不允许再有系统 `CheckBox`**：开关一律用全站统一的按钮（选中 = 按进去），
    系统控件的勾选色是自带的一套，与「选框不带颜色」冲突。

## 7. 验证边界

静态检查（`tools/verify-button-system.py`、`gradlew :core:test :app:lintDebug :app:assembleDebug`）
只能证明「只有一套实现、能编译、lint 无错、选框里没有颜色」。
`tools/theme-preview.py` 能证明十四套材质的**派生结果**与状态台阶在离线渲染下成立，
但**新拟态的观感、投影在低端 GPU 上的帧率、遥控器焦点在 4K 画布上的对比度必须在实体电视上验收**，
本轮没有实体设备（本机只有 JDK 17 + Android SDK，模拟器系统镜像是空壳、下载失败），
因此这些仍是待验收项：

- 十四套主题在电视上的实际观感，特别是**十二套浅色主题**在 3 米外的
  焦点辨识度。这一条是**已知的固有限制**，不是没测出来：浅色主题的底色到纯白只有
  `1.12:1`（优雅奶白）～`1.28:1`（高级柔冷），两套深色主题同一项是 `10.3–10.9:1`。
  浅色底上「打亮」的余地只有到白为止，因此焦点实际上由三个弱信号叠加承担：
  面变白 + 一圈光晕 + 放大 1.05。`tools/theme-preview.py` 把这一项的门槛定在 1.10，
  正是承认这个上限；**如果真机验收不合格，唯一不引入颜色的加强手段是给焦点面补一圈
  45% 文字基色的中性细线（`TvStyle.focusLine`）**，那仍然不是「带颜色的选框」，
  但会回到「描边」的观感，因此留作最后手段而不是默认；
- 换主题后整页重建的那一瞬间（`showCatalog()`）在低端机上的耗时与闪动；
- 播放界面在浅色主题下的可读性（本轮把它的字与线固定成暖白，但只有真机能确认
  标题条与控制层的对比度够用）；
- 主题外观分组的 4 行芯片（一行 4 个）+ 上面两列设置项在 720p 画布上的换行与焦点串联
  （源码里按行号对齐，越界时停在原地）；14 套材质排下来设置页会比一屏高一点，需要滚动。
