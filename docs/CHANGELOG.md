## 1.0.7：下一集无感切换

### 修复

- **自动连播切下一集不再黑屏转圈**：切集原先要把播放器停掉、清空播放列表再挂上新的一集，
  画面因此掉到黑屏、编解码器还要重建一次；新地址没到手时更是要在空白画面上等一整个请求往返。
  现在下一集**已经预热好**时走无感路径（见下一条）：不清播放器、不重建画面，直接把新源顶上去，
  画面停在上一集最后一帧上等下一集的第一帧；过渡期不显示缓冲转圈（上限 1.2 秒，真要走网络时
  该转还得转）；旧一集的视频与传输等新源出画面之后再收（3 秒兜底）。
- **下一集预热更靠谱**：预取窗口只有片尾 30 秒（`PrefetchPolicy.nearEnd`），而这条接口约一半
  概率回空响应；原先窗口内 15 秒才重试一次、最多 3 次，实际只来得及试两次，两次都空就只能
  退回「切集时现取播放地址」那条慢路——用户看到的正是黑屏转圈。现在改成 6 秒一次、最多 5 次。

### 版本

- versionName `1.0.6` → `1.0.7`、versionCode `30` → `31`。
- 产物：`HGTV_1.0.7.apk`。签名与 1.0.6 相同（证书 SHA-256 `27da9072…e019`），可直接覆盖安装，本机记录保留。

## 1.0.6：账号参数导入、设备注册与相关作品接口

### 修复

- **手机扫码导入账号参数报「来源不匹配」**：扫码 App 的内置浏览器（微信 / QQ / 支付宝的 X5 内核）
  会把页面套进自己的容器里，提交时 `Origin` 变成 `null`、`Sec-Fetch-Site` 报成 `cross-site`，
  原先「`Origin` 必须与本机地址逐字符相等」加「`cross-site` 一律拒绝」两条检查于是把**自己人的
  浏览器**挡在门外。现在只拦能明确指认的第三方站点（`http(s)://` 且不是本机），
  认不出来源的放行；边界仍由临时端口、128 位随机地址、15 分钟时限、一次性消费与
  局域网来源判定守住。
- **未登录时「我的」页焦点下不到「导入账号参数」**：导航栏那排圆形入口（以及同在一行的
  收藏 / 历史 / 点赞 / 预约芯片）的「按下键」原先落在同一视觉行的芯片上，内容为空时
  也没有后续接线能改它，焦点只能在导航栏那一行里打转。现在它们统一落到导航栏正下方的
  身份行（未登录时就是「导入账号参数」）。
- **相关剧集不再等 2~4 秒**：原先「同系列各季」是拿剧名去官网搜索近似召回——沿季号逐季搜
  （1 到「当前季 + 2」每个季号中文 / 阿拉伯各一次）、基名与去尾字各搜一次、再扫 6 页片库目录，
  二十多次请求、实测 2~4s，召回还不稳定（同一部剧的某一季有时在前 10、有时不在）。
  现在改用 App 详情页那一栏自己的接口 `GET /reading/bookapi/plan/v:version/`
  （`scene=10&from=detail_page_more_related&book_id={剧集 ID}`）：**一次请求拿全**，
  实测 0.4~1.1s（含空响应换线重试），并且平台自己给了 `season_index`。

### 变更

- **播放只用平台注册过的设备身份**：`device_id` / `install_id` 不再有「本机随机值」这一路，
  唯一来源是匿名注册（`device_register`）下发的那一对。启动时异步注册一次，**取播放地址
  之前再同步兜一次**（取地址与下一集预取两条路），预取另开的那个仓库实例也共用同一份身份
  与注册 Cookie。注册没落地时不再拿随机值签名，也不会落到内置那份被平台拉黑的档案上。
- `ContentRepository.related(id, title)` 改为读「相关作品」cell（`show_type=547`）的
  `video_data[]`；同系列仍按剧名（`SeriesSeasons.normalize`）筛、按季号升序排在前面，
  其余条目接在后面并按剧集 ID 去重，正在看的那一部不出现。
- 那一栏另按剧集 ID 缓存（`RELATED_CACHE_LIMIT`，16 条）：看一集回简介再点开不再打接口。
- 官网详情页的 `recommendationGroups.related_list` 退居**兜底**（接口整轮失败时用），
  不再触发任何搜索与片库目录扫描；`SEASON_*` 那一套常量与线程池随之删除。
- 界面把剧名一起传下去（`repository.related(id, detail?.series?.title)`），core 不必再取一次详情。

### 说明

- 这个接口约一半概率回 **HTTP 200 + 0 字节**（与设备是否注册无关），客户端按六条线路轮换重发、
  最多 8 次；`ads5-normal-*.zijieapi.com` 不认这个接口（实测 0/6），不在候选里。
- 不能只看 `tag_info`（`第N季` / `同IP`）挑同系列：`第N季` 那一组里混着同 IP 的另一个系列
  （万妖图录传第一季那页有「万妖图录传：月落镇魔第二季」）。筛选规则仍是按剧名归一化比对。
- 协议、字段、坑见 [HONGGUO_API.md](HONGGUO_API.md) 4.6。

## 1.0.4：修掉长文本弹窗第二次打开时按钮被顶出画面

1.0.3 的弹窗封顶做在布局回调里，有时序依赖：第一次弹窗（内容就地变长）能封顶，
第二次打开时内容一开始就是长的，判定成「不溢出」，按钮又被顶出画面。

### 修复

- 弹窗内容区的封顶移到**测量阶段**：无论内容何时变长，量的那一刻就已经封顶。
- 内容区溢出时的焦点接线只在溢出状态翻转时触发一次。

### 版本

- versionName `1.0.3` → `1.0.4`、versionCode `27` → `28`。
- 产物：`HGTV_1.0.4.apk`。签名与 1.0.3 相同，可直接覆盖安装，本机记录保留。

## 1.0.3：长文本弹窗改为滚动，按钮不再被顶出画面

更新日志、开源许可这类正文很长，弹窗的内容区原先**既不封顶也不滚动**，一长就把
按钮行顶出画面——用户看得到日志、却看不到「更新 / 暂不更新」。

### 修复

- 弹窗的内容区加上「封顶 + 滚动」：超出部分在内容区里滚动，按钮行始终留在画面里。
- 内容区与列表区**共用一份高度预算**（屏幕高度的 50%），两块同时出现时
  （备份恢复：说明文字 + 选项）加起来也不会顶出一屏；只有一块时那一块独占，
  短内容按自然高度摆、不封顶，观感与以前完全一致。

  取「不是某一部剧」的那些词合成一份（`都市日常 / 逆袭翻身 / 甜宠 / 战神归来` 这类），
  按词类型分层 + 层内按种子轮询，避免整排都是一个题材的变体；接口整体不可用时退回一张写死的兜底表。
- **搜索页重做**：搜索框与「搜索 / 历史」搬进顶部导航栏，页面第一行就是热搜词 / 提示词；
  输入框固定 300dp、两个按钮按文字宽收紧、三个元素彼此靠近，与右边那排圆形入口之间留出空白。
  输入框提示写明「怎么打字」（遥控器方向键选字，也可外接键盘），提示字号比正文小一档，
  整句放得下。「手机输入」按钮去掉（手机填写搜索登录态、备份恢复仍在设置里）。
- **榜单页「AI」按钮改为「AI剧」**；**分类页「真人剧」大类改为「真人」**，
  与榜单页那四枚芯片（漫剧 / 短剧 / 真人 / AI剧）写法统一。

### 修复

- **榜单 / 分类首次进入的默认选择与落点**：本次运行第一次进分类页默认「漫剧 · 全部」、
  焦点落在二级分类的「全部」上；第一次进榜单页默认「漫剧」、焦点落在「漫剧」芯片上。
  这两页是「先挑一个再看内容」，原先焦点直接跳到内容第一张卡，让人不知道自己看的是哪一类。
  分类选择的**本机持久化**一并去掉：每次打开应用都从默认值起步。
- **榜单 / 分类的焦点**：点哪一枚芯片，焦点就留在那一枚上（不再跳到内容第一张卡，
  也不再「选完二级分类先跑到一级分类」）。为此换榜单 / 换分类时不再清空列表——
  旧的一屏留在原位等新数据落地，观感上不再「每次选分类都闪一下」。
  页头芯片的左右键改为显式接管（只写 `nextFocusRightId` 时会被行外控件抢走，
  表现出来就是「向右切不动」）；页头最上面那一行按上键**停在原地**，
  不再跳到导航栏的圆形入口上。
- **首页按返回**：首页按返回键直接弹退出确认。原先先把焦点搬到顶部圆形入口再等第二次返回，
  而页头收起时那一行高度是 0，焦点请求没有可见落点，表现出来就是「按多少次都没反应、也弹不出退出框」。
- **从首页剧架进不去榜单页**：`switchRankBoard` 里少了「从首页进来时把顶部标签切到排行榜」那一步，
  导致点剧架行末「查看全部」（或行末按右键）后页面原地重画成首页。
- **榜单 / 分类「加载更多」接不上最后一行**：一页 20 部按六列切开时最后一行只有 2 张、
  后面 4 个槽位是空槽；追加下一页时窗口范围没变，那一行不会重绑，
  于是新内容从下一行开始显示，看起来像「第 4 列只有 2 个、第 5 列又继续加载」。
  现在追加后重绑一次当前物化的那几行，新的一页会先把最后一行填满。
- **首页剧架最右边进不去榜单**：同上一条的入口问题，行末「查看全部」与右键两条路径都已核对。

### 性能

- **封面缓存重做**：磁盘缓存从「存原图」改为「存已经缩到卡片尺寸的 WebP」
  （一张 15~25 KB），命中时解的是小图；解码改成一次解到目标尺寸，
  不再「解出接近源尺寸的位图再复制一张」。内存缓存从 4 / 8 MB 提到 16 / 24 MB
  （原先刚好装不下一屏，滚一屏就把上一屏全挤掉，往回滚等于全部重解码——这是「滚动一直看到灰卡」的直接原因）。
- **剧卡栅格改为固定窗口 + 行复用**：列表高度由两个 Space 撑出来，只物化视口附近那几行，
  行与卡片都复用。View 数、每次追加的工作量、每次滚动的重排量都与「已加载多少」无关，
  根治了「加载几百个卡片之后越来越卡」。

### 版本

- versionName `1.0.1` → `1.0.2`、versionCode `25` → `26`。
- 产物：`HGTV_1.0.2.apk`。签名与 1.0.1 相同，可直接覆盖安装，本机收藏 / 进度 / 设置保留。

## 0.15.1：弹幕里的表情标签还原成表情图

平台的弹幕里表情不是字形，而是方括号包起来的名字：`[笑哭]`、`【赞】`、`［狗头］`。
以前照原样画出来，屏幕上就是一串 `[笑哭]` 文字；这一版把它们还原成表情。

- 包名 `com.hongguotv.nativeapp`，versionCode 22，versionName 0.15.1，最低 API 26 / 目标 API 36。
- 产物：`outputs/hongguotv-kotlin-0.15.1-android8.apk`（debug 包为 `hongguotv-0.15.1-debug.apk`）。
- 签名与 0.9.x–0.15.0 相同，可直接覆盖安装；本机收藏 / 历史 / 设置保留。

### 1. 三层映射：标签名 → 字形 → 图片

```
[笑哭] ──标签表──▶ 😂 ──图片表──▶ 1f602.webp ──▶ 画在画布上
```

- **标签表**（`core/.../DanmakuEmoji.kt`）：231 条名字 → 字形。同一张脸在平台上有很多叫法
  （`笑哭` / `大笑` / `爽`），都收在同一张表里；名字大小写不敏感（`OK` / `okk`）。
- **图片表**：144 个字形 → 文件名，文件名就是码位（`1f602.webp` = 😂，`2764-fe0f.webp` = ❤️）。
- **图片**：`app/src/main/assets/danmaku_emoji/`，Microsoft Fluent Emoji 转 128px WebP，
  144 张共 592 KB（原 PNG 是 5.3 MB）。许可证随图放在同目录 `LICENSE.txt`（MIT）。

### 2. 标签识别

三种括号都认：半角 `[名字]`、全角 `［名字］`、`【名字】`。名字 1–16 个字符，且不含任何括号与换行。

这样几条边界是对的：

| 输入 | 结果 | 为什么 |
| --- | --- | --- |
| `前面高能[笑哭]` | `前面高能😂` | 正常标签 |
| `[不存在]高能` | 原样保留 | 认不出的名字不吃字 |
| `看到第[3]集` | 原样保留 | 正文方括号大多认不出名字 |
| `[前面[笑哭]` | `[前面😂` | 名字里不允许出现括号，外层不匹配、里层照常换 |
| `[笑哭\n]高能` | 原样保留 | 换行把标签截断 |

### 3. 一个表情可能不止一个码位

`✌️` 带变体选择符、`😮‍💨` 用 ZWJ 连、`👉👈` 是两个表情并排。切片段时按**字形簇**切，
整簇一起查表——按码位切会拆出半个表情，把两张图叠在一起。

正文里本来就打出来的 emoji（`哈哈😂`）一样能认出来：表按字形给，不要求先有标签。

### 4. 弹幕层的画法

`DanmakuView` 的每条弹幕从「一段文本」变成「文字片段 + 表情片段」：

- 宽度 = 文字按字体量 + 表情按 `1.2 × 字号` 算；表情图贴着文字行中线居中
  （按基线直接画会整体偏上）。切片段只在整批重排轨道时做一次，每帧只按播放位置求 x。
- 图还没解好时**退回画字形**（片段里就存着字形），宽度早已按图片边长算过，
  所以换成图片之后这条弹幕的位置和长度都不会跳。
- 表情图跟着弹幕透明度一起淡：字淡了、表情还是全彩，看上去就像贴上去的贴纸。

图片解码在 `DanmakuEmojiStore` 里：固定 128px 解码（字号是用户 0.6–2 倍滑出来的，
跟着字号解码会为每个缩放档位各存一份位图），LRU 封顶（低内存设备 4 MiB、其余 8 MiB），
整批重排时先把这一集用到的表情排进解码队列，屏幕上不会先闪字形再换图。

### 6. 修复：所有影片都放不了（平台改了播放接口路径）

现象：这一版（以及**未改动的 0.11.0 基线**）所有影片都打不开，提示「播放接口暂不可用」。

原因在平台侧，不在客户端改动：播放接口从

```
POST /novel/player/multi_video_model/v1/            ← 旧路径，现在一律返回 Code 110001 未知异常
POST /novel/player/multi_video_model/:dr_scene/v1/  ← 现在要带场景段
```

改成了带场景段的形式（路由表里本来就是这两条，`:dr_scene` 之前可以省略、现在不能）。
实测同一份请求体：旧路径 `110001`，`.../default/v1/` 与 `.../detail/v1/` 都返回 `code 0` 与完整的
`video_model`。六条线路（a/b/c/lf/lq/hl）表现一致，逐档版本号（7.1.3 → 7.4.2）也一样，
所以与线路、与 App 版本都无关。

修法（`ContentRepository.videoModel`）：按 **`default` → `detail` → 旧路径** 的顺序试，
第一个业务成功（`code == 0` 且 `data` 非空）的就用；全失败时抛最后一个错误，
界面照常显示「播放接口暂不可用」。旧路径留在最后，灰度环境或平台回滚时还能用。

回归测试三条（`ContentRepositoryTest`）：优先带场景段的路径、带场景段全失败时退回旧路径、
三条路都只有业务错误码时如实报错。联网复测：`quality=1080P; total=28974608; header=ftyp`
（真实 1080P 分段可读）。

### 7. 弹窗按钮不再「常亮」、二级分类小一档

**弹窗里的按钮一律常态外观。** 之前「确认 / 知道了 / 手机填写 / 合并恢复」用的是 PRIMARY——
PRIMARY 是「常亮的亮面板」（给详情页主操作用的，一屏最多一个），放进弹窗里看起来就像
**一直处于焦点**，退出确认时容易误以为焦点已经落在「确认」上。现在弹窗里全部改用常规档，
靠文案区分动作；焦点落点不变（列表型弹窗落在第一项，其余落在第一个按钮）。

**分类页的二级分类（小类）整体小一档。** `ToggleChip` 增加尺寸档参数，
分类页的大类用默认档（高度 48dp / 字号 16sp / 左右内边距 28dp），小类用紧凑档
（40dp / 15sp / 18dp），小类那一行的行内间距也收一档。两行大小不同，一眼能看出层级。

## 0.12.4：相关剧集改成懒加载，并尽量把同系列各季找齐

0.12.3 把「同系列各季」挂在了详情接口上，导致每次进简介页都要多等几次搜索；这一版把它挪到
「相关剧集」按钮里，并换了召回更好的取数方式。签名与 0.9.x–0.12.3 相同，可直接覆盖安装。

- 包名 `com.hongguotv.nativeapp`，versionCode 19，versionName 0.12.4，最低 API 26 / 目标 API 36。
- 产物：`outputs/hongguotv-kotlin-0.12.4-android8.apk`。

### 1. 懒加载：详情先上屏，相关剧集后台预取

`Detail` 不再带 `related` / `seasons`（改由 `RelatedWorks` 单独返回）。流程是：

1. 点进简介页 → 只等详情，**内容立刻渲染**（实测 458–522ms）；
2. 详情落地的那一帧就把相关剧集丢到后台去查（`prefetchRelated`，2~4s 跑完，界面无感知）；
3. 用户点「相关剧集」时**不再发新请求**——取好了直接铺；还在途中就等它落地
   （这段时间界面显示「正在查找同系列…」，通常察觉不到）；同一部剧不会重复请求
   （`relatedFor` 挡住重复，失败后用户再点开才补一次）。

失败显示「相关剧集加载失败」+「重试」按钮，不再静默空列表。

这条请求**不走 `work`**：`work` 会取消上一次在途请求（详情页重排、切集都会触发），
相关剧集的结果会被自己页面的重排取消掉，永远停在加载态。因此它单独持有
`relatedToken` + `relatedJob`，结果落地前再确认「还是同一部剧、还停在详情页」。

### 2. 召回：沿季号逐季搜索 + 三路合并

官网搜索一次只回 10 条、且**忽略所有分页参数**（实测 `?page=2/3`、`?page_num`、`?offset`、
`?pageNo`、`?p`、`?limit` 全部同一批），但**换关键词就是换一批**。于是取数改成：

| 手段 | 说明 |
| --- | --- |
| **沿季号逐季搜** | 搜 1 到「当前季 + 2」的每个季号（`第三季` → `第四季` → `第五季`…）。**不能只往上搜**：当前是最新一季时，更早的那几季只能靠搜它们自己的季号命中；每个季号带回的 10 条里往往包含好几个季，逐个搜一遍就都覆盖到了。中文写法优先，整轮无命中才补一轮阿拉伯写法 |
| 基名与去尾字 | 基名本身搜一次（第 1 季的剧名常常就是基名），再去掉 1~3 个尾字各搜一次 |
| 片库目录扫描 | `/category/real-drama?page=N` 每页 24 部、共 34 页，稳定分页，是召回的最后一道保险；最多 6 页 |
| 并发 | 这些请求彼此独立，二十多个串行要一分多钟（实测 1m49s），因此走 4 路 `relatedPool` 并发，整轮约 2~3s |
| 归一化筛选 + 按季号排序 | 剥季号、全角转半角、去标点后完全相同才算同一系列，再按季号升序 |

实测（同一部剧三次跑）：

| 剧集 | 0.12.3（只搜基名） | 0.12.4 | 耗时 |
| --- | --- | --- | --- |
| 聚宝仙盆之杂灵根才是真BOSS第十三季 | 8 季 | **13 季全** | 2.6s |
| 一梦青玄，团宠小师妹一剑毁天灭地第七季 | 5 季 | **7 季全** | 2.1s |
| 帐中香（只有 1 季） | 1 季 | 1 季 | 2.3s |

合并后共 29 条（同系列 13 季在前，相关短剧在后，按 id 去重）；`帐中香` → 17 条。

### 3. 简介页按钮行：四个入口等宽，播放键不再常亮

- **等宽**：「开始观看 / 继续第 N 集 / 重新观看」「收藏」「完整简介」「相关剧集」四个按钮
  改成**等宽**。原先按文字宽度自适应，「继续第 12 集」与「收藏」差一倍，整行参差不齐。
  实现用 `weight=1f` 让父容器等分，并把这些按钮的最小宽度清零
  （`TvButton` 默认 92dp 最小宽度，等分到的宽度比它小时会按最小宽度量出来，四个加起来顶破父容器）。
  **不要自己按屏宽算像素**：这一行在海报右侧的信息列里，可用宽度是
  「屏宽 − 两侧边距 − 海报宽 − 间距」，按整屏四等分会直接溢出屏幕（踩过一次，见下）。
- **播放键不再常亮**：去掉 `ButtonTone.PRIMARY`（常亮的亮面板），四个按钮统一走常规档。
  简介页这一行是四个平级入口，只有一个亮着会让其余三个看起来像次要操作；主次交给位置表达。
- 实现：`addButton()` 增加可选 `width`（固定像素）与 `weight`（等分父容器），
  默认仍是按内容宽度自适应，其它页面不受影响；`TvButton` 增加可选 `pad` 覆盖左右内边距
  （这一行用 14dp 而不是 HERO 档的 36dp，否则「继续第 12 集」会被挤成省略号）。
- **播放按钮的文案固定为「播放」**，不随状态变（曾按状态显示「开始观看 / 继续第 N 集 / 重新观看」）。
  续播目标仍由 `ResumePlayback.target` 计算——上一集看完 → 从下一集开头，
  看到一半 → 回到那一集的那个位置；文案与动作同源，只是不再把集数写在按钮上。

### 4. 不再弹系统 Toast

应用里**不再弹 Toast**（`MainActivity` 里 `Toast.makeText` 已全部移除，dex 里 0 处引用）。
Toast 是独立于界面的一层浮窗：样式、字号、焦点行为都不受本应用控制，电视上还会盖在画面正中。

逐处处理方式：

| 原 Toast | 现在 |
| --- | --- |
| 热门已更新 / 刷新失败 / 加载更多失败 / 搜索结果已过期 / 记录已合并恢复 | 改为**页面内提示行**（页头下面一行淡字，不参与焦点、4 秒后自己消失，页面重建时按状态复原） |
| 正在更新热门… | 只在没有缓存可显示时才提示；有缓存时页面本身就是「上次内容」 |
| 已收藏 / 已加入稍后看 / 已隐藏推荐 / 恢复隐藏推荐 / 搜索登录态已保存、已清除 / 主题已切换 / 删除记录 | 直接删掉——按钮文案或列表本身已经变了，不需要再说一遍 |
| 本集没有弹幕 | 播放界面状态行本来就报条数（`弹幕 全屏弹幕 · 无`） |
| 定时停止已生效 | 状态行已经写了「定时停止已生效 · 观看位置已保存 · 按播放可继续」 |
| 正在刷新某页 | 删掉——页面本身会重新加载 |

## 0.12.3：相关剧集改成「同系列各季 + 相关短剧」

上一版的相关剧集取的是官网详情页的推荐位（`related_list`），实测那不是同一部剧的其它季。
这一版把「同一部剧的其它季」排在前面（按季号升序），后面再接原来的相关短剧，重复的去掉。
签名与 0.9.x–0.12.2 相同，可直接覆盖安装。

- 包名 `com.hongguotv.nativeapp`，versionCode 18，versionName 0.12.3，最低 API 26 / 目标 API 36。
- 产物：`outputs/hongguotv-kotlin-0.12.3-android8.apk`。

### 1. 平台没有分季接口（实测）

| 位置 | 结论 |
| --- | --- |
| `seriesDetail` 全字段 | 只有当前这一季，没有 season / series_group / album 字段 |
| `recommendationGroups.related_list` | 「看了这部还看什么」的推荐，不是同系列 |
| `recommendationGroups.hot_list` | 同页热门栏，与本剧无关 |

能拿到同系列的入口只有一个：**用剧名去官网搜索**。实测搜「聚宝仙盆」时，同一系列的
7 季都排在第 1 页 10 条里；搜全名时前 10 条全是本系列。

### 2. 做法

`core/SeriesSeasons.kt`（纯逻辑，6 项单元测试）：

1. **基名**：剥掉剧名尾部季号——`第X季` / `第X部` / `X季` / `SX` / `Season X`，
   中文数字（`十三`）与阿拉伯数字（`13`）都认；`第一季` 归一为第 1 季，没有季号算第 1 季；
2. **归一化比对**：候选剧名同样剥季号、全角转半角、去空白与标点后与基名完全相同才算同一系列
   （否则 `咱家剑宗团宠小师妹第五季` 会被当成 `一梦青玄，团宠小师妹一剑毁天灭地` 的兄弟）；
3. **排序**：按季号升序，季号相同按剧名兜底。

`ContentRepository.seasonSiblings()` 用基名走官网搜索，最多翻 3 页（一页约 10 条，
第 2 页起是片库目录扫描，按 id 去重），再用上面的规则筛出同系列。

`relatedFor()` 把两段合并：**同系列各季在前，`related_list` 的内容在后，重复的按剧集 ID 去掉**
（正在看的那一部本身也不重复出现）。`Detail` 因此增加 `seasons` 字段，界面据此标注季号。

### 3. 界面

- 标题按有没有同系列区分：「**同系列 N 季 · 相关剧集**」/「相关剧集」；
- 同系列的卡片在**海报右下角标**上写「第 N 季」，正在看的那一季写「正在看」
  （状态行那点字号读不出季数）；
- 点其它季的卡片直接进那一季的简介页；空列表时仍显示「这一部暂时没有相关剧集」。

### 4. 验证与边界

- `:core:test` 全绿（新增 `SeriesSeasonsTest` 6 项：季号解析、中文数字、无季号按第 1 季、
  归一化、同系列筛选与排序、空输入）；
- `--related` 探针实测：
  `聚宝仙盆之杂灵根才是真BOSS第十三季` → 同系列 8 季（第 1 / 4 / 5 / 6 / 7 / 10 / 11 / 13 季，
  升序、无别的剧混入）+ 相关短剧，合并后 24 条且无重复；
  `帐中香` → 同系列 1 季（就是它自己）+ 相关短剧 16 条；
  探针内置断言：升序、不混入别的剧、无重复条目、同系列排在前面；
- `:app:lintRelease` 无 error；`:app:assembleRelease` / `:app:assembleDebug` 通过；
- 文档：`docs/HONGGUO_API.md` 新增 3.4.2 节（做法 + 实测证据 + 局限），
  `README.md` 顶部版本与本节同步。

**局限（如实记录）**：剧名写法不统一时会漏掉或混入——改名、副标题变化、外传与正片同名都算；
平台把同一系列拆成不同基名（`聚宝仙盆仙界篇` 与 `聚宝仙盆之杂灵根才是真BOSS`）时也会各算一系列。
因此这一栏做的是「同系列各季 + 相关短剧」的合并列表，而不是严格的分季树。

## 0.12.2：简介页「相关剧集」

简介页新增一栏「相关剧集」，数据取自官网详情页同一份 HTML 里的相关短剧列表。
签名与 0.9.x–0.12.1 相同，可直接覆盖安装，本机收藏、观看进度、主题与播放偏好全部保留。

- 包名 `com.hongguotv.nativeapp`，versionCode 17，versionName 0.12.2，最低 API 26 / 目标 API 36。
- 产物：`outputs/hongguotv-kotlin-0.12.2-android8.apk`。

### 1. 相关剧集的数据来源

官网详情页 `GET /detail?series_id={id}` 的 HTML 里有两段数据：

1. `_ROUTER_DATA.loaderData.detail_page.seriesDetail` —— 现有的详情（`vid_list` 等），**不含相关作品**；
2. `<script data-fn-name="mergeLoaderData" data-fn-args="…">` —— 相关短剧的增量数据。参数是 HTML
   实体转义过的 JSON 数组 `["detail_page",[{key:"recommendations", routerDataFnArgs:["<JSON>"]}]]`，
   内层 JSON 是 `{videoList, recommendationGroups:{hot_list, related_list}}`。

客户端取 `recommendationGroups.related_list`（实测 16 部，字段与 `Card` 同构），缺失时退回
`videoList`，解析失败按「没有相关短剧」处理——相关剧集只是附加内容，不能影响详情本身。
解析实现在 `ContentRepository.extractRecommendations` / `relatedOf`，`Detail` 增加 `related` 字段，
详情页因此**一次请求**就能拿到两者（不再多发一次）。

联调：`./android/gradlew -p android --offline :core:run --args="--related <剧集ID>"`。

### 2. 交互与布局

- 「**相关剧集**」按钮排在「完整简介」之后，与「开始观看 / 收藏」同档同高（56dp）；
- 点开后：**左边封面缩到与右边「开始观看」按钮的底边平齐**（高度 = 右侧信息区的高度，
  宽度按 7:10 一起缩，避免 FIT_CENTER 在变矮的卡座里留白），
  **下方的选集整块隐藏，换成横向排列的相关作品**；再点「收起相关」恢复选集与大海报。
- 相关作品沿用首页剧架的卡片（竖版海报 + 剧名 + 状态），横向可滚动，左右选片、确认进那一部的简介页；
  长按 / 菜单键的卡片菜单也在（详情页上不出现「不在热门推荐中显示」这一项）。
- 焦点：按钮行按下键落到相关作品第一张卡，卡片按上键回到「相关剧集」按钮；收起时这套指向改回选集网格。
- 接口没给相关剧集时显示「这一部暂时没有相关剧集」，不留空白。

### 3. 验证与边界

- `:core:test` 全绿；`:app:lintRelease` 无 error；`:app:assembleRelease` / `:app:assembleDebug` 通过。
- `--related` 探针实测：`聚宝仙盆之杂灵根才是真BOSS第十三季` 与 `首辅娇娘` 各 16 部，两次请求结果一致。
- 文档：`docs/HONGGUO_API.md` 新增 3.4.1 节（取值步骤 + 字段说明 + 联调命令），
  `docs/hongguo-openapi.yaml` 的 `/detail` 同步说明。
- 本机无可用 AVD（`system-images` 为空目录、`sdkmanager` 拉取报 `Premature EOF`），
  因此没有模拟器交互复测：封面与按钮底边的对齐、横向列表在 720p 画布上的密度，
  仍需在 Android 8 实体电视上看一眼。

## 0.12.1：图标扁平化、设置页去掉刷新入口

- 产物：`outputs/hongguotv-kotlin-0.12.1-android8.apk`。

### 1. 设置页不再显示顶部刷新入口

顶部导航栏的圆形「刷新」按钮在**设置页**上不创建（其余页面照旧，位置仍在「搜索」左边）。
这一页没有任何可刷新的列表——偏好改动立即保存——留着它只会占一个位置，点下去还得弹一句
「没有可刷新的列表」；去掉之后顶部的「设置」图标自然补上它的位置。

刷新按钮同时从 `nav` 列表里挪出来单独持有：`nav` 恢复成「搜索 / 排行榜 / 设置」三个页面入口，

### 2. 应用图标铺纯白背景

图标底板由「透明」改成**纯白不透明**（`@color/ic_launcher_background` = `#FFFFFF`），
自适应图标背景层、API 26 以下的位图兜底、iOS 那九张图标统一用同一个色值。

透明底时图标在桌面上的观感完全由启动器决定：模拟器上的 Lawnchair 会给每个图标垫一块纯黑底板
（深色模式），同一张图在不同设备上会落成黑方块 / 深灰方块 / 直接贴壁纸，看起来像三个应用。
实测白底压在启动器底板之上（`background` 换白后量到 (1,1,1)），因此各设备观感一致。

### 3. 图标改成扁平风格，并去掉播放三角

果身、果叶各一块纯色（`#EE4C33` / `#6E9F3E`），果叶上一条 `#3E6522` 的中脉，就这些：

- 拟物版那套径向渐变（迎光面 → 本色 → 背光边缘）、接触阴影、左上高光、右下环境反光全部删掉
  ——缩到桌面的 48dp 之后它们只剩一两个像素的杂色；
- 果身正中那枚播放三角一并去掉——同样缩到 48dp 只剩几个像素，读起来像果身上的一块白斑；
- 颜色沿用拟物版的本色，因此与旧版是同一个红、同一个绿；
- 轮廓、安全区（0.80）与自适应图标的拆层方式都没动。

位图与矢量两条渲染路径同时改：`render_master()` 只剩纯色填充与一条中脉，
`vector_xml()` 只剩 3 条路径（果身 / 果叶 `fillColor` + 中脉 `strokeColor`），
渐变相关的辅助函数与 `<aapt:attr>` 结构整段移除。`docs/preview/.local/icon.png` 重出，
新增「白底 / 透明底」对照行。

### 4. 弹幕选「隐藏弹幕」时收起外观两项

隐藏档整层不画、也不发请求，这时改字号或透明度看不到任何变化——留着一排调不出效果的滑动条，
只会让人以为功能坏了。因此：

- **设置页**：「弹幕大小」「弹幕透明度」两行**连行一起** `GONE`（只藏滑块会在左边留一条空标签）；
  隐藏时「弹幕显示」的下行出口直接指到主题网格，焦点若正停在被收起的那一行上则退回「弹幕显示」。
- **播放设置面板**：那两行**直接不添加**，面板从「弹幕」直接接到「定时」；
  「定时」的行号因此不固定，收敛成 `sleepRow(showsStyle)` 现算（原先写死 `MENU_ROW_SLEEP = 6`）；
  在面板里切档会整块重建，焦点按回「弹幕」这一行、落在同一个档位上。

- 滑动条标签字号回到与其它设置项同一档（`TvStyle.BUTTON_TEXT_NORMAL`），不再单独放大一档。

## 0.11.0：弹幕看得见、播放界面更安静、播放设置收进下方三分之一

本版把「弹幕」这条路从「接口能取到数据」推进到「屏幕上真的看得见、能调大小与浓淡」，
并把播放设置面板收进屏幕下方三分之一。签名与 0.9.x / 0.10.0 相同，可直接覆盖安装，
本机收藏、进度、主题与播放偏好全部保留。

### 1. 弹幕不显示：根因是视图可见性把自己锁死了

`DanmakuView` 原来在排轨道之前先把空态设成 `GONE`。`GONE` 的视图**不参与测量**，
于是 `width`/`height` 永远是 0，「有宽高才排轨道」的条件永远不成立，
接口就算返回几千条也一条都画不出来——表现和「弹幕功能没生效」完全一样。

现在的规则：

- 空态用 `INVISIBLE`（照样被测量、被布局，只是不绘制），取到弹幕时能立刻按真实尺寸排轨道；
- 可见性只按「这一集有没有数据」判断（`mode==HIDDEN || raw.isEmpty()`），不再按「排没排成轨道」判断，
  两个条件不再互相等待；
- 每换一集 `danmakuToken` 自增一次，在途的窗口循环发现 token 变了立刻收手，旧剧的弹幕不会接到新一集上。

### 2. 边拉边画：不再等整集拉完才出第一条

整集要按 30 秒窗口连着拉几十页，窗口之间还有 180ms 频控间隔，整集拉完要十几秒。
等全量再画等于前十几秒一条弹幕都没有。`ContentRepository.danmaku` 因此增加
`onWindow` 回调，每到一个窗口就交给主线程先铺上屏（带 token 校验，切集后到达的旧窗口直接丢弃），
整集拉完再替换成完整的一份。

### 3. 弹幕稀疏是平台行为，不是参数问题（实测结论）

模拟器上装了抓包工具与官方短剧 App，请求被断开、拿不到有效数据，于是改成在系统 CA + Frida 挂钩
`SSL_write`/`SSL_read`（命中 `libsscronet.so`、`libttboringssl.so` 等 11 个库，响应是 brotli）。
**决定性证据**：原版 App 对同一集也只收到 `total: 2`，5 个窗口只有窗口 0 有数据；
用抓到的请求体逐字段回放，结果一样是 2 条。

结论：接口对匿名设备返回的是**采样后的热弹幕**，与请求参数无关，`cursor` 里的
`danmaku_count` 也不是弹幕条数。表现就是「有的剧一屏弹幕、有的剧一条都没有」——
同一部剧的另一集实测拿到 114 条。播放界面的状态行会直接报出这一集取到多少条，
`adb logcat -s HongguoTV` 里也有一行 `Danmaku episode=... count=...`，
便于区分「这一集本来没有弹幕」和「弹幕功能没生效」。

### 4. 播放时屏幕上只剩画面与弹幕

- **顶部标题条默认收起**：整宽 96dp 的「剧名 · 第几集 + 时钟」原来一直压在画面上，
  现在只在唤出播放界面时出现（底部控制条、播放设置面板、选集面板、播放失败界面都会把它带出来），
  收起时整条 `GONE`，不占画面也不参与绘制。
- **上方弹幕只占最上面四分之一**：`TOP` 档的可铺区域从「约三分之一」收到 `0.25`，
  离顶边的安全边距从 104dp（标题条高度）收到 20dp，留白全放在下面，
  弹幕整体往上走、不再压画面正中；`FULL` 档仍然是整幅画面，只让开标题条与底部控制层。

### 5. 播放设置面板收进下方三分之一，多出来的滑出来

面板原来是「内容多高就多高」，七行铺下去会占掉大半个屏幕。现在：

- 整宽贴在画面下方，**高度锁死为屏幕高度的三分之一**（`heightPixels/3`）；
- 装不下的行留在滚动容器里，遥控器焦点走到哪一行就自动把哪一行带进可视区
  （`ScrollView` 自身的 `requestChildFocus` 行为），七行全都按得到；
- 渐变背板画在外壳上而不是面板上：否则背板会跟着内容一起被拉长，滚到下半段时面板顶部会变成半黑，
  而不是「从透明渐渐暗下去」；外壳同时负责裁剪，面板内容不会画到面板之外；
- 行号收敛成常量（`MENU_ROW_*`）：面板里几处「改完就地重画这一行、再把焦点按回同一格」的调用
  原来写死数字，中间插一行就会全部错位。

### 6. 新增「字幕大小」「字幕透明度」两条滑动调节

播放设置面板与设置页都加了这两条，改的是同一份本机偏好，进播放界面立刻生效：

| 项目 | 范围 | 步长 | 默认 |
| --- | --- | --- | --- |
| 字幕大小 | 60% – 200% | 10% | 100% |
| 字幕透明度 | 20% – 100% | 10% | 100% |

滑动条复用全站紧凑档按钮的外观与焦点体系（凸起 / 打亮 / 按进去三态、胶囊圆角、同样的柔光带），
里面画轨道、已选填充 + 圆钮、右对齐的百分比读数。**不用 `SeekBar`**：
电视上 `SeekBar` 会自己抢焦点、自己处理左右键，和面板的四向锁定打架。
这里左右键由控件自己在 `onKeyDown` 里吃掉（按一下走一档、长按连续走），上下键仍然交给焦点系统。

值统一由 `DanmakuStyle`（core）归一：先吸附到 0.1 的整数倍、再夹进上下限、最后抹掉浮点误差，
因此「面板上滑到的数」「写盘的数」「下次读回来的数」是同一个浮点值，
不会出现显示 130% 却和 130% 不相等这类抖档。字号变化会重排轨道（行距跟着字号走），
透明度只改画笔 alpha、不重排；描边的不透明度跟着文字一起缩，字淡了不会留一圈黑边。

### 7. 兼容与验证

- 设置键新增 `danmakuScale` / `danmakuAlpha`；备份文件新增 `danmakuScale` / `danmakuAlpha` 两个字段，
  **旧备份没有这两个字段时按 100% 读回**，越界值直接夹进合法区间，旧文件仍然可以恢复。
- `:core:test` 全绿，新增用例覆盖「两个字段的备份往返」「旧备份缺字段按 100% 读回」
  「越界值夹进区间」「百分比读数」。
- Android 12 模拟器（1440×2560 / 360dpi，横屏 2560×1440）上实测：面板固定在下三分之一、
  滚动可达全部七行、两条滑动条左右键连续调节、弹幕字号与浓淡立刻作用在画面上。

Android 8 实体电视的遥控器手感、4K 画布下的弹幕字号上限、以及长时间播放的稳定性仍需实机确认。

| 用途 | 请求 / 字段 |
| --- | --- |
| 一集弹幕 | `POST https://{api5-normal-*}.fqnovel.com/novel/commentapi/comment/list/{vid}/v1/` |
| 专用请求头 | `comment-source: 601`、`server-channel: 1000`、`x-ss-stub:`（空） |

六条线路（`api5-normal-sinfonlinea / c / b`、`api5-normal-lf / lq / hl`）依次失败转移，
窗口之间留 180ms 间隔避开平台频控；一集最多 40 个窗口、最多保留 3000 条。

**播放设置里的「弹幕」一行**提供三档显示方式，选中即生效并写入本机设置（换集、重开应用都保持）：

| 档位 | 表现 |
| --- | --- |
| 全屏弹幕 | 整幅画面从上到下都是弹幕轨道 |
| 上方弹幕 | 只在画面上部约三分之一内滚动 |
| 隐藏弹幕 | 整层不可见，也不发起弹幕请求 |

**平台只放出一小部分弹幕（已实测）**：接口对匿名设备返回的是「热弹幕」样本，而不是全部。
同一个 30 秒窗口里，服务端自报的弹幕数（`common_list_info.cursor` 里的 `danmaku_window_count`）
与实际下发的条数差得很远：

| 剧集 | 服务端自报（首窗口 / 全片） | 实际拿到 |
| --- | --- | --- |
| 咱家剑宗团宠小师妹第五季 第 1 集 | 6424 / 3706 | 43（整集 119） |
| 万妖图录传第十三季 第 1 集 | 10830 / 27824 | 2 |
| 聚宝仙盆之杂灵根才是真BOSS第十三季 第 1 集 | 3137 / 8430 | 0 |
| 问鼎仙途：踏碎仙凡 第 1 集 | 1036 / 1559 | 0 |

`count` 调到 500、换 `sort`、去掉 `need_danmaku_guide_type`、加 `user_is_login`、把 `x-ss-stub` 换成
body 的 MD5、六条线路挨个试——结果都一样，所以这是平台侧的匿名采样，不是参数问题。
**表现就是「有的剧一屏弹幕、有的剧一条都没有」**，播放界面的状态行会直接报出这一集取到多少条
（`弹幕 全屏弹幕 · 119 条` / `· 无` / `· 加载中`），`adb logcat -s HongguoTV` 里也有一行
`Danmaku episode=... count=...`，便于区分「这一集本来没有弹幕」和「弹幕功能没生效」。

### 2. 搜索：漫剧不再报错，结果改成向下自动加载

- **漫剧搜索报错的根因**：App 搜索接口 `GET /reading/bookapi/search/tab/v` 现在对匿名设备返回
  **HTTP 200 + 空响应体**（六条线路、多组设备参数、GET / POST、全新设备标识都一样，
  `danmu_api` 的独立签名实现同样拿不到数据）。旧代码把空 body 直接丢给 `JSONObject`，
  抛的是 `A JSONObject text must begin with '{'`，而短剧还有一条「退回官网搜索」的兜底、漫剧没有，
  于是漫剧搜索只剩一句错误提示。现在先判空、再退回官网搜索，漫剧和短剧走同一条路。
- **翻页改成向下追加**：搜索页去掉「上一页 / 下一页」，改成和热播榜、热门集合页同一套
  「往下接」机制——滚到接近底部（或焦点走到最后两行）就静默取下一页，接在列表末尾，

- **「更多结果」从片库目录补**：官网搜索不区分内容类型、也**没有分页**——`?page=2`、`page_num`、

  所以搜索被拆成两段：

  | 位置 | 来源 | 说明 |
  | --- | --- | --- |
  | 第 1 页 | App 搜索接口；拿不到数据时退回官网搜索 | App 接口一次 20 条、按内容类型分 tab；官网搜索最多 10 条，按相关度 |
  | 第 2 页起 | App 搜索接口的游标；接口不可用时退回片库目录（`/category/comic-drama` / `/category/real-drama`） | 目录 24 部一页、各 34 页，每次往后扫 3 页，只留下**片名含关键词**且**界面还没见过**的剧 |

  实测「修仙 · 漫剧」（匿名）：10 + 2 + 4 + 4 + 1 = **21 条**，滚到底再收；「聚宝 · 漫剧」：10 + 1 条后收手。
  目录翻完、或者连续一轮一个新条目都没有，`hasMore` 就收掉——不会让用户一直往下滚却什么都没有。
  同一部剧的不同季、目录分页本身的重复都由「已发过名单」挡掉，界面不会看到重复卡片。
- **可选登录态（2026-10-09 复测后新增）**：设置 → 片单与设备 → 「搜索登录态」，用手机扫码粘贴
  App 抓到的 `x-tt-token`（整段 Cookie 也可以）。填上后 App 搜索接口按该账号返回数据，
  搜索第 1 页起就直接用它（一次 20 条、按短剧 / 漫剧分 tab、可继续翻页），不再依赖官网搜索与片库目录。
  口令只存在本机（`native-session-v1`）、只用于搜索请求，不进备份文件、不上传；清除口令即回到匿名请求。
  **不填也能搜索**：退回官网搜索 + 片库目录补页，这是默认路径。
- **翻页改成向下追加**：搜索页去掉「上一页 / 下一页」，改成和热播榜、热门集合页同一套
  「往下接」机制——滚到接近底部（或焦点走到最后两行）就静默取下一页，接在列表末尾，
  视口上方的像素一个都不动，因此不会跳回顶部。底部只留一行不可聚焦的进度文字。
  游标缺失或过期时回到第 1 页重新搜（提示「搜索结果已过期，已回到第 1 页刷新」）。
- **搜索框不再困住焦点**：输入框是 `EditText`，方向键会被它的光标移动逻辑吃掉，焦点回到搜索框后
  上下键就出不去。现在这两下显式交回页面：上=分类开关（短剧 / 漫剧），下=搜索结果第一张卡
  （没有结果时退到顶部入口）。

扁平化与去三角是同一件事的两面：拟物版那套径向渐变（迎光面 → 本色 → 背光边缘）、接触阴影、
左上高光与右下环境反光，缩到 48dp 之后都只剩一两个像素的杂色；扁平色块反而更干净。
颜色沿用拟物版的本色，因此与旧版是同一个红、同一个绿。

矢量与位图（含 iOS 图标、电视桌面卡片）由 `python3 tools/app-icon.py` 从一份几何生成，
没有设备时的校对图是 `docs/preview/.local/icon.png`（含白底 / 透明底对照）。

**为什么从透明改成白底**：透明背景时图标在桌面上的观感完全由启动器决定。模拟器上的 Lawnchair
会给每个图标垫一块纯黑底板（深色模式），三轮实测把这件事钉死：

1. `background` 层留透明 → 黑方块；
2. `background` 换成 alpha=1 的白色 → 量到 (1,1,1)，白底叠在黑底板上，说明底板在图标下面；
3. **前景也换成全透明**（图标什么都不画）→ 那块纯黑方圆仍然在（128×128、15596 个
   `sum(rgb)<40` 的像素）。换启动器即消失。

同一张图在不同设备上因此会落成黑方块、深灰方块或直接贴壁纸，看起来像三个应用。
现在底板由图标自己给，任何启动器、任何壁纸上看到的都是同一块白底 + 同一颗果标。

安全区（同一台设备上量）：启动器把 108dp 画布画成 192px、只露出中央 72dp（128px）的方圆遮罩，
越出去就被切。物件因此缩到 0.80——果身整个落在中央 66dp 的圆里（最远 31dp），果叶尖到 42dp，
离遮罩边缘还有 3dp（实测果叶顶边距遮罩顶边 7px）。

**整个播放界面保持原样、不套新拟态**：顶部「剧名 + 集数」标题条（整宽 96dp 渐变 + 带投影的粗体字）、
底部控制层（三段黑渐变）、进度条（4dp 轨道 + 白色已播 + 白色圆滑块）、播放设置面板的渐变底座、
选集面板压在画面上的渐变背板。播放时这些元素一直压在画面上，柔光底板会和画面抢注意力。

## 0.10.0：界面改版

界面按极光 TV 的排版逻辑重做：近黑沉浸底色、顶部频道导航（选中为强调色下划线）、分区横向剧架、
圆角竖版海报卡与统一的焦点放大描边。原先占掉半屏的大标题预览块整块去掉，

设置页与播放器控制条改用同一套胶囊按钮与圆角单元格。

顶部导航只留品牌、搜索、排行榜、设置四个入口，收藏和历史记录从导航移到首页剧架。
首页剧架按「历史记录 → 我的收藏 → 热门推荐 → 热门发现」排列（用户加过稍后看内容时，稍后看作为
最后一栏出现）：每栏最多十部，来自本机记录的剧架没有数据就不占位，超过十部时行末「查看全部」
进集合页继续看，集合页里「检查更新」和「管理记录」跟着各自的内容放在页头。

简介页与播放界面的选集是同一份网格实现（`EpisodeGrid`，一页 20 集、10 列 × 2 行）：
简介页把网格整幅贴在页面末尾，播放界面按「下」弹出的仍是贴底面板，两处宿主不同、翻页方式相同——
左右到行两端、上下到第一行 / 最后一行到边缘翻页；没有目标页时按键交回焦点系统，
简介页第一页第一行按上因此仍能回到「继续观看 / 收藏 / 完整简介」这一行。
两处都不再提供「跳转集数」键盘，选集路径统一为「翻页 → 确认」。

首页「热门推荐」展示热门列表前十部，第 11 部起顺延到「热门发现」，两个分区不重复。
2026-10-12 起「热门发现」的标题只写这四个字，不再拼片库分类（短剧 / 漫剧）——分类已经在页头
的开关上，标题里再写一次是重复的。
热播榜和首页「热门推荐 / 热门发现」向右进入的热门集合页都去掉「上一页 / 下一页 / 下一批热门」：
列表只在原位向下追加，底部留一个「展示更多 ↓」按钮，停在最后一行按下键落到该按钮，
再按确认或下键继续加载下一页，已显示的名次、热度与滚动位置都保留。

排行榜 / 搜索 / 首页三处的页头（工具条与二级页标题行）随列表滚动收起：向下滚收起、回到列表最上边
或焦点回到页头里再展开，列表内容不会盖住顶部那一排按钮；「展示更多 ↓」原地追加一页时页头保持
原来的收 / 展状态，不会又弹回来。实现与规则见 [界面改版说明](UI_REDESIGN.md) 的「页头随滚动收起」。

播放界面不再有「播放 / 上一集 / 下一集 / 选集 / 播放设置」这一行文字操作：按「上」在画面右侧打开竖向
设置菜单，上下换项目（清晰度 / 倍速 / 画面模式 / 定时）、左右换选项、确认立即生效、返回收起；
按「下」仍是选集面板，停在菜单最后一行再按下键也直接进选集。播放与暂停回到确认键和底部播放键图标。

设计令牌、焦点裁剪规则与组件清单见 [界面改版说明](UI_REDESIGN.md)。
本轮只改了 UI 层源码；调试包已在本机编译并装到连接的 Android 12 设备上复核选集两处界面，

（那次复核之后简介页的选集改成了四向翻页，按键记录不再覆盖现在的行为，
