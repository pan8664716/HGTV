# 多端重构：差异矩阵与迁移说明

> 分支：`arch/v2-rebuild`
> 回退点：`pre-multiplatform-split`（拆分之前的单体 `:app`，36k 行）
> 检查点：`99d8b21`（按端拆分完成、可构建）
> 验证：`:app:assembleDebug` 通过；`:core:test` 382 例通过；`:shared:testDebugUnitTest` 19 例通过

---

## 一、先说结论

这次重构**不是**「把两套重复代码合并成一套」，而是反过来做了一件更彻底的事：

1. 先把原来装在单个 `:app` 里的 TV 代码按职责拆成 `:core`（纯 JVM）/ `:shared`（Android 公共层）/ `:feature-tv`；
2. 手机端**建在已经抽好的公共层之上**，从第一行代码起就没有复制过 TV 的实现；
3. 平台差异全部落在「页面实现 + 尺寸令牌 + 输入层」，业务逻辑只留一份。

因此当前状态的关键数字是：

| 指标 | 结果 |
| --- | --- |
| 公共层（`:core` + `:shared`）里的平台判断（`isTV` / `deviceForm` 分支） | **0 处** |
| 两端「同一规则、两处实现」的函数（相似度 > 0.85） | **2 个**，都是 `onTouchEvent` 的**分发外壳**（12 行，内部逻辑已共用）；重构前 4 个 |
| 业务规则（降级 / 重试 / 进度 / 历史 / 收藏 / 选剧）的重复实现 | **0 处**，全部在 `:core` 或 `:shared` |
| `:shared` 公开符号被两端同时使用的比例 | 45 / 67（67%） |
| 单元测试 | 401 例（core 382 + shared 19），全绿 |

一句话：**改一个公共问题只需要改一处**，这条验收标准已经成立；剩下的工作是「结构更清晰」而不是「消灭重复」。

## 二、重构前后

### 2.1 代码规模

| 模块 | 重构前 | 重构后 | 说明 |
| --- | --- | --- | --- |
| `:core`（纯 JVM） | 71 文件 / 16,928 行 | 82 文件 / 18,516 行 | 新增 11 个纯逻辑文件（选剧过滤、历史对账、快进合并、读数格式化…） |
| `:shared`（Android 公共层） | 不存在（逻辑混在 `app/data`、`app/architecture`、`app/compat`） | 46 文件 / 9,873 行 | 账号 / 会话 / 收藏 / 进度 / 封面 / 播放传输 / 弹幕 / 主题 / 兼容层 / 调试 |
| `:feature-tv` | 不存在（= `app` 的页面部分） | 43 文件 / 27,563 行 | 遥控器 + 焦点导航 + 1280×720 画布 |
| `:feature-phone` | 不存在 | 43 文件 / 16,998 行 | 触摸 + 竖屏 + 手势播放 |
| `:app`（壳） | 73 文件 / 36,256 行 | 2 文件 / 203 行 | `Application` + 启动路由 |
| 合计（main） | 53,184 行 | 73,153 行 | 增量 19,969 行 ≈ 手机端新建（17.0k）+ 公共层补的纯逻辑 |

行数**增加**了近 2 万行，这不是重复代码，是手机端从无到有。判断重复要看下面的同名相似度与公共层使用率，不能看总行数。

### 2.2 依赖方向

```
core（纯 JVM，零 android.*）← shared（Android 公共层）← feature-tv    ← app
                                                    ← feature-phone ←
```

- `feature-tv` 与 `feature-phone` **互不依赖**：手机端编译期看不到 TV 的任何 `View`，反之亦然。
- 这条规则由 Gradle 的模块依赖强制，不靠 review。要共享只能往下沉到 `:shared`。

## 三、差异矩阵

「归属」一列的含义：**公共层**＝两端必须一致、只该有一份；**平台层**＝真实差异，保留两份且允许各自演进；**配置层**＝差异用数据/策略表达，不写成分支。

### 3.1 输入与交互

| 文件 / 模块 | 手机 · 平板 | TV | 相同点 | 差异点 | 归属 |
| --- | --- | --- | --- | --- | --- |
| 输入源 | 触摸（`MotionEvent`） | 遥控器（`KeyEvent`）+ 少量触摸 | 都要处理「按下 / 移动 / 抬起 / 取消」 | TV 15 个文件碰 `KeyEvent`，手机 0 个 | 平台层 |
| 按键语义表 | 不使用 | `core/KeyMap.kt`：有哪些键、每个键能绑哪些动作、出厂绑定 | 表本身是**纯数据**，可单测 | 只有 TV 有「按键自定义」这回事 | 公共层（数据）+ 平台层（设置页 UI） |
| 手势播放 | `phone/ui/PhoneTouch.kt`：单击显隐 / 左右拖进度 / 上下滑亮度音量 / 长按倍速 | 无手势（方向键 seek） | 「拖进度」的落值规则共用 `core/SeekStep` | 手势种类、速度追踪、双击判定只有手机有 | 平台层 |
| 滑杆拖动 | `phone/ui/PhoneSettingControls.kt` | `tv/SettingSlider.kt`、`tv/player/DanmakuSlider.kt` | 按下不抢事件 / 越过 slop 且横向占优才算拖动 / 没拖动＝轻点 / 抬起清状态 | 手机多一个按下变暗（`alpha=.9`）与 `performClick()`；TV 多一条「轻点落在右侧读数上不落值」 | **公共层** `shared/ui/SliderDrag.kt`（本轮抽出） |
| 焦点导航 | 无焦点概念（`requestFocus` 1 个文件，仅输入框） | 22 个文件主动 `requestFocus`、7 个文件挂 `setOnFocusChangeListener` | — | 焦点链、焦点环、缩放动画、`nextFocusDown` 全是 TV 独有 | 平台层 |
| 遥控器按键分发 | 无 | `tv/MainActivityKeyMap.kt`（设置页那一栏）+ 各页 `onKeyDown` | 动作枚举共用 `core/PlayerKeyAction` | — | 平台层 |

### 3.2 页面与导航

| 文件 / 模块 | 手机 · 平板 | TV | 相同点 | 差异点 | 归属 |
| --- | --- | --- | --- | --- | --- |
| 页面容器 | 6 个 `Activity`（`PhoneMainActivity` / `Detail` / `Player` / `Search` / `Settings` / `Account`） | **1 个** `MainActivity` + 22 个 `MainActivity*.kt` 分片，用 `screen` 字符串切页 | 页面清单一致（首页 / 剧场 / 详情 / 播放 / 搜索 / 设置 / 账号） | TV 是「单 Activity + 状态机」，手机是「多 Activity + 系统返回栈」 | 平台层 |
| 返回逻辑 | 各 Activity `onBackPressed`（3 个文件） | `MainActivityNavigation.kt` 统一处理：播放页 → 详情 → 上一页 | 「播放页返回详情、详情返回来源」的**顺序**一致 | TV 要自己维护页面栈；手机用系统栈 | 平台层 |
| 页面栈恢复 | `Bundle`（7 个文件，系统自动重建） | 手动 `onSaveInstanceState` + `screen` 复原 | 都要在进程被杀后回到原页面 | 恢复的粒度不同 | 平台层 |
| 启动路由 | — | — | `app/LaunchActivity`：唯一 `LAUNCHER` / `LEANBACK_LAUNCHER`，`Theme.NoDisplay`，判形态后转发 | 判定读设置优先于自动探测 | **配置层** `shared/compat/DeviceForm.kt` |
| 转场 | `PlayerTheme`（`values-v28`）关掉窗口动画 | 无转场（页面切换是 `View` 换内容） | 都要求「进场不闪」 | 手机靠窗口主题，TV 靠不重建窗口 | 平台层 |

### 3.3 尺寸、安全区与主题

| 文件 / 模块 | 手机 · 平板 | TV | 相同点 | 差异点 | 归属 |
| --- | --- | --- | --- | --- | --- |
| 设计画布 | `phone/ui/PhoneTheme.kt`：竖屏 360×640 / 横屏 640×360，取 `min(宽/设计宽, 高/设计高)` | `tv/TvMetrics.kt`：1280×720，同样的 `min` 规则 | **同一条思路**：只按屏幕像素算，不读 `density`（`wm density` 改一档不会让版面变形） | **取像素的来源不同**：手机取整屏物理像素（`currentWindowMetrics` / `getRealMetrics`），TV 取 `resources.displayMetrics`（窗口可用区） | 平台层（**刻意不合并**，见 §7.2） |
| 安全区 / 沉浸式 | `phone/ui/PhoneWindow.kt`：状态栏透明、导航条让位（`tabBarInset`） | 无系统栏（电视全屏）；过扫描安全区**未启用**（试过 +24，观感变化，已回退） | — | 只有手机有系统栏 | 平台层 |
| 配色 | `phone/ui/PhoneStyle.kt` 读 `shared/ui/TvTheme` | `tv/TvStyle.kt` 读同一个 `TvTheme` | 20 套新拟态配色、语义令牌（base/light/dark/text/sub/focus/accent/danger）、派生规则**完全同一份** | 两端各自的「品牌强调色」取值不同 | **公共层** `shared/ui/TvTheme.kt` + `SoftPalette.kt` + `Soft.kt` |
| 字号 | `phoneSize()` 缩放 + 系统 `fontScale`（夹在 1.0–1.3） | `designTextSize()` 按画布缩放 | 都按画布比例算 | 手机额外尊重系统字体大小设置 | 平台层 |
| 动效 | 无焦点动画 | `TvStyle.focus()`：焦点缩放 + 时长，低配机由 `shared/compat/lowEndTv()` 关掉 | 低配判据只有一份（`lowEndTv`） | 只有 TV 有焦点动效 | 平台层 |

### 3.4 播放

| 文件 / 模块 | 手机 · 平板 | TV | 相同点 | 差异点 | 归属 |
| --- | --- | --- | --- | --- | --- |
| 播放器宿主 | `PhonePlayerActivity` 自己持有 `ExoPlayer` | `MainActivityPlayer` + `MainActivityPlayback` | 都用 Media3 1.4.1（被 minSdk 19 钉死） | TV 走 `shared/architecture/PlaybackController`（Flow 状态机）；手机仍直接读 ExoPlayer 回调 | 平台层（后续可收敛，见 §8） |
| 失败自愈 | `PhonePlaybackRecovery.kt` | `PlaybackDiagnostics.kt` + `MainActivityPlayback` | **决策完全同一份**：`core/PlaybackDegradation.kt`（4001/4003 先同档重建、4004/4005 才降档、每集最多降两档、绝不改用户设置） | 手机多「网络/源类失败 3/6/12 秒退避重试」与触控错误页；TV 多定时停止 | **公共层**（决策）+ 平台层（错误页与重试节奏） |

| 进度落盘 | 每 5 秒 + 退出 | 每 5 秒 + 退出 | `shared/data/ProgressStore`：一剧一文件 | — | **公共层** |
| 弹幕 | `PhonePlayerActivity` / `PhoneFeedView` | `MainActivityPlayer` | 同一个 `shared/media/DanmakuView` + `DanmakuLoader`；字号按各自画布比例注入 | 手机弹幕面板是底部抽屉，TV 是播放菜单里的一栏 | **公共层**（渲染）+ 平台层（面板） |

## 四、公共层对外 API

`:shared` 共 67 个顶层公开符号，其中 **45 个被两端同时使用**，13 个目前只有 TV 用（多为兼容层工具，手机暂时用不到），1 个只有手机用，8 个是 `:shared` 内部互相调用（对 feature 不可见）。

### 4.1 分组清单

| 包 | 主要 API | 用途 |

### 4.2 边界规则（由 Gradle 强制）

| 规则 | 强制方式 |
| --- | --- |
| `:core` 不允许出现 `android.*` | 它是 `kotlin("jvm")` 模块，import 到 Android 类直接编译失败 |
| `:shared` 不允许出现页面、版面令牌、`Activity` / `Fragment` | 约定 + review；`shared/build.gradle.kts` 的注释写明「这里不放任何页面」 |
| `feature-tv` 与 `feature-phone` 互不依赖 | `settings.gradle.kts` 里没有彼此的依赖，互相 import 编译失败 |
| `:app` 不允许有业务逻辑 | 目前只剩 2 个文件（`Application` + 启动路由），203 行 |
| 公共层不允许反向依赖平台 | `:shared` 的依赖列表里没有 `:feature-*`，加了会形成环，Gradle 直接报错 |

### 7.2 刻意保留的差异（不要「顺手合并」）

| 项 | 为什么不能合并 |
| --- | --- |
| 设计画布的像素来源 | TV 用 `resources.displayMetrics`（窗口可用区），手机用整屏物理像素（`currentWindowMetrics` / `getRealMetrics`）。手机的注释写明：用 `displayMetrics` 会随状态栏高度与 density 变化，同一块 2160×3840 屏只改 dpi 比例就从 6.00 掉到 5.66。把 TV 改成整屏像素会改变 TV 的 `designScale`，整套版面跟着变——这是**观感回归**，不是重构。 |
| 画布尺寸 | TV 1280×720，手机 360×640 / 640×360。曾经把手机画布换成 960×540 让版面放大 1.33×，用户第一反馈是「界面明显变大，完全不是我想要的效果」，已整体回退。要调可读性只能动字号。 |
| 页面容器模型 | TV 单 Activity + 状态机（遥控器不适合频繁起 Activity），手机多 Activity（系统返回栈、转场、`onSaveInstanceState` 都是现成的）。强行统一会同时得罪两端。 |
| 播放器宿主 | TV 走 `PlaybackController`（Flow 状态机，为「异步回调落到已失效剧集」这类问题建的），手机仍直接读 ExoPlayer 回调。收敛是**后续建议**（§8），不是本轮。 |

## 十、开发规范

### 10.1 判断一段代码该放哪一层

按顺序问三个问题，**第一个「是」就停**：

1. **它需要 `android.*` 吗？** 不需要 → `:core`（并且必须能写单测）。
2. **两端都要用、且规则必须一致吗？**（数据、会话、进度、策略、配色、兼容、诊断）
   → `:shared`。放进去之后，两端**不允许**再各写一份。
3. **它描述的是某一端的版面、输入方式或生命周期吗？** → 对应的 `:feature-*`。

判断「必须一致」的标准：**如果两端给出不同结果，用户会不会认为是 bug？**
会 → 公共层（例如「同一部剧的进度」「同一个作者的头像颜色」「同一个失败该不该重试」）。
不会 → 平台层（例如「按钮多高」「焦点怎么走」）。

### 10.2 改公共功能

```
1. 只改 :core 或 :shared 里的那一处
2. 如果它有单测 → 先让单测红，再改，再绿
3. 如果没有单测但逻辑是纯的 → 补一个（:core 或 :shared 的 src/test）
4. ./gradlew :app:assembleDebug :core:test :shared:testDebugUnitTest
5. 两端各回归一次（见 §9）
```

**不要**为了「先让这一端跑起来」在 feature 模块里复制一份公共实现。复制之后两端就会开始漂移，这正是这次重构要消灭的问题。

### 10.3 改平台功能

只改对应的 `feature-*`。如果发现需要动 `:shared` 的 API：

- 加参数 → 给默认值，避免另一端被迫修改；
- 改语义 → 先确认另一端也接受，否则加一个新函数、旧的标记废弃。

### 10.4 新增一个平台端（例如给平板做独立版面）

1. 新建 `:feature-tablet`，在 `settings.gradle.kts` 里 `include`，**只依赖 `:shared`**；
2. 在 `shared/compat/DeviceForm.kt` 的 `OPTIONS` / `pickerLabels` 里加一档（落盘值同时加）；
3. 在 `app/LaunchActivity.kt` 的 `targetFor()` 里加一条分支；
4. 在 `app/AndroidManifest.xml` 里声明新端的 Activity；
5. 版面令牌（画布尺寸、字号、间距）在**新模块内**定义，不要去改 `TvMetrics` / `PhoneTheme`；
6. 输入层按新端的输入方式实现（遥控器抄 `feature-tv` 的焦点链，触屏抄 `feature-phone` 的手势）；
7. 业务逻辑一行都不要新写——缺什么就往 `:shared` 补，并补单测。

### 10.5 禁止事项

| 禁止 | 原因 |
| --- | --- |
| 在 `:shared` / `:core` 里写 `if (isTV)` / `if (deviceForm == TV)` | 公共层一旦认识平台，平台就再也加不进来 |
| `feature-tv` 依赖 `feature-phone`（或反向） | 会让两端在编译期互相看见，边界立刻失效 |
| 在 `:app` 里写业务逻辑 | 壳层只做路由与装配 |
| 为「两端看起来一样」而合并版面代码 | 版面是两端最大的差异，合并等于牺牲其中一端的观感 |
| 改落盘格式（偏好 key、进度文件名、字段名） | 用户升级后会丢进度与收藏；要改必须写迁移 |

### 10.6 提交前检查

```bash
cd android
export JAVA_HOME=/opt/homebrew/Cellar/openjdk@17/17.0.20.1/libexec/openjdk.jdk/Contents/Home

./gradlew :app:assembleDebug          # 必须过
./gradlew :core:test :shared:testDebugUnitTest   # 401 例必须全绿
```

改到下面这些地方时，额外检查：

| 改动 | 额外检查 |
| --- | --- |
| 包名 / 类名 | `res/layout/*.xml` 里写死的自定义 View 类名、`AndroidManifest.xml`、`baseline-prof.txt`、`proguard-rules.pro`（编译期查不出，运行时才崩） |
| 资源 / 主题 | 两端各截一张图对比（TV 1280×720 画布，手机 360×640） |
| 播放相关 | 两端都要试「切集 / 断网 / 片尾 / 后台再回前台」 |
| 落盘相关 | 升级安装（不卸载）后进度与收藏仍在 |

## 十二、一句话维护说明

> 找业务规则去 `:core`（纯 Kotlin，能单测）或 `:shared`（要 Context 的）；
> 找版面、焦点、手势、生命周期去对应的 `:feature-*`；
> 两端对同一件事给出不同答案，就是 bug——修在公共层，不要修两次。
