## iOS 端从零落地（ios/，40 个 Swift 文件 / ~8.8k 行）

- 工程用 `ios/tools/gen_project.py` 生成 pbxproj（本机没有 xcodegen）。
  **踩坑**：对象表里不能带最外层花括号；PBXProject 的 mainGroup 必须是独立根组，
  不能把 HGTV 组自己塞进自己的 children。生成后 `xcodebuild -list` 能读即正确。
- 签名移植（SM3 / AesV3 / gorgon / helios / medusa）**一次对上** Android 的 12 组向量：
  `ios/tools/signer_oracle.swift`。移植时最容易错的是 `ushr`（逻辑右移）与 `Integer.reverse`。
- 设备身份**必须同时进 query 与签名器**（x-medusa 里编了 device_id）。顺序反了会回
  `110001`（播放）或 `200 + 0 字节`（搜索）。`values()` 里先铺 profile 再盖 identity。
- 播放接口按 device_id 计额度：本机注册号基本已被打满，**每次现造 15 位随机 id**，
  空响应就换号重试；否则所有片子都放不了。
- 平台的 MP4 是 **CENC AES-CTR**（encv + 逐样本 IV + spade_a）：
  AVFoundation 不认，必须整集取回 → 解析 stbl 样本表 → `encv` 换回 frma 原编码、
  `sinf` 改 `free` → 逐样本 AES-ECB 出 keystream 异或 → 落本地再播。
  验证方式：`ios/tools/decrypt_check.swift` 用 AVFoundation 读时长/轨道（实测 170.6s、1280×720、1 音轨）。
- 版面：360×640 画布；几何倍率取 1.25（不是 Android 的 1.6），字号按画布 1:1。
  再乘 1.6 会让内边距变成 28pt，是平板手感。
