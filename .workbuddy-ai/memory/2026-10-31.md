## 推荐页 ↔ 正式播放页「内容不能断」（收尾）

- 定位到进场那一下的停顿不是应用自身的活（`enter timing ui=16~40ms`），而是系统给播放页
  半透明窗口排的入场动画：逐帧改 alpha 时视频层必须退出 HWC 直通、退回 GPU 合成，
  实测一次 150~280ms 的整屏停顿。`PlayerTheme`（values-v28）加
  `android:windowAnimationStyle=@null` 之后，连续 17 次进场全部 ≤21ms（60fps 满帧）。
- 加了三条常驻读数（DEBUG 包）：`enter timing`（进场耗时）、`adopt begin …pos/state/items/underlay`
  （接手前的现场）、`player pause handoff=… pos=… items=…`（退出时交出去的是哪一集）。
- 实测退回推荐页位置连续递增（114810 → 127095 → 139370），同一部剧、`items=1 cur=0`、无重取地址。

## 推荐页 ↔ 播放页「内容不能断」：控制层的交接顺序

- 现象：播放器那一路本身是连续的（`adopt begin pos=4008` → `feed adopt pos=4008`，同集同秒），
  但退回去的一瞬会看到**标题 / 集号 / 「选集 全N集」跳一下**：播放页在 `onPause` 里
  就把推荐页的控制层还回去了，那一刻 `A.onResume` 还没跑，推荐页手上还是离开前那份数据。
- 修法（顺序，不是新增状态）：
  1. `PhoneSession` 记 `feedChromeHidden`（控制层现在是否真的收着），`restoreFeedChrome`
     只在收着的时候才放；新增 `ensureFeedChrome()`：计数归零 + 强制放。
  2. 播放页 `onPause` **不再**还控制层，只在 `onDestroy` 兜底（交接没走成时）。
  3. `PhoneFeedView.onShown()` 拆成 `resumeOnShown()` + 末尾 `ensureFeedChrome()`：
     接完这一路（集号 / 进度条已对齐）之后才亮控制层。
  4. 起播放页之前（`launchPlayer` / 片尾交接）先 `hideChromeForHandoff()`：播放页窗口是
     透明的，晚收几十毫秒会让本页「观看完整短剧」从它底板下透出来再被盖掉。
     只在 9.0+ 且这一路真的会借这块 Surface 时收。
- 验证：暂停在正片第 7 集返回 → `player pause handoff=true pos=4008 pwr=false` →
  `feed adopt episode=7 pos=4008`；dump 到推荐页「第7集 / 观看完整短剧 · 全43集」+ 体裁行 +
  底部 tab 齐全，位置没有回 0、没有 `feed play`（未重取）。

## 播放页：长按设置面板「点空白」后信息残留

- 现象：播放页长按中间弹播放设置，点面板外空白只收面板，标题 / 集号 / 「观看完整短剧」/
  进度条 / 返回箭头全留在画面上。
- 原因：`PhoneSheet` 的遮罩与「关闭」只 `dismiss()`；播放页的控制层是独立一层
  （`chromeVisible`），没人去收它。
- 修法：
  1. `PhoneSheet` 分出 `onUserDismiss`（只有「点空白 / 点关闭」才回调），
     `dismissByUser()` 先收面板再通知；程序性 `dismiss()`（换集、换清晰度、转屏）不变。
  2. 播放页 `onUserDismiss = { setChromeVisible(false) }` → 标题、集号、观看按钮、清屏、
     进度条、返回箭头、顶部读数一起隐藏（与电视端「开菜单收 HUD」同一语义）。
  3. 横屏：左侧 2/3 只读层的点击、右抽屉的「关闭」同样连控制层一起收。
  4. 「播放界面自动消失」到点也一并收控制层（电视端 `scheduleOverlayAutoHide` 同一条）。
  5. 推荐信息流里的同名面板**不接**：那边竖屏规范是「点屏幕=播放/暂停、信息常显」，
     收了就没有回来的手势（`PhoneVideoPage` 的信息栏在信息流里没有独立开关）。
