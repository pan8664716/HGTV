# 2026-11-06

## 修复：已预约的剧，简介页仍显示「预约」（TV + Phone）

三条原因叠加，缺一条都修不干净：

1. **手机端从来没把预约发到云端**。`PhoneDetailActivity.onPrimary` 只写本机
   `library.setReserved`，`repository.accountReserve` 在手机模块里一次都没被调用过
   （只有 `PhoneAccountSync.reservationsDeleted` 里的取消）。所以手机上预约完，
   平台侧根本没有这条记录，电视端拿到 `online_subscribed=0`，显示「预约」是必然的。
   → 新增 `PhoneAccountSync.reserve(context, series, reserved, onNeedSignIn, onDone)`，
   与 `favorite` 同一条路：本机先改、账号缓存 `applyReserve` 同步、云端随后推、失败回滚。

2. **详情页用接口值覆盖/压过本地状态**。
   - TV：`openDetail` 里 `if(result.upcoming) library.setReserved(id, result.reserved)`
     无条件覆盖本地，紧接着 `showDetail` 读本地 → 刚预约的那一次被回包翻回 false。
   - Phone：`bindDetail` 只用 `d.reserved`，完全不看本地。
   → 统一规则：**本地「最后已知」优先**，接口值只在 `!reservedKnown(id)` 时落一份。
   TV 改覆盖条件；Phone 加 `reservedState(d)` / `paintReserve()`。
   TV `reserveSeries` 增加 `current` 参数，切换基于按钮上显示的状态，不再重读本地表。

3. **`online_subscribed` 解析太窄**。`optBoolean` 只认布尔与数字，平台若回字符串
   `"1"` 会被当成缺字段落回 false。→ `ContentRepository` 加 `JSONObject.flag(key)`，
   接住 Boolean / Number / "1"|"true"|"yes"。

未登录语义两端统一：提示「登录后才可以添加预约」，不改按钮状态。

编译：`./gradlew :app:assembleDebug` 通过（JDK 17）。未改版本号、未推送。

## 崩溃分析（只分析，未改代码）：4.4.4 上 NoClassDefFoundError: T1/r

线上 1.3.2 / JmGO_T6 / Android 4.4.4 的崩溃，用 `app/build/outputs/mapping/release/mapping.txt`
把栈全部还原后定位到：

- `T1/r` = `okhttp3.internal.platform.Platform`，`S0/J0.a` = `HgtvTls.configure`
- 链路：详情页点击 → 账号面板 → `QrLogin.<init>`（`HgtvTls.configure(OkHttpClient.Builder())`）

**根因**：OkHttp 4.12 的 `AndroidPlatform.isSupported` 在 `<clinit>` 里是
`check(SDK_INT >= 21)`，SDK 19 直接抛 `IllegalStateException("Expected Android API level 21+ but was 19")`。
`Platform.findPlatform()` 的 Android 分支**没有任何 try/catch**，异常穿出 `<clinit>` →
`Platform` 被 Dalvik 标成 CLASS_ERROR → 此后每次访问都是 `NoClassDefFoundError: T1/r`。

第一次失败发生在 `HgtvApplication.startTlsWarmup()` 的后台线程里，被 `runCatching` 吞掉，
所以线上只看到第二次访问的 NoClassDefFoundError。

**回归来源**：提交 `5140a0e`（tag 1.3.1.1）把兼容层包进了
`if (Build.VERSION.SDK_INT >= 21)`。之前 `OkHttpPlatformCompat.installAndroidFallback()`
无条件执行，靠把 `java.vm.name` 改成非 Dalvik 让 `isAndroid()` 为 false，绕开 Android 分支；
加了门槛之后 4.4/4.4W 全部走 Android 分支 → 必崩。

排除项：不是 multidex（APK 里只有 `classes.dex` 一个 dex），也不是 R8 裁掉该类
（dex 里 `LT1/r;` 定义完整）。

影响面：minSdk 19，所以所有 4.4.x 设备的网络全废，且任何一个没被 catch 的
`HgtvTls.configure` 调用点（播放、封面、心跳、扫码登录…）都会崩。
