
## 设备身份：换设备的真正决定因素（实测结论）

**服务端认设备靠的是 Cookie（`install_id` / `sessionid`）+ `X-Tt-Token`，不是 cdid。**

隔离探针（无会话的仓库，拦截器无身份可补）结论：
- 决定换设备：`cdid` / `openudid` / `clientudid`、`device_type`（机型）
- 不决定：`device_brand`、`resolution`、`dpi`、`os_version`、`os_api`、`rom_version`
- 残留的旧身份 / 旧 Cookie **不会**粘住（探针里四种组合都拿到新 device_id）

真机上完全相反，原因是 `SessionInterceptor` 把 `log.snssdk.com` 也算作会话 host，
会给注册请求补 `Cookie: install_id=…; sessionid=…` 与 `X-Tt-Token`。于是：
```
wire cdid=caf33c91-…(全新)  id=null
resp {"device_id":656883219175530,"new_user":0}   ← 换 cdid 没用
```
修复：`registerDevice(withIdentity=false)` 打 `X-HGTV-Anonymous` 头，
`SessionInterceptor` 见到它就整条跳过身份补齐（并摘掉这个头）。修完同一台机、同一账号：
```
resp {"device_id":1554084714260939,"new_user":1}   ← 真的换了设备
```
账号未受影响（推荐 / 播放 / model 接口正常，无 session_expired）。

单测：`core/src/test/.../SessionInterceptorTest.kt`（2 条：普通注册带 Cookie、匿名注册一个身份都不带）。

**推论**：`upgradeIdentitySchemeIfNeeded` 之前"执行了但无效"，就是因为它走的是同一条被补 Cookie 的注册；
修好之后它会**真的换设备**——老版本升级的用户会一次性换掉 device_id，这是产品取舍，不是 bug。

## 撤掉「升级时强制换设备」

`Library.upgradeIdentitySchemeIfNeeded` / `markIdentityScheme` / `IDENTITY_SCHEME` / 镜像键
`device-identity-scheme` 全部删除。老版本（种子由系统标识符派生）升级上来时**档案原样继续用**，
不再换身份。

原因：平台认设备靠 `install_id` / `sessionid` 这串 Cookie，cdid 换不换无所谓；强制换一次
只会让账号在平台上被当成陌生机器，收益为零。

现在「换设备」只剩一条路：`MainActivity.healDeviceIdentity`（TV 端，服务端明确不认这份身份）。

## 搜索自愈顺序 + 手机端接入（2026-11-03）

**① 先换设备重搜，再降级官网。** 顺序原先反了：`ContentRepository.search` 先 catch 住
`DeviceNotRegisteredException` 去走官网搜索，成功就 return，异常传不到界面层，
电视端 `healDeviceIdentity` 成了死代码。

现在 `search()` 里是 `while(true)`：第一次被拒 → 调 `ContentRepository.deviceHeal` 钩子 →
成功就 `continue` 重搜一次 → 还失败才走官网兜底。`healed` 保证一次搜索只换一次设备。

**② 手机端接同一条自愈。** 判定与预算抽到 `:shared` 的 `DeviceHealer`（2 次/进程、间隔 20s、
只处理"新的一次被拒"），电视端 `healDeviceIdentity` 改成调它，手机端在
`handlePlayerFailure` 里加了一条：`PlaybackFailures.deviceRejected(error)` 命中就先
`DeviceHealer.heal` 再 `play()`。

接线点：`AppRuntime.installDeviceHeal`（进程级静态钩子 `ContentRepository.deviceHeal`），
启动日志 `I/HGTV: Device heal hook installed` 可验证。

同时删掉了 `ListPage` 里那条旧的 `healDeviceIdentity("搜索被拒")`——核心已经处理，
再换一次只会连烧两份身份。

单测：`SearchDeviceHealTest`（4 条：先自愈再重搜 / 自愈失败才降级 / 一次搜索只换一次 /
官网搜索不触发）。`:core` 共 69 条全绿。

真机验证：`device_id` 改成随机 15 位后 App 搜索**依然正常返回**（服务端对随机号放行），
所以没能造出"被拒"现场——这条路径目前只有单测覆盖，真实现场要等风控真拒。

## 自愈层抽成公共（同一份，两端只写「成功之后做什么」）

`DeviceHealer` 现在是唯一入口 `healAsync(library, repository, reason, onResult)`：
判定 → 预算（2 次/进程、间隔 20s、同一次拒绝只处置一次）→ 单线程后台注册 →
回主线程回调。`heal` 改成 `internal`（只给搜索钩子和工作线程），`wouldHeal` 私有。

- 电视：`healDeviceIdentity` = `healAsync { 成功 → DebugEnv.invalidate + retry }`
- 手机：`handlePlayerFailure` = `healAsync { 成功 → clearPlaybackError + play(index, at) }`
- 判定别名 `deviceRejectionOf` 改为直接转发 `PlaybackFailures.deviceRejected`

真机观察：测试期间设备身份确实被换了一次（seed `20b232b1` → `d364784a`，
device_id `1554084714260939` → `2803129928124490`），候选档案已转正、无残留 pending，
播放与搜索正常。说明自愈链路在真机上能跑通；但也要注意**一次偶发空响应就可能触发换设备**
（预算只限制了频率，没有限制误判）。

### 更正：那次换设备是「设置 → 清空应用缓存」，不是自愈误触发

上面记的「一次偶发空响应就可能触发换设备」**作废**。真实原因：手动执行了设置里的
「清空应用缓存」（`MainActivityReset` / `PhoneSettingsActivity` → `LocalReset.wipe`），
它把 `shared_prefs`、`files`、`cache`、`Android/data/<包名>` 与 `/sdcard/.hgtv` 一起删掉，
下次启动没有档案 → 按新随机种子派生 → 注册一台新设备。这是**设计如此**。

因此「会换设备」的完整清单是两条：
1. 服务端明确不认这份身份 → `DeviceHealer` 自愈（电视搜索/播放、手机播放）
2. 设置 → 清空应用缓存（`LocalReset.wipe`，删档后重建，等同换设备）

（「全新安装 / 系统清除数据 / 卸载重装且镜像也没了」属于「新建」，用户视角同样是新设备号。）

### 为什么第一次改 device_id 没触发（重要）

之前改 `registered-device-id` 搜索照样出结果，因为**当时是登录状态**：
`ContentRepository.deviceProfile()` 的合并顺序是
`VendorConstants.device → registerProfile → deviceIdentity → credentials.device`，
**账号档案（`account-device`）压在最上层**，请求里带的 device_id 是它，不是 `registered-device-id`。
所以调试设备身份时，登录状态下要改 `account-device` 里的 `device_id`（或先退出登录）。

## 修：动作按钮按完后面板关了、控制条常亮、左右键失效

根因是 `panel` 这个「方向键交给浮层焦点链」的开关**只置真不复位**：

- `showPlaybackMenu` 置 `panel=true`；`dismissPlaybackMenu` 只摘控件，没改回来。
- `dispatchKeyEvent` 里 `if(!panel) playerKeyAction(key)...` → 方向键 / 确定键全被吞。
- `hudShown()` 要求 `!panel` → `scheduleOverlayAutoHide` 排不上 → 控制条与进度条永久常亮。
- 返回键在 `!panel` 判据之前单独处理，所以「按返回才好使」。

修法：`dismissPlaybackMenu` 末尾 `panel=playError`（出错页的按钮要能被焦点选中，
那一页保留 true，其余一律放开）；`hidePlaybackOverlay` 在 `dismissPlaybackMenu()` 之后
再显式 `panel=false`；`detachPlayerSurface` 补一次归零。

**教训**：这类「一个布尔开关同时管焦点路由和常显判据」的字段，置真点与复位点必须成对，
且复位点要覆盖所有收起路径（菜单键 / 返回 / 自动消失 / 点动作 / 离开页面）。
