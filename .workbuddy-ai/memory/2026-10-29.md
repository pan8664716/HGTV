## 播放失败重试 / 降级逻辑审核（只审不改）

审了 `core/PlaybackDegradation.kt`、`MainActivityPlayback.kt`（playerFailure / replayWithPlan /
recoverQueuedCurrent / resetBudgetsForManualRetry）、`PlaybackDiagnostics.kt`（两条看门狗 /
recoverFormalPicture）、`MainActivityPlayer.kt`（playEpisode / applyDecoderMode）、
`core/Watching.kt`（RecoveryBudget）、`data/PlaybackCapability.kt`。

确认的主要缺口（按优先级）：

1. 音频故障没有恢复路径：`decide()` 对 AUDIO 直接 null，`limitOf(AUDIO)=0`；
   且错误页两颗按钮（切换为软解 / 换到 xP）只看 `playbackDecoderMode`，不看媒体类型 → 对音频无效。
2. 队列项（下一集）的连接类故障在「未到片尾」时被归因到**当前集**：
   `failingEpisode` 用 `queuedNearEnd` 判定，会 forgetStream 当前集、重放当前集。
3. 播到一半进入 BUFFERING 无限转圈没有任何看门狗覆盖（起播看门狗首帧后已撤，
   停帧看门狗要求 STATE_READY）。
4. 起播看门狗 `playbackWatchdogAt` 在用户暂停时不重置 → 暂停 >90s 后恢复播放立即误判 stall_buffer。
5. 看门狗 tick(15s) == 阈值(15s)，最坏 30s 才动手。
6. 错误页 → 返回前台走 `playEpisode(recovering=false)` → 预算全量归还，「每集有界」不成立。
7. 手动重试三份额度口径不一致：`requestPlayback` 只还 session 那一份；
   `onManualRetry()` 拒绝归还时 `resetBudgetsForManualRetry` 仍重置其余三份。
8. 5xxx（AudioTrack 初始化 / 写入失败）既不重试也不降级，直接死路。

结构性问题：六套预算（SessionPlaybackPolicy / RecoveryBudget / formalPictureRecoveries /
queuedRecoveries / streamRetriedFor / autoNextFailures）分散三处、五种重置条件，
`decide()` 用可变字段 `manualHint` 当「为什么放弃」的返回值。

## 架构与性能评审（只审不改）

产出 `docs/架构与性能评审.md`。全量读 57,032 行 Kotlin + Gradle + CI 配置。

实测确认的两条：

1. `.github/workflows/release.yml` 的「校验元数据能被客户端解析」跑
   `:core:test --tests com.hgtv.star.core.AppUpdatesTest`，而 `AppUpdates` 全仓已不存在
   → 实测 `BUILD FAILED: No tests found for given includes`。发版流水线是断的。
2. `data/PlaybackTransport.kt:69` 与 `:78` 重复 `addInterceptor(SessionInterceptor())`
   → 播放链路每个响应 `peekBody(32KB)` 跑两遍，在首帧关键路径上。

评审主结论：工程质量本身很高（基线 profile、首块 512KB、索引落盘、R8 剥日志、279 单测），
但复杂度已超出单体 Activity 上限——`MainActivity` 家族 23 文件 15,384 行、297 个可写字段、
七套手工"代际号"（generation / playbackSession / watchdogSession / failureHandledSession /
danmakuToken / accountToken / recommendToken）、22 个线程池、0 协程、app 层 0 测试。

其他重点：API<22 跳过证书链校验（但内置 G2 根已备好，可改单锚）；会话凭证明文写
`/sdcard/.hgtv/`（targetSdk 29 + requestLegacyExternalStorage）；播放进度每 5s 把 200 条历史
全量序列化 + SharedPreferences 整文件 commit（约 288MB/小时写入）；无 onSaveInstanceState；
无 WAKE_LOCK/WifiLock；ExoPlayer 2.19.1 / OkHttp 3.12.13 均 EOL；无字幕/音轨选择。
