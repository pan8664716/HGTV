## Frida 17 三个必须记住的坑

1. Python `Session.create_script()` **不注入 Java 桥**（`typeof Java === 'undefined'`，`require` 也没有），
   只有 `frida` CLI 会注入 → runner 必须走 CLI（`frida -U -l x.js -q -t N --no-auto-reload`）。
2. spawn 时默认 ClassLoader 是系统 webview，`Java.use` 全报 ClassNotFoundException →
   先 `Java.enumerateClassLoaders()` 找到能 `loadClass` App 类的 loader，设 `Java.classFactory.loader`。
3. **不要主动调用 native 签名函数**（metasec），早期 `re/frida_call_security*.js` 导致
   `libmetasec_ml.so` SIGSEGV；只做被动 hook。attach 空闲 App 抓不到流量，请求集中在启动阶段，用 spawn。

另：WorkBuddy 的 `grep` shim 在管道里返回空，bash 里请用 `/usr/bin/grep`。

### IR 能否直接翻译成算法（17:50 分析）

结论：**能翻译，但得到的是 7 万行汇编级代码，不是算法。**
`MedusaIRStats`/`MedusaDisasm`（`sign/ir_stats.go` + `cmd/medusa-ir`）显示：
- coreIR 71956 + extensionIR 4773 = 76729 条
- 高频：add32 9583 / ldr 9523 / ldrsw 8509 / xor64 7860 / str 4810 /
  strw 4578 / add64 3946 / ror32 3280 / or64 2546
- 入口 `0xa6d20` 是典型函数序言：`add_imm sp, sp, #-0xc98`、`str x30, [sp, #0xc98]`

即这是编译器生成的 ARM64 级语义 IR，`medusaCore` 是 71K 条指令的混淆程序，
不是单个哈希函数。直接翻译 → 约 7 万行 `r[5] = r[4] + 8` 式代码；
真正的「算法还原」需要反编译/符号执行/模式识别，属逆向工程，不保证成功。

建议：保持 VM（已验证逐字节一致）。若目标是减体积，优先考虑 IR 压缩/分片，
而不是翻译成源码。

## medusa 去掉 VM，改成纯算法（22:40）

外部给的 `x_medusa.go`（无 VM 版）证明 core 段只有 3 个算法族，不是 71K 条 IR：

- selector ∈ {0,3,6,9,12,15} → **mix32**（SHA-256 变体：8 lane、100 轮、timestamp 参与旋转）
- selector ∈ {2,5,8,11,14} → **word32**（MD5 变体：64 轮 + 自定义置换/常量旋转）
- selector ∈ {1,4,7,10,13} → **table64**（宽轨迹查表，AES 风格，5 张 8×256 表）

对拍结果（Go 侧 VM 为基准）：

- core 384 组（16 selector × 6 个 ts 含 0 / 0xFFFFFFFF × 4 输入）**逐字节一致**
- extension 201 组（长度 0..200）**逐字节一致**
- 整条 header 64 组 **逐字节一致**（1184 字符）
- 性能：VM 1.085 ms/core（M 系 Mac），算法 0.001 ms/core，约 **1000×**

移植到 Kotlin 时踩到的两个坑（**不是**算法本身）：

1. 附件把 `FKD`/`PD` 从 CDID 用 CRC32 推，我们是存值。直接换会导致环境串 JSON 不同 → header 不同。
   移植只取 `medusaCore` / `medusaExtension` 两个函数，其余保持原样。
2. 附件 field 9 写死 `0x04090900`（7.1.1.32）；我们是 7.4.3.32，必须是 `0x040A0300`。

落地：

- 新增 `MedusaAlgorithm.kt`（三族 + extension）、`MedusaAlgorithmTables.kt`（常量表由 Go 机械生成）
- 删除 `MedusaVm.kt` / `MedusaProgram.kt` / `medusa_program.z`（486948B）、`MedusaCache` 预热
- Go 侧保留 VM 作 oracle，新增 `cmd/medusa-dump`（整链路向量）、`cmd/medusa-core-dump`
  （core/extension 向量，同时写 /tmp/core.txt 供 JVM 侧读）、`cmd/medusa-bench`
- 产物 `outputs/HGTV_1.3.6.2_debug_nomv.apk`（APK 体积基本不变：资源 -487KB、dex +50KB）

**32 位机器不再是问题**：原来的「7 万条 IR 解释执行」估算 50–300 ms 已经不成立。

  兜底保证每秒至少落地一次（也顺带释放任何卡住的过渡）。
