## 设置页顶部留白收紧（Phone）

- 现象：四个大选项（页签网格）上方空白过大。
- 根因：`scroller` 的 `topMargin = status + dp(52)`（1080P 上 156px），而标题栏实际高度只有
  `status + dp(6) + 一行标题 + dp(8)`（约 76px），两者间空出 80 余像素；再加 container 顶部 `dp(8)`。
- 改法：`topMargin = status + dp(30)`、container 顶部内边距 `dp(8) → dp(2)`。
  标题栏本身（padding / 字号 / 位置）一个字没动。
- `:app:assembleDebug` 通过。

## 播放页退出全屏后方向无视系统「自动旋转」（Phone）

- 现象：全屏（横屏）退出后，播放页会跟着手机物理方向自动横/竖切换，系统自动旋转关着也一样。
- 根因：`PhonePlayerActivity.exitFullscreen()` 1.2 秒后设的是
  `SCREEN_ORIENTATION_FULL_SENSOR` —— 完全由传感器决定，**无视自动旋转开关**；
  且这个方向一直挂到 Activity 销毁，所以「进过一次全屏」之后整个播放会话都跟着转。
- 改法：改成 `SCREEN_ORIENTATION_USER`（用户偏好方向，遵守自动旋转）。
  全屏按钮主动锁 LANDSCAPE 的行为不变。
- `:app:assembleDebug` 通过。

## 选集网格左右翻页改成跟手动画（Phone）

- 原来：`ACTION_UP` 时判 `|dx| > 48dp` 直接 `jump()` —— 松手瞬间换一块内容，没有拖动反馈。
- 现在（`PhoneEpisodeGrid`）：
  - 起手阈值 48dp → 12dp，手指一动就接住；
  - `ACTION_MOVE` 里 `translationX` 跟手（阻尼 0.62、上限 0.85 屏；到头那一侧 0.12）；
  - 松手按位移（22% 屏宽）或速度（0.55 px/ms）结算：滑出 150ms → 换页 → 反向滑入 170ms；
  - 点分页芯片也改成「新页从翻页方向滑入 180ms」；
  - 动画中再按下会立刻取消旧动画，连滑不卡。
- **平移目标只限 `gridScroll`**（网格那一块）：上面的「第 A—B 集」与分页芯片行保持不动，
  它们是导航，跟着翻会分不清在拖什么。
- 注意：`translationX` 靠父容器 `clipChildren`（默认 true）裁剪出滑动观感，别改成 false。
- 卡顿处理：拖动/动画期间给 `gridScroll` 挂 `LAYER_TYPE_HARDWARE`（`beginDragLayer`），
  结束立刻摘掉（`endDragLayer`）。一页最多 100 个格子，逐帧重绘 + 视频解码 + 弹幕会让低端机掉帧；
  硬件层下平移只改纹理矩阵。**不要**长期挂着（占一块与网格等大的显存）。

## 竖屏 ↔ 全屏加过渡动画（Phone）

- 现象：点全屏时画面「啪」一下换掉。根因是播放页声明了 `configChanges=orientation`，
  转屏不重建 Activity，系统也就没有窗口转场。
- 改法：`applyMode()` 末尾调 `animateModeEnter(新形态那一层)`——淡入 + 从 97% 放到原尺寸，
  220ms、DecelerateInterpolator（常量 `MODE_TRANSITION_MS`）。
- 缩放只给 3%：那一层里是 `PlayerView`（SurfaceView），放大倍数大会露黑边 / 闪。
  真正的过渡感靠淡入。若以后要更明显，得改成抓帧做过渡层（PixelCopy），成本高。 

## 播放页方向改为跟随系统「自动旋转」开关（Phone）

- 需求（覆盖了当天早些时候「完全手动」的要求）：正式播放页竖/横都跟系统自动旋转走。
- `autoRotateEnabled()` 读 `Settings.System.ACCELEROMETER_ROTATION`。
- 进入播放页：`SCREEN_ORIENTATION_USER`（自动旋转开→跟随传感器；关→停在进入时方向）。
- 点全屏：先锁 `LANDSCAPE`，**自动旋转开着时 1.2 秒后设 `USER`**（给用户时间把手机转横；

- 退出全屏：锁 `PORTRAIT`，1.2 秒后设 `USER`（开→可再自动进全屏；关→停在竖屏）。
- `onConfigurationChanged` 里 `landscapeMode = nowLandscape` + `applyMode()` 就是自动切换的执行点，
  过渡动画沿用 `animateModeEnter`。
- `:app:assembleDebug` 通过。

## 顶部下拉不再误触发换集（Phone）

- 现象：播放页从顶部下拉想拉通知栏，结果画面被「上一集」切走。
- 根因：`PhoneTouch` 的触摸层整屏铺满，`ACTION_DOWN` 一旦被接住，后续 MOVE 全归它，
  纵向手势直接进 `VERTICAL`（向下 = 上一集）。
- 改法（两层）：
  1. `TOP_GUARD_DP = 16`：`ACTION_DOWN` 落在屏幕最顶部这一条时直接 `return false`，不接手势；
  2. `TOP_PULL_GUARD_DP = 64`：从顶部一带**向下**拉不进入 `VERTICAL`（部分 ROM 的下拉区更深，
     事件已被接住时至少不换集）。点击 / 长按 / 横滑不受影响。
- `:app:assembleDebug` 通过。

## 退出全屏后竖屏残留一块画面（Phone）

- 现象：横屏播放正常，按返回退出全屏后，竖屏视频区域下部残留一条旧画面。
- 根因：两个 `PlayerView` 都开了 `setKeepContentOnPlayerReset(true)`。横屏时竖屏层被解绑
  但保留了**横屏尺寸**的最后一帧；回竖屏后 Surface 尺寸变化，旧 buffer 只被新帧盖住一部分。
- 改法：
  1. 进横屏前先 `setKeepContentOnPlayerReset(false)` 再解绑竖屏层；
  2. 回竖屏时对横屏层同样先关再解绑（避免它的 Surface 带旧帧留在窗口里）；
  3. `rebuildPortraitSurface()`：回竖屏后解绑再挂一次播放器，强制重建 Surface，
     600ms 后恢复 `keepContent`（换清晰度 / 连播仍要保留帧）；
  4. `applyVideoScale()` 补一次 150ms 延迟调用，避免按横屏尺寸算缩放。
- `:app:assembleDebug` 通过。

## 长按被当成点击（Phone）

- 现象：长按卡片不弹菜单，松手反而跳进详情页 —— 长按**没有被消费**，抬手又走了一遍 click。
- 两处修复：
  1. `PhonePosterCard.setOnLongClickListener` **始终返回 true**（原来 handler 为空时返回 false，
     View 就把这次长按当作未消费，抬手触发 click）。
  2. `PhonePosterFeed.onLongPress` 加自定义 setter：赋值时把**已经绑好的卡片**一起更新。
     页面可能在 `load()`（缓存先铺）之后才挂回调，那批卡片的 handler 会一直是 null。
- `PhoneCardMenu.show` 的 Activity 查找改成沿 `ContextWrapper` 链向上找（不再只 `as? Activity`）。

## 长按 handler 为 null（Phone，真机日志确认）

- 真机 `adb logcat -s HGTV-CARD` 实测输出：`long press ignored: item=<id> handler=false` ——
  长按**确实到达卡片**，只是卡片上的 `onLongPress` 是 null。**不是遮罩问题**。
- 修法：`PhonePosterCard` 新增 `longPressResolver`，`PosterCell.bind` 里设为
  `{ this@PhonePosterFeed.onLongPress }`；长按触发那一刻**现取**宿主回调，
  不再依赖绑定时抄的那一份。配合 `PhonePosterFeed.onLongPress` 的 setter 刷新，
  两条时序都覆盖。
- 长按监听始终返回 true（消费），避免松手退化成点击。

## 长按菜单里点收藏/稍后看会整页刷新（Phone）

- 根因：`PhoneCardMenu.dispatch` 末尾统一 `onChanged()`，各页面传的是 `render()` / `selectBoard()`
  ——整页重建，屏幕闪一下、滚动位置被顶走。
- 改法：`show()` 增加 `onItemChanged`（默认 = onChanged）。dispatch 里只有
  **收藏 / 稍后看**（纯状态改动）走它，**删除记录 / 从热播榜隐藏**（改变列表成员）仍走 `onChanged`。
- 各页面：`feed.refreshItems()`（新增，`adapter.notifyDataSetChanged()`）用于轻量刷新；
  榜单页 / 我的页 / 搜索页都已接上。

## 「不在热播榜中显示」也会整页刷新（Phone）

- 上一条把收藏 / 稍后看改走 `onItemChanged` 后，用户指出**隐藏**这一项仍在整页重取。
- 根因：`HIDE_FROM_HOT` 走的是 `onChanged`（榜单页 = `selectBoard()` 清空列表重新请求）。
  设计初衷是「列表成员变了要重载」，但被隐藏的那部本来就会被
  `CatalogFilter.visible(page, library.hidden())` 过滤掉，**重取是多余的**。
- 改法：
  - `PhonePosterFeed.removeItem(id)`：从内存 `items` 摘掉一项，`notifyItemRemoved`
    + 对后面的项 `notifyItemRangeChanged`（名次角标按位置算，不重绑会留旧名次）。
  - `PhoneCardMenu.show()` 新增 `onItemRemoved: ((String) -> Unit)?`；
    `HIDE_FROM_HOT` 置 `itemOnly = true` 且带 `removedId`，
    派发优先级：`onItemRemoved` > `onItemChanged` > `onChanged`。
  - 榜单页接 `onItemRemoved = { feed.removeItem(it) }`。
  - 顺手修掉一个旧 bug：书库未就绪时 `loadAsync` 重试调 `show(...)` 只传了前 5 个参数，
    重试弹出的菜单会丢掉 `onItemChanged`（点收藏又整页重铺）。现在全参转发。
- 删除历史仍走 `onChanged`：我的页历史栏要重算「已看完 / 未看完」计数，不能只摘一行。

## TV 弹窗关闭「屏幕闪一下」

- 现象：TV 端弹窗弹出后，点任何按钮（含「取消」）整屏闪一下，焦点其实没变。
- 根因：`TvDialog.show()` 给窗口设了 `setDimAmount(.66f)`（FLAG_DIM_BEHIND 压暗整屏），
  而 `Dialog.dismiss()` 是**瞬间移除窗口**——面板和压暗层在同一帧消失，
  整屏亮度从 34% 一步跳到 100%。焦点关闭后还回 anchor，所以读起来就是「无缘无故闪一下」。
  **不是页面重建**：设置页 / 卡片菜单的动作都是就地改文字，不调 `base()`。
- 改法（`TvDialog.dismiss()`）：先按 `EXIT_FADE_MS = 120ms` 把
  `WindowManager.LayoutParams.alpha` 与 `dimAmount` 一起降到 0，再真正 dismiss。
  - 必须动 **LayoutParams.alpha**（整个窗口含背景板），不能用 `body.alpha`：
    面板底板是窗口背景，`View.alpha` 只淡内容，底板会留在原处。
  - 每帧现取一份 LayoutParams 再写回（`window.attributes = attrs`），
    直接改字段在部分 ROM 上下发不到 WindowManager。
  - `closing` 标志挡住淡出期间重复点按。
- 返回键：`Dialog` 自己处理 BACK 走的是 `cancel()` → `Dialog.dismiss()`，绕开我们的淡出。
  在 `setOnKeyListener` 里吞掉 BACK（DOWN 时调 `dismiss()`，UP 也返回 true），
  否则按返回关弹窗还是会闪。
- 没能真机复现：TV 盒子（192.168.31.121:5555）当前不在线，只有手机连得上。

## 「全屏顶部有黑雾」（TV + 手机同一类问题）

- 现象：用户反馈全屏画面顶部有一层暗带，渐变很缓，亮场里对比才看得出。
- 根因：**顶部压暗渐变在「没有内容」时仍然存在**。
  - TV：`MainActivityPlayer.kt` 的 `info`（96dp 高、整宽、`0x80000000 → 透明` 的竖向渐变，
    给白字垫底）被 `layer.addView(..., -1, dp(96), Gravity.TOP)` 贴顶。
    `syncPlaybackInfo()` 原来只判 `screen=="player"` 就 `VISIBLE`——而「播放显示」四项
    **默认全关**，于是播放页上这一行常驻但空着，底色照画：画面顶部平白多一条暗带。
  - 手机：`PhoneVideoPage.topShade`（110dp、`topScrim(130)`）跟着 `setChromeVisible` 开关，
    但这一页顶部什么都没有（竖屏的「播放显示」是**兄弟层** `portraitTop`，不在页里），
    推荐页更是整页无顶部内容 → 同样是空压暗。
- 改法：压暗层只在「真的有字」时存在。
  - TV：`syncPlaybackInfo()` 先算四项显隐，再 `bar.visibility = if (shown && anyItem) VISIBLE else GONE`。
  - 手机：`PhoneVideoPage.setTopScrimVisible(Boolean)` 接管 `topShade`，默认 GONE，
    与 `setChromeVisible` 解耦；`PhonePlayerActivity.syncPlayInfo()` 用同一份
    `visible`（= 这一行真有字）驱动它。推荐页从不调用 → 永远没有这条暗带。
- 结论：这类「压暗层」一定要和**它服务的那个内容**同生共死，不能和「页面/控制层」绑在一起。

## 手机端「第三集播完进不了第四集 + 退不回去」

两个独立缺陷叠在一起，症状像一条：

1. **换集取地址失败 = 死路**
   `PhonePlayerActivity.play()` 里 `releasePlayer()` 在取地址**之前**，随后
   `stream()` / `prepare()` 失败时只往 `landInfoLeft` 写一句「第 N 集 · 准备失败」就 `return`。
   而那一行**只在横屏存在**，竖屏什么都看不到；播放器已经被拆，页面停在黑屏上。
   用户读到的「没准备好」就是这句。
   改法：新增 `onEpisodeSourceMissing()` —— 先自动重试两次（3s / 6s，用 `hint` + `hintToken`
   那套提示，重试前收掉），仍不行就 `failureStage = PlaybackStage.PREPARE` +
   `showPlaybackError(playbackAttribution(2000), BUDGET_EXHAUSTED)`，给出「立即重试 / 下一集」。

2. **退出全屏后自己转回横屏**
   `exitFullscreen()` 末尾是**无条件** `postDelayed(1200) { requestOrientation(USER) }`。
   看全屏时人是横着拿手机的，1.2 秒后方向交回传感器 → 立刻又转回横屏，
   用户按返回看到的是「没反应」，连按几次都出不去。
   改法：`pinPortraitUntilUpright()` —— 退出后钉住竖屏，用 `OrientationEventListener`
   等设备真的立起来（0±45° 或 180±45°）再放开 `USER`；系统自动旋转关着时不钉；
   没有方向传感器（`canDetectOrientation()==false`）时保持竖屏。
   `enterFullscreen()` 先 `releasePortraitPin()`，`onDestroy()` 里也释放。
   **注意**：`OrientationEventListener.enable()` 返回 void，别写成 `getOrDefault(false)`。

## 播放失败处置：两端统一到 `:core` 的 `PlaybackFailurePolicy`

- **动机**：电视端有一套完整的失败处置（地址自愈 / 队列项接回 / 换设备号重试 / 错误页倒计时），
  手机端另写了一套只有「解码降级 + 盲目重试 + 一张卡片」。同一个故障两端表现完全不同。
- **新增 `core/PlaybackFailurePolicy.kt`**（312 行，纯 Kotlin，可单测）：
  - `FailureFacts`：平台层负责读出来的事实（异常链布尔量、队列/片尾、设备能力、是否推荐页）。
  - `FailureAction`：`RefetchStream` / `RecoverQueuedCurrent` / `Replay` / `ShowError(reason, autoRetryDelayMs)`
    / `SkipRecommend` / `GiveUpRecommend`。
  - `PlaybackFailurePolicy.decide(facts, attr, ledger, session, recommendFailures)`：**唯一判定入口**，
    顺序 = 地址自愈 → 推荐页 → 队列项 → 解码降级 → 错误页。会消费额度（什么时候记账也是规则）。
  - `FailurePresentation`：错误页文案 + 能力表（`RETRY` / `SWITCH_SOFTWARE` / `CHANGE_QUALITY`）
    + `swapTarget` / `softwareTarget`。**两端同一句话、同一套按钮**。
  - `decoding` 只认 **4xxx**（3xxx 是封装解析，不进降级）；文案用 `pictureProblem`（3xxx+4xxx）。
- **`:shared` `PlaybackFailures`** 新增四条判据 + 清缓存：`expired` / `videoChanged` /
  `hostUnresolved` / `transportDead` / `dropTransportCaches(hosts)`。
  电视端原来的 `streamExpiredOf` / `videoChangedOf` / `transportDeadOf` / `dropDeadTransport`
  改成一行转发，手机端直接用——四条判据从此只有一份。
- **电视端**：`playerFailure` 的判定整段换成 `decide()` + `when(action)`，**执行代码原样保留**；
  错误页文案换成 `FailurePresentation.message`；两颗手动按钮换成 `capabilities` + `swapTarget`。
- **手机端**（补齐原先完全没有的能力）：
  - `refetchAndReplay`：`forgetStreamAllQualities` + `invalidateIndex` + `dropTransportCaches`；
  - `recoverQueuedCurrent`：队列项坏了原地接回当前集，额度按「集 + 上限」记，接不回再判一次；
  - 自动重试改成「错误页 + 倒计时 + 停止自动重试」，且**换设备号重取地址**（原先只是同源重开）；
  - 手动「立即重试 / 换到 xP」也换设备号；
  - `onResume` 注册 `registerDefaultNetworkCallback`（API 24+），网络恢复立刻重取地址。
- 单测 `PlaybackFailurePolicyTest` 17 条：判定顺序、额度记账时机、预加载不记账、
  推荐页上限、音频不给视频按钮、换档必须严格更低。

## 手机端手机号登录补上「区号选择」（与电视端同步）

- 现象：手机端手机号登录没有区号可选，只有中国大陆号码能登录。

- 改法：新增 `core/PhoneRegion.kt` —— **区号列表与归一规则只留一份**：

    **不判长度、不判「1 开头」**（各地区号码形状不同，长度交给平台判）
  - `indexOf(e164)` / `split(e164)`：预填时按最长匹配拆出区号与本地号码
- 电视端 `MainActivityAccountPanel` 改成直接用这份：`dialCodes = PhoneRegion.labels`、

- 手机端 `PhoneAccountActivity`：手机号输入框左边加一枚区号按钮（凹槽材质、与输入框同高），

  `pendingPhone`（二次验证后重发那条路）用 `split` 预填；发码与登录都走 `normalize`。
- 单测 `PhoneRegionTest` 7 条：香港 8 位、带 `+` 原样、空号、拆分、最长匹配（`+1` vs `+12…`）、越界收敛。

## 弹窗滚动区超出面板（区号选择框）

- 现象：手机端「选择国家 / 地区」弹窗里上下滑动，内容超过弹框范围。
- 根因：`PhoneDialog.CappedScrollView.onMeasure` **把父容器的高度约束整个丢掉**——
  它把高度重新量成 `AT_MOST(屏高 62%)`。窗口一旦比「标题 + 62% + 按钮行」矮
  （矮屏、大字号、界面缩放都够），可滚区仍按 62% 撑开，面板就比窗口高，
  超出窗口的那一截被裁掉 → 读起来是「滑动超出弹框」。
- 改法两条：
  1. `onMeasure` **尊重传入的 heightMeasureSpec**：`limit = min(cap, parentLimit)`
     （UNSPECIFIED 时才用 cap）；
  2. `PhoneDialog.show()` 里先算 `scrollBudget()`：窗口上限（屏高 88%）减去
     面板上下内边距、标题、外层 4+4、按钮行（40dp×n + 6×(n-1) + 8），
     写进 `CappedScrollView.maxHeightPx`。
- 这是 `PhoneDialog` 的公共修复，所有弹窗（导入账号参数等）一起受益。
- **本轮按用户要求只编译 debug**，没有出 release、没有改版本号 / 标签。

## 推荐页：去掉横滑拖进度 + 修「上滑误触左右翻页」

- **取消横滑拖进度（仅推荐页）**：`PhoneVideoPage` 新增构造参数 `dragSeek: Boolean = true`，
  透传给 `PhoneTouch(dragEnabled=...)`。`PhoneFeedView` 造页面时传 `dragSeek = false`；
  正式播放页保持默认 true（`PhonePlayerActivity` 里 `p.onDrag*` 仍在用）。
  推荐页的进度条**拖动**照旧（`onSeekStart/onSeek/onSeekEnd`），去掉的只是「在画面上横滑」。
- **上滑误触左右翻页**：根因在 `PhoneRecommendPage.LockablePager`——它用的是 RecyclerView
  默认拦截判据 `|dx| > slop`，**没有任何主轴偏向**。手指上滑时开头几像素的横向抖动就够
  外层横向 pager 抢走手势；竖屏列表那一侧救不了，因为它只能在**自己被判定为纵滑之后**
  才 `requestDisallowInterceptTouchEvent`，那时已经被抢走。
  改法：pager 自己加方向锁——MOVE 里算 `axis`（`|dx| > |dy| * 1.8` 才算横向），
  判定为纵向后**整个手势**都 `return false`，交给里面的竖屏列表。1.8 这个门槛不会让
  刻意横滑变难（正常横滑 dx 往往是 dy 的 5–10 倍）。
- 顺带删掉推荐页里只为横滑服务的 `dragTo(page, delta)`、`seekFrom`、`seekTarget`。
- 行为变化：推荐页的左右滑现在**只**归外层 pager（换体裁），受设置「推荐页左右滑动」控制。

## 推荐页：关掉左右滑动后，横滑会误触上下翻页

- 上一轮去掉横滑拖进度之后暴露的**新问题**：横滑不再有谁去
  `requestDisallowInterceptTouchEvent`，于是「横滑带一点纵向分量」被里面的竖向
  RecyclerView 按 `|dy| > slop` 认成上滑，`PagerSnapHelper` 顺势吸附到下一页。
- 改法：`PhoneFeedView.list` 换成 `VerticalPagerList`，加**互补的方向锁**——
  只在 `|dy| > |dx|` 时才滚；判成横向就整场手势 `return false`。
  同时把 `PhoneRecommendPage.LockablePager` 的 `AXIS_BIAS` 从 1.8 降到 **1.0**，
  让两条判据刚好互补（pager 拦 `|dx| >= |dy|`，列表拦 `|dy| > |dx|`），
  中间不留「斜着划谁都不动」的死区。
- 最终行为矩阵：
  - 上下滑 → 竖列表接管，翻下一条（开关无关）
  - 左右滑 + 开关开 → 外层 pager 换体裁
  - 左右滑 + 开关关 → **什么都不发生**（不再误触上下翻页）

  - 新增 `deviceSeed()`（随机 UUID，首次写盘 + 镜像，之后只读）、`newSeed()`；
  - `deviceProfile()` 重写：**盘上有就原样返回，没有才派生一次并落盘**（`commit()` 同步写）。
    删掉了原来那套「按系统标识符算指纹 → 比对 → 三种情形」的分支；
  - 新增 `queueNewDeviceIdentity()`：生成新种子 + 新档案，存成**候选**（`device-profile-pending`
    + `device-profile-pending-seed`），注册成功才由 `commitPendingProfile()` 转正
    （档案与种子一起换，`commit()` + 镜像同步）；
  - 删掉 `installNonce()` / `rememberSeed()` / `profileRebuilt` / `consumeProfileRebuilt`
    （那套是「旧随机档案→派生值」迁移用的，新模型下不存在了）；
  - `MIRROR_KEYS` 补 `device-seed` 与 `device-profile-pending-seed`（不补的话重装拿不回种子）。
- `DeviceRegistration.registerOnce` 拆出两个开关：
  - `force` = 无条件注册一次（首次 / 换新失败重试）；
  - `regenerate` = **换一台设备**（新种子 → 新档案 → 新身份），只有 `healDeviceIdentity` 用。
  `registerOnce` 里顺带 `repository.registerProfile = library.registrationProfile()`，
  保证注册与签名用同一套档案。
- `MainActivityAccount`：`ensureDeviceRegistered` 去掉 `profileRebuilt`；
  `healDeviceIdentity` 不再预置旧档案，改由 `registerDeviceOnce(force=true, regenerate=true)`。
- **实机验证**（S905L3B / Android 9，清数据 + 删 `/sdcard/.hgtv` 后首次启动）：
  - `device-seed` = `05d6523e-8589-4b23-a1a0-c410b880b43f`（随机 UUID）
  - `device-profile` 的 cdid/openudid 由它派生，`registered-device-id` 注册成功
  - 重启后种子与身份都不变；镜像 `/sdcard/.hgtv/hgtv-session.json` 里有 `device-seed`
  - 旧的 `device-profile-seed`（指纹）不再出现

## 老版本升级到「随机种子」版的实测行为

- 实测（S905 / Android 9）：先装 1.3.0（老代码）跑一次 → 覆盖装新 debug → 冷启动。
  | 键 | 升级前 | 升级后 |
  | --- | --- | --- |
  | `device-profile`（cdid/openudid） | `919511a6…` / `94c4eda8…` | **完全一致** |
  | `registered-device-id` | `656883219175530` | **完全一致** |
  | `device-seed` | 不存在 | **仍不存在**（只在重新注册时生成） |
  | `device-profile-seed`（旧指纹） | `c6122de7c301122b` | 保留但新代码不读 |
- 原因：`deviceProfile()` 先读盘，盘上有档案就直接返回，走不到 `deviceSeed()`。
- 边界：
  1. 老版本有待转正候选档案 → `commitPendingProfile()` 读 `-pending-seed` 读不到（老版本存的是
     `-pending-stamp`）→ 只换档案不写种子；下次重新注册才补 `device-seed`。
     已让 `commitPendingProfile` 顺手清掉 `-pending-stamp` 这个孤儿键。
  2. 老版本处于「档案与身份对不上」的坏状态 → 升级后先按旧档案温和重注册一次；
     仍被拒才由 `healDeviceIdentity` 走 `regenerate=true` 换设备。不会一升级就全员换设备。
- **升级时不做强制换身份**（用户尚未拍板是否要强制）。

## 强制升级换身份 —— 实测结论（2026-11-02 23:50）

- 实现在 `Library.upgradeIdentitySchemeIfNeeded()`：盘上有老档案且 `device-identity-scheme`
  不是 `seed-v1` 时，挂一套新种子派生的候选 + 标记，启动时按候选注册，成功才转正。
- 实测（S905，已登录账号 `066831371270` / 阴阳穿梭者吴远，升级前 device_id=656883219175530）：
  | 项 | 升级前 | 升级后 |
  | --- | --- | --- |
  | device-seed | 无 | `3964d4c7-…`（新生成） |
  | device-profile cdid/openudid | `919511a6…` / `94c4eda8…` | **换成** `c564d8ea…` / `6305eb7d…` |
  | device-identity-scheme | 无 | `seed-v1` |
  | **registered-device-id** | 656883219175530 | **不变** |
  | **registered-install-id** | 656883219179626 | **不变** |
  | account-cookie / session-token | 在 | **在**（23:52:21 还成功刷新了账号资料） |
- 结论：
  1. 强制升级**执行了**（档案与种子都换了）；
  2. **但平台没换设备** —— 注册请求不带旧身份，返回的仍是同一个 device_id。
     说明平台按**设备指纹**（brand/model/os/rom/resolution/dpi）认设备，不是按 cdid/openudid；
  3. 账号没受影响，搜索也正常（用「新档案 + 旧 device_id + 旧 cookies」实测搜索返回 20 条）。
- 推论：**换种子换不了设备**。issue #44 那种「被当陌生设备」靠这条治不好；
  而且「强制换档案」人为制造了「档案新、身份旧」的组合（历史上这个形态会出事，只是这次平台认了）。
